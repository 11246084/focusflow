## 為什麼要跑

到 SP-2 為止，生成階段的 17 個測試全部以 mock `fetch` 執行。這證明的是**機制正確**（驗證器擋得住捏造引用、失敗會退回重試、狀態機正確），但完全沒有證明**模型實際上會不會遵守契約**。

三次真實試跑的價值在於：**每一次都暴露了 mock 測試不可能發現的問題**。

---

## 第 1 次：引用驗證器攔下真實的捏造引用

```
shortScript.citation_validation_failed {
  attempt: 1,
  errors: [ '鏡 2：引用了證據包外的 chunkId「6a02f2d417c615e872035b94_chunk_0005」' ]
}
完成：2 次嘗試通過引用驗證，耗時 45.3s
```

### 這個 ID 是怎麼來的

證據包內實際存在的兩個 ID：

```
6a02f2d417c615e872035a68_chunk_0005     ← 第三支影片
6a02f38c17c615e872035b94_chunk_0002     ← 第二支影片
```

模型輸出的 ID：

```
6a02f2d417c615e872035b94_chunk_0005
└──── 取自第三支 ────┘└b94┘
                      取自第二支
```

**前半來自一支影片、後半來自另一支**，拼出一個不存在的 ID。這是典型的 LLM 幻覺形態：形式正確、字元組成看似合理，但指向不存在的東西。

### 意義

- 引用驗證**不是理論風險的防護，是實際會發生的錯誤**，第一次真跑就命中。
- 帶著錯誤訊息重試有效：第 2 次即通過。
- 若沒有這道驗證，這份腳本會帶著一個追不回逐字稿的引用進入教師審核，而教師幾乎不可能用肉眼發現 ID 中間的三個字元被換掉。

### 同次發現的缺陷：簡體字

鏡 07 口白出現「**经**典功能」（`经` 為簡體）。同一拍的字幕欄卻是正確的「經典」。

**這門課是繁體教材，口白最後要餵給中文語音複製**，混入簡體會唸錯或顯示錯字。

## 第 2 次：JSON 解析失敗，且錯誤中沒有原始輸出

```
生成失敗：SHORT_SCRIPT_OUTPUT_INVALID — Generation output is not valid JSON.
```

### 兩個問題

1. **解析失敗不會重試**：`parseJsonPayload` 直接拋錯，跳出重試迴圈。但輸出截斷或多帶文字是可以靠重試修正的暫時性問題，與捏造引用同性質。
2. **錯誤中沒有原始輸出**：DR-07 要求失敗時保留最後一次原始輸出供診斷，但該要求只實作在引用驗證失敗的路徑上。解析失敗時原始輸出直接遺失，無從得知模型到底吐了什麼。

### 修法

解析失敗改走同一條重試路徑，並在最終失敗時附上 `rawOutput`。

## 第 3 次：字幕複製口白、結尾放 CTA

修掉簡體字與解析重試後，第 3 次一次通過引用驗證，但輸出違反兩條模板規則。

### 缺陷一：結尾放了 CTA

```
鏡 08：在你的專案中，你更常使用 OpenCV 還是 YOLO 呢？留言跟我聊聊吧！
```

V5 模板明訂結尾「留白收尾，**不放 CTA**」；`docs/short-video-examples/` 的十支體系 v8 亦定案「導流不做」。

### 缺陷二：字幕直接複製口白

八拍的 `subtitle` 與 `narration` **一字不差**，每則 30 字以上。

模板要求字幕是短字卡（每屏 4–7 字），V5 的實際字幕為「越強就該用？」「CPU vs GPU」「等於沒有」。字幕與口白相同就失去意義——模板的驗收標準是「靜音播放要能看懂」，整句話塞在畫面上讀不完。

| 06 | 面對經典的辨識功能，直接用 OpenCV 現成的就好，不必殺雞用牛刀！ | 經典辨識免自行訓練 |
| 07 | 其實無論後面搭配什麼套件，八、九成的前置處理都還是先靠 OpenCV。 | 八九成前置靠OpenCV |

繁體、字幕為短字卡、結尾無 CTA、`basedOn` 全部合法。

### 與手寫腳本 V5 的對照

| 敘事位置 | V5 手寫 | 系統生成 |
|----------|---------|----------|
| 鉤子 | 你以為，越厲害的工具，就一定要用嗎？ | 你以為要做影像偵測，就非得用強大的 YOLO 嗎？ |
| 正解 | OpenCV 能用 CPU；YOLO 通常要靠 GPU | 鏡 03 + 鏡 04（拆成兩拍） |
| 反轉 | YOLO 有 CPU 版但效果很差，等於沒有 | 沒 GPU 跑 YOLO 慢到無法接受 |
| 高潮 | 工具各有用途，不用殺雞用牛刀 | 不必殺雞用牛刀 |
| 結尾 | 那你的任務，你會選哪一個？ | 你會選擇輕量的 OpenCV 還是強大的 YOLO？ |

**敘事骨架與 V5 幾乎重合。**

**唯一實質差異在反轉**：V5 的反轉是「YOLO **也有 CPU 版本**，但效果很差、等於沒有」，系統版本只有「沒 GPU 會很慢」。

原因不在模型——證據包缺少 `chunk_0004`（含「效果非常非常的差」那格）。**證據品質決定腳本品質的上限**，這是檢索層的問題，不是生成層的。

## 本輪的四項修正

| 缺陷 | 修法 | 檢測方式 |
|------|------|----------|
| 捏造 chunkId | 引用驗證整份退回重試（原已實作） | 確定性 |
| 混入簡體字 | 常見簡體字偵測清單，命中即驗證失敗重試 | 確定性（清單為盡力而為，非完整對照表） |
| 字幕複製口白 | 長度上限 20 字，且不得與口白完全相同 | 確定性 |
| 結尾放 CTA | 系統指示明禁 | **僅靠指示**，屬主觀判斷，由教師審核把關 |

另修正：JSON 解析失敗改為可重試，並在最終失敗時保留原始輸出。

新增 6 個測試（總計 23 個生成測試）；backend **714 tests 全數通過**。

## 已知限制

- 只試跑同一個主題、同一門課、同一個模型。其他主題與課程的表現未驗證。
- **簡體字偵測清單不完整**：只收錄常見於技術／教學文本的簡體字，漏網者仍需教師審核攔下。發現新的漏網字應直接加入該集合。
- **CTA 沒有程式檢測**，完全依賴系統指示與教師審核。
- 生成品質沒有客觀判準（P-02 待指導教授定義），本紀錄只能陳述「與 V5 手寫版的敘事骨架相近」，不能宣稱品質達標。
- 未測試弧線不適用的情境（`arcApplicable: false`）在真實資料上是否會正確觸發。
