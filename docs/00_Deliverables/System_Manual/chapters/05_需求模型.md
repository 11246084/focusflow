# 第5章 需求模型

## 5-1 使用者需求

FocusFlow 的主要使用者為學生、教師與管理員，LINE 平台則是學生問答的外部系統。所有角色的可見功能必須由後端權限再次驗證，不以選單是否顯示作為授權依據。

### 功能性需求

下表各條均為 FocusFlow 應滿足之功能性需求，依功能歸屬分列，並標示對應的使用個案。

表5-1-1　使用者功能性需求表

| 功能性需求 | 描述 | 對應使用個案 |
| --- | --- | --- |
| 註冊與登入 | FR-01　學生以姓名、Email 與密碼自助註冊；教師與管理員帳號僅由管理流程建立，不開放公開註冊。<br>FR-02　以 Email、密碼及所選角色驗證登入，角色不符、帳號停用或憑證錯誤時拒絕；未達鎖定門檻時提示剩餘可嘗試次數，同一 Email 連續失敗達門檻時暫時鎖定登入嘗試。<br>FR-04　一般入口與 `/admin` 分流，非管理員不得進入管理介面，管理員不提供自助註冊（另見 UC-09）。 | UC-01 |
| 課程與修課名單管理 | FR-05　教師建立、查看、修改及刪除自己的課程，並管理 draft／published／archived 狀態；管理員可跨課程管理（另見 UC-09）。<br>FR-06　課程教師或管理員以學生 Email 指派、以名單匯入及撤銷修課資格，並保留撤銷稽核資訊。 | UC-02 |
| 影片加入與處理追蹤 | FR-08　教師或管理員將本機影片或 YouTube 連結加入可管理的課程，並阻擋同課程的明確重複來源。<br>FR-09　以單一 multipart 請求建立多影片批次，查看批次與單項狀態，並對允許的失敗項目重試。<br>FR-10　記錄影片 queued、processing、completed、failed 狀態與嘗試資訊；非法狀態轉換及重複回報不得破壞既有結果。<br>FR-11　將既有影片掛載至其他可管理課程或解除掛載，刪除與解除掛載保持不同語意。 | UC-03 |
| 網頁觀看與課程問答 | FR-07　學生只能存取「有效修課資格且課程已發布」的課程、影片、問答、課程通知、短影音與 LINE 課程範圍；不提供自助選課、邀請碼或申請審核流程（亦適用 UC-05、UC-07）。<br>FR-12　學生播放授權影片，系統記錄開啟事件；達成觀看門檻時以不重複方式更新修課進度。<br>FR-13　在授權課程中建立或續用網頁對話、提出問題、查看歷史訊息，並對可重試的失敗訊息重試。<br>FR-14　問答回覆提供回答狀態及實際命中的來源資訊，包含影片、片段文字與可用時間點，使用者可由引用跳回影片（亦適用 UC-05）。<br>FR-15　權限不足、影片尚未可用或檢索證據不足時，拒絕請求或回覆無充分答案，不得虛構課程內容（亦適用 UC-05）。<br>FR-16　對無對話歷史且符合條件的問答使用 FAQ 快取；影片重新處理或內容移除時依規則失效快取。 | UC-04 |
| LINE 綁定與提問 | FR-17　已登入使用者取得一次性 LINE 綁定資訊；綁定後學生可在有效修課課程間選擇並提問，LINE 問答重用後端課程授權與問答服務。 | UC-05 |
| 個人資料與通知 | FR-03　已登入使用者查看與修改個人姓名、Email、密碼及私有頭像；忘記密碼流程以驗證碼重設。<br>FR-18　使用者查看站內通知並標記單筆或全部已讀；系統發送影片完成、短影音退回等通知，管理員可發送全站公告（另見 UC-09）。 | UC-06 |
| 短影音瀏覽 | FR-20　學生短影音牆只顯示其有效修課且已發布課程中，狀態為 published 且 YouTube 可播放的短影音成品。 | UC-07 |
| 短影音腳本與成品審核 | FR-21　啟用短影音腳本功能時，教師或管理員由課程提問候選建立凍結證據、生成腳本版本、核准、要求修改或放棄主題；生成內容只能引用凍結證據。<br>FR-22　啟用短影音腳本功能且教師已備妥成品時，允許人工上傳成品、留存 AI 揭露與同意確認、上傳 YouTube 供預覽，並以成品審核決定是否進入學生牆。成品由教師於系統外製作，系統不提供自動剪輯或渲染功能。 | UC-08 |
| 系統維運 | FR-19　提供學生、教師與管理員相符的儀表板及統計；管理員可維護使用者、影片並查看事件資料。 | UC-09 |

### 非功能性需求

表5-1-2　非功能性需求表

| 編號 | 非功能性需求 |
| --- | --- |
| NFR-01 | **授權安全：** 所有受保護 API 與非公開媒體交付應驗證身分，並依角色、課程所有權、Enrollment 與資源狀態判斷權限。 |
| NFR-02 | **憑證安全：** 密碼只保存雜湊；Webhook 應驗簽；secret 不得寫入程式、文件或回應。 |
| NFR-03 | **隱私：** 私有頭像必須登入後讀取；Email、LINE 識別、提問與使用紀錄不得無授權公開。 |
| NFR-04 | **資料完整性：** 影片處理、批次、重試、Webhook 回放、Enrollment 指派及審核版本應具冪等或衝突保護。 |
| NFR-05 | **可追溯性：** 問答引用只能來自實際檢索片段；影片、批次、短影音腳本與審核應保存狀態及必要稽核欄位。 |
| NFR-06 | **失敗透明度：** 外部服務或資料未就緒時應回傳可判讀的錯誤、拒答或降級狀態，不得以成功訊息掩蓋失敗。 |
| NFR-07 | **可用性：** 核心頁面應呈現載入、空資料、錯誤與重試狀態；重新整理後應能恢復有效登入或批次追蹤。 |
| NFR-08 | **效能與容量：** 問答、影片處理與批次需在目標使用規模內可接受。 |
| NFR-09 | **相容性與可及性：** 網頁應支援受安全更新的主流瀏覽器及鍵盤操作；引用卡片等互動元件需可聚焦與啟動。 |
| NFR-10 | **可維護性：** 後端維持 routes／controllers／services／models 分層；API、前端消費端、資料契約與文件需同步。 |
| NFR-11 | **資料治理：** 教材、逐字稿、提問、使用事件、暫存檔與備份應有授權、保存及刪除規則。 |
| NFR-12 | **部署驗收：** 本機或 mock 測試不得替代共享 Atlas、真實 AI、LINE、YouTube、SMTP、HTTPS 與正式瀏覽器驗收。 |

## 5-2 使用個案圖（Use Case diagram）

表5-2-1　行為者與系統邊界

| 行為者 | 主要責任與權限 |
| --- | --- |
| Student（學生） | 使用自己的帳號及有效修課資格查看課程、影片、進度、QA、通知與 Shorts；可綁定 LINE。不能建立 Enrollment 或自行加入課程。 |
| Teacher（教師） | 建立與管理自己的課程、Enrollment、影片及批次；在功能開啟時管理短影音腳本與成品。不能管理其他教師課程。 |
| Admin（管理員） | 由獨立入口登入，跨課程管理使用者、課程、影片、Enrollment、通知、事件與統計。 |

LINE Platform 是學生透過 LINE Bot 提問時的訊息傳遞管道，角色類似網頁使用個案中的瀏覽器；提問的
行為者仍是 Student，技術契約見第6-1節循序圖。系統為達成使用個案而呼叫的 AI、YouTube、SMTP、
MongoDB Atlas 等外部服務不列為行為者，其依賴關係見各使用個案描述（表5-3-1至表5-3-9）。

圖5-2-1以單一系統使用個案圖呈現 FocusFlow 的系統邊界與角色分工，涵蓋 UC-01 至 UC-09，並依功能歸屬劃分為學生功能、權限控管、教師功能與管理員功能四個區塊。各使用個案的完整描述見表5-3-1至表5-3-9，對應的功能性需求見表5-1-1。

- **權限控管**：註冊與登入（UC-01）、維護個人資料與通知（UC-06）為三種角色共用。
- **學生**：在網頁觀看授權影片並提問（UC-04）、綁定 LINE 後於 LINE 提問（UC-05），以及查看所修課程已發布的短影音（UC-07）。
- **教師**：管理自己的課程與修課名單（UC-02）、加入影片並追蹤處理狀態（UC-03），並在短影音功能啟用時產生腳本與提交成品（UC-08）。
- **管理員**：由獨立入口登入，執行跨課程的維運作業（UC-09），包含管理使用者帳號、管理課程與影片資料，以及發送系統公告。管理員對個別課程與影片的操作屬維運範圍，其權限邊界見表5-3-9。

圖中虛線箭頭表示使用個案之間的關係：`«include»` 為必然執行的步驟，`«extend»` 為特定條件才觸發的延伸行為。

UC-04 與 UC-05 皆包含「取得回答與影片時間段」，表示網頁與 LINE 兩種提問管道共用同一套檢索、回答與引用機制，學生在任一管道都能由引用跳回影片對應時間點，其訊息流程見第6-1節循序圖；UC-08 包含「成品審核」，短影音成品通過審核後才進入學生的短影音牆。

延伸關係對應各使用個案的條件分支：

- **UC-01**：同一 Email 連續登入失敗達門檻時觸發帳號鎖定。
- **UC-06**：使用者忘記密碼時以驗證碼重設。
- **UC-02**：教師建立課程並管理其發布狀態、以名單批次建立修課資格，或撤銷學生的修課資格。
- **UC-03**：將既有影片掛載至其他可管理課程，或於批次中個別影片處理失敗時重試。
- **UC-08**：腳本內容不符需求時退回修改。
- **UC-09**：管理員管理使用者帳號、管理課程與影片資料、發送全站公告。

## 5-4 分析類別圖（Analysis class diagram）

分析類別模型先表達需求概念，再由第 8 章對應至實際 MongoDB collections，分為邊界類別、控制類別
及實體類別；邊界／控制類別採責任導向命名（如「課程授權」），落實為程式類別的對應見表6-2-1。

表5-4-1　主要分析類別

| 類別類型 | 代表類別（分析層概念名稱） | 責任 |
| --- | --- | --- |
| 邊界類別 | 網頁介面、管理員入口、LINE 訊息介面、影片處理回報介面、外部服務介面 | 接收角色操作或外部事件，呈現結果，不自行決定課程授權 |
| 控制類別 | 身分驗證、課程授權、修課管理、影片管理、影片批次管理、提問處理、對話管理、LINE 對話處理、通知發送、短影音腳本產生、短影音成品審核 | 執行驗證、權限、狀態機、檢索、回答、通知及審核流程 |
| 核心實體 | User、Course、Enrollment、Video、VideoBatch | 表達帳號角色、課程所有權、修課授權、影片來源與處理批次 |
| 問答實體 | VideoSegment、Question、FAQ、Conversation、Message | 表達可檢索片段、提問／回答、快取及多輪對話來源 |
| 營運實體 | Notification、UsageLog | 表達通知已讀、來源、事件與統計基礎 |
| 短影音實體 | ShortScript、ShortAsset | 表達候選證據、腳本版本／回饋，以及成品 generation、審核、YouTube 與發布狀態 |

系統分析類別圖如圖5-4-1所示，呈現實體類別間的領域關聯與多重性；邊界／控制類別歸屬見表5-4-1，
不重複畫入圖中。補充關係（圖上不易一眼看出者）：Admin 跨課程管理不取代 `teacherId` 代表的課程
owner；VideoBatch 聚合多支影片的部分成功／失敗狀態；LINE 短期對話狀態存於 User，未獨立成實體。

判讀重點：

- User 僅一個類別，角色為屬性；學生內容授權來自「active Enrollment × published Course」交集，
  非 User 直接連到 Course。
- Question／Message 對 VideoSegment 的關聯代表回答只能引用實際檢索片段（對應 NFR-05 可追溯性）。
- ShortScript（腳本／凍結證據）與 ShortAsset（人工上傳成品）為不同實體，以版本關聯連結。
