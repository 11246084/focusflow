範圍是管理員的系統總覽、使用者、課程、影片、YouTube 上傳、問題回報、使用統計，以及教師的總覽頁。不含學生端、短影片製作與管理頁（見[短影片決策](../Short_Video/decisions.md)）與對話欄（見[對話功能優化](../QA_Conversation/decisions.md)）。

## 名詞

- **儀表板**：登入後第一眼看到、用來掌握狀況的頁面。這裡指管理員的系統總覽、使用統計，與教師的總覽。
- **洞察**：從學生的提問與觀看紀錄整理出來、能讓教師決定下一步的資訊，例如「這一段很多人問、而且常答不出來」。
- **待辦提醒**：需要這個人動手處理的事，例如處理失敗的影片、等待確認的短影片。
- **答不出來的提問**：系統找不到足夠的課程內容而回覆無法回答的題目，問答紀錄的狀態是 `no_match`。

### Q1：教師可以看到個別學生的哪些資料

**問題**：教師追蹤個別學生時，是否可以看到「這位學生的姓名、他問過的問題原文、看完哪些影片、最近的活動時間」？

**建議答案**：可以，但有三個條件：

1. 只限教師自己授課的課程，而且只看得到該課程內的紀錄。
2. 上線前在學生端加上告知，讓學生知道授課教師看得到他在這門課的提問與觀看紀錄。
3. 不顯示學生的 Email、LINE 帳號，也不顯示他在其他課程的紀錄。

**理由**：這是整個設計的前提，所以先問。你要的「追蹤個別學生」一定要能對到人，匿名的話只能做到課程層級的洞察。但這是系統第一次讓教師看到個別學生的提問原文：學生可能問得很基礎，知道老師看得到之後有人會不敢問。告知是最低限度的做法；是否需要指導教授或學校同意，請你判斷，我無法替你確認。

**替代方案**：教師只看得到每位學生的數字（提問次數、看完幾支影片、最近活動），提問原文只在課程層級以不具名的方式顯示。隱私風險低很多，但教師無法知道某位學生到底卡在哪裡。

### Q7：教師找到需要關心的學生之後，要能在系統裡做什麼

**問題**：追蹤個別學生是「只看」，還是要能從儀表板對學生採取動作，例如傳訊息或標記已處理？

**Claude 無法確定的原因**：你說的是「進一步追蹤個別學生的情況」，可以解讀成只看資料，也可以解讀成要能聯絡。兩者的範圍差很多：只看的話是查詢與畫面；要能聯絡的話要新增通知或 LINE 推播給個別學生的功能，還牽涉訊息內容由誰負責。

**暫定**：在你回答之前先當作只看，另外讓教師可以把某位學生標記為「已關心」，避免同一個人一直出現在名單上。
