# 教授會議（簡報架構、系統設計與競賽規劃）

- 會議日期: 2026-05-19
- 會議類型: 教授會議（進度回報）
- 與會者: 邱偉豪、張庭語、鍾百陶、張家瑜、蒯思齊(教授)

## 討論內容

1. 簡報整體架構

- 背景：需確認專題簡報的鋪陳方式，讓評審快速理解專題價值。
- 內容：簡報分為六大部分，由研究背景與動機切入；點出學生在教學影片學習上的痛點（影片過長、重點難以擷取、課後複習無法即時定位片段、學習效率低落）。
- 結論傾向：以痛點為起點，凸顯 FocusFlow 將教學影片由不可搜尋的「黑盒子」轉換為可被問答的「知識庫」。

2. 系統設計與使用情境

- 背景：說明 FocusFlow 的核心流程與三種角色的使用方式。
- 內容：
  - 核心流程：透過語音轉文字、切段檢索與生成式回答達成全自動化處理。
  - 學生端：可透過 Web 介面或 LINE Bot 提問，並跳轉至影片關鍵片段。
  - 老師端：上傳 MP4 或 YouTube 教材，後端自動完成音訊提取、轉錄、切段與向量化索引。
  - 管理者端：負責平台管理、帳號停權與資料審核。
- 結論傾向：以三角色情境呈現完整使用流程，突顯自動化處理能力。

3. 市場調查與需求驗證

- 背景：以問卷數據佐證系統需求的真實性。
- 內容：
  - 53.8% 的學生曾遇到「老師講過但無法快速定位片段」的窘境。
  - 84.7% 認為在影片中尋找特定概念非常耗時。
  - 69.2% 因無法即時提問而中斷學習。
- 結論傾向：數據可有效驗證需求，建議於簡報中以圖表呈現。

4. 競賽與行銷規劃

- 背景：規劃專題的推廣路徑與商業化方向。
- 內容：
  - 初期以校內測試驗證學生與老師的使用需求。
  - 後期推廣至補習班或其他學校。
  - 長期目標發展為 SaaS 授權模式。
  - 需準備甘特圖、貢獻圖等行銷素材，並量化自動化效益。
- 結論傾向：以校內測試 → 他校推廣 → 授權商業化三階段呈現成長藍圖。

5. 技術重點與教授建議

- 背景：技術呈現需聚焦核心，並回應 AI 生成正確性的疑慮。
- 內容：
  - 採用 MongoDB 儲存影片資料、文字片段與索引。
  - 教授建議補上 AI 幻覺與生成結果正確性的檢核說明。
  - 教授建議於簡報加入操作示範短片(時長約3分鐘)，提升評審理解。
  - 架構圖維持精簡、突出技術核心，不過度著墨語法細節。
- 結論傾向：強化正確性機制說明，並以示範短片與精簡架構圖輔助。

6. 參賽規劃

- 背景：鎖定適合的專題競賽以擴大成果能見度。
- 內容：鎖定大專院校專題競賽、全國技專院校專題競賽與全國績優院校專題競賽，強調學習效率提升與商業化潛力。
- 結論傾向：確定參與至少三項專題競賽。

## 決議事項

1. 簡報中補強系統操作流程的示範影片，以提升評審對功能的理解。
2. 移除開發階段的程式碼等技術細節，將重心放在解決方案與實際應用場景。
3. 強化 AI 處理後資訊正確性的機制說明，降低評審對 AI 生成錯誤的疑慮。
4. 確定至少參與三個以上的專題競賽。
