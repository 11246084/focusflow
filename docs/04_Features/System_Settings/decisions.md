# 系統設定設計決策

系統設定讓管理員在後台調整**非密鑰**的執行期參數，例如各功能用哪個模型、功能開關、門檻與學生額度，改完立即生效，不必上 VM 改環境變數再重啟。這份文件記錄 2026-10-20～21 與使用者逐題討論後**已定案的設計**、接受的風險與還沒討論完的問題，讓接手的人或 AI 不用重讀對話。功能是否完成只看[目前狀態](../../current-status.md)。

## 名詞

- **provider**：提供模型的廠商與它的 API，例如 Gemini、OpenAI、Anthropic。
- **兩層開關**：環境變數決定這個環境「允不允許」開啟，資料庫的設定只能在允許範圍內切換，兩者都開才生效；沿用 [YouTube 恢復與清理](../YouTube_Lifecycle/decisions.md)的做法。
- **預扣**：學生提問前先扣掉預估用量，答完再依實際用量多退少補，避免同時送出很多題時超過上限。
- **重置券**：管理員發給學生、學生自己按下就能把當天用量歸零的一次性憑證。
- **高權限短效憑證（step-up）**：高風險操作前重新輸入密碼，換到一張 5 分鐘內有效的憑證，只有拿這張才能執行該操作。
- **圖文選單／Flex 卡片／快速回覆**：LINE 的三種按鈕。圖文選單固定在聊天室下方；Flex 卡片是聊天紀錄裡可以點的卡片；快速回覆是跟著某則訊息出現在輸入框上方、點了就消失的按鈕。

## 整體流程（例）

管理員把「FAQ 快取相似度」從 0.95 改成 0.92 → 畫面顯示「0.95 → 0.92，影響所有學生的問答」並確認 → 後端依定義表驗證範圍 → 寫入 `RuntimeSetting` 與 `adminAuditLogs` → 同一個程序的記憶體立即更新 → 下一位學生提問就用 0.92。

學生在網頁選「Gemini（回答較精簡）」→ 系統預扣今日額度 → 用該模型回答，回答下方顯示「由 Gemini 3.5 Flash 回答」→ 依實際 token × 模型倍率結算 → 額度顯示「今日已用 40%，明天 00:00 重置」。

## 已定案

依 2026-10-21 程式查證（`dev` 112b7ba）；資安相關項目依同日的[現有程式資安審查](evidence/2026-10-21_security-review.md)。

### 儲存與讀取

| # | 決策 | 理由、取捨與來源 |
|---|---|---|
| 5 | 設定值沿用現有的 `RuntimeSetting` 集合，一個 key 一筆，key 依用途分組命名（例 `qa.answerModel`、`quota.dailyTokens`）。每個 key 的型別、範圍、預設值、對應的環境變數、中文說明、風險等級寫在程式內的定義表，資料庫只存值 | 現有 [RuntimeSetting](../../../backend/src/models/runtimeSetting.model.js) 與 [YouTube 開關服務](../../../backend/src/services/youtubeLifecycleSettings.service.js)已是同樣的結構，另開集合會重複。一個 key 一筆，兩位管理員同時改不同參數時不會互相覆蓋；整份存成一筆則後存的會蓋掉先存的 |
| 6 | 另開**只能新增**的 `adminAuditLogs` 集合，記錄設定修改、帳號角色與停用、額度重設、重置券發放與使用、admin 登入成敗；欄位含操作者與當時 Email、時間、對象、舊值、新值、理由 | `RuntimeSetting.history` 只保留最近 50 筆，與「紀錄不能刪除」衝突；角色變更目前沒有任何紀錄（資安審查第 4 項）。每次調整都能追溯是誰、何時、為什麼改 |
| 7 | 優先順序：**功能開關**用兩層開關；**數值**（模型、門檻、額度）用「資料庫 → 環境變數 → 程式預設值」。「恢復預設」就是刪除資料庫裡的值 | 開關與 YouTube 開關一致，維運人員在 VM 關掉環境變數就能強制關閉（[YouTube 決策](../YouTube_Lifecycle/decisions.md)第 9 項）。數值若讓環境變數優先，VM 上已設定的參數後台就改不動；資料庫優先、沒設才用預設，與現有的 `User.dailyAskLimitOverride` 相同 |
| 8 | 讀取函式 `getSetting(key)` 是**同步**的，從記憶體讀；啟動時載入，存檔後同一程序立即更新，另外每 60 秒重讀一次資料庫。啟動時連不上資料庫就先用環境變數與程式預設值，並在狀態頁顯示警告，不擋啟動。實作時**不修改 `env` 物件** | 現有服務都在呼叫當下讀 `env.xxx`，改成同步函式只要改一行。問答每個請求會讀好幾個設定，每次查資料庫會增加延遲；YouTube 開關每次讀資料庫是因為使用頻率低（該文件第 11 項）。部署只有一個 pm2 程序，60 秒重讀是給「有人直接改資料庫」或日後多程序部署的保險。不改 `env` 是為了避免有人藉設定覆寫金鑰（資安審查第 9 項） |
| 9 | 寫入時依定義表嚴格驗證型別（`typeof`）與範圍，**不認得的 key 回 400**；讀取資料庫時不認得的 key 才忽略。修改模型與開關時必填理由，數值類選填 | `app.js` 允許巢狀表單，`Boolean("false")` 會變成 `true`（現有 `updateUser` 就有這個問題，資安審查第 4、12 項）。模型與開關影響範圍大，事後需要知道當初為什麼改 |

### 學生自選模型

| # | 決策 | 理由、取捨與來源 |
|---|---|---|
| 10 | 網頁問答的對話框上方有模型選單，以對話為單位：開新對話時帶入上次的選擇，中途切換從下一題生效。每則回答記錄 provider 與模型 ID，並顯示「由 ○○ 回答」 | 不同模型的回答風格不同：[AA-PersonalityBench](https://artificialanalysis.ai/evaluations/aa-personalitybench) 以 LLM 評審兩兩比較 30 種特質，各模型的個性分布明顯不同（使用者提出）。記錄模型才能統計各模型的品質與用量 |
| 11 | LINE 不必打字：①**圖文選單**常駐四格「切換課程」「切換模型」「本月額度」「網頁版」，用 Messaging API 與 repo 內的腳本建立；②點選後回 **Flex 卡片**，每個選項一張，目前使用中的標示「使用中」，最多 12 張；③每則回答後附**快速回覆**「換模型」「換課程」；④保留「切換課程」「切換模型」文字指令。LINE 的模型選擇存在學生帳號上。建立圖文選單屬於對外設定，上線時另外授權 | 目前只有「切換課程」用 Buttons Template，且要先打字，按鈕最多 4 個（[LINE 服務](../../../backend/src/services/line.service.js)）。依 LINE 文件：[圖文選單](https://developers.line.biz/en/docs/messaging-api/rich-menus-overview/)常駐但電腦版不顯示，用 API 建立才能依使用者切換；[快速回覆](https://developers.line.biz/en/docs/messaging-api/using-quick-reply/)最多 13 個、點了就消失。用 API 建立可留版本紀錄，也能由 AI 直接完成；後台的圖形介面只能手動點選。官方帳號目前沒有設定過圖文選單 |
| 12 | 管理員按「重新抓取」向各 provider 列出可用模型，只留下能產生文字回答的模型（清單快取 10 分鐘）；管理員勾選「開放給學生」，為每個模型填顯示名稱、一句說明、排序與計算倍率，並指定預設模型。**只能從清單選，不能自己輸入**。8 拍腳本與 recut 的模型從同一份清單選，不受「開放給學生」影響。學生端 API 與 LINE 按鈕只傳伺服器端的模型代號（例 `gemini-fast`），不傳真正的模型 ID | 使用者要求先用下拉選單，由管理員決定開放哪些模型。模型 ID 打錯一個字，全校的問答就會壞掉。只傳代號，學生無法自己改成未開放的模型（資安審查第 8 項） |
| 13 | 勾選開放某個模型前，系統用固定的測試問題與假的檢索片段實際呼叫一次，檢查回傳是否符合問答需要的 JSON 格式（含引用來源、答不出來時的回覆），不合格就不能勾選。回答品質用 [QA_Evaluation](../QA_Evaluation/README.md) 評估，不是勾選條件 | 引用來源、時間戳與「答不出來」都靠 Gemini 的 `responseSchema` 固定格式（回答生成服務），換 provider 也必須產出一樣的格式，否則網頁與 LINE 顯示會壞 |
| 14 | 判斷能不能用分兩層：**這一家**：①程式有呼叫程式；②環境變數有金鑰；③啟動時與每 6 小時呼叫一次「列出模型」成功。**這個模型**：④在最近一次的清單裡；⑤通過格式測試；⑥不在故障後的 10 分鐘跳過期；⑦管理員有開放。全部成立才出現在學生端；管理員頁把不能用的 provider 顯示成灰色並寫出原因（例「未設定金鑰」） | 只看有沒有金鑰不夠：金鑰可能填錯或過期。列出模型的 API 不耗 token。學生只看到真的能用的模型，避免以為可以用 |
| 15 | 問答新增 Anthropic 的呼叫程式，現有的 OpenAI 路徑改成相同的 JSON 格式；第一版實際只有 Gemini 可用，另外兩家只用假的回應測試，申請到金鑰後再做真實呼叫的驗收。8 拍腳本與 recut 第一版只用 Gemini | 目前只申請了 Gemini 金鑰。加了金鑰還要有對應的呼叫程式才能用；問答已有 `gemini`、`openai`、`template` 三種，8 拍腳本只有 Gemini。腳本與 recut 的提示詞與驗證都是針對 Gemini 調的。Jev 是判斷模型，不能寫回答，不在選單內（recut 決策第 46 項） |
| 16 | FAQ 快取依 **provider** 區分（gemini／openai／anthropic），同一家的不同模型共用快取；舊快取一律算 gemini，不回填資料庫。命中時標示「快取答案，原由 ○○ 回答」 | 不區分的話，學生選 Claude 卻拿到 Gemini 寫的答案，選模型就沒有意義。分到每個模型會讓命中率分散得太細，使用者決定只分三家。分散只影響成本與速度，不影響正確性。過去全部由 Gemini 回答 |
| 17 | 模型故障時，依序改用：學生選的模型 → 預設模型 → 其他開放的模型（依管理員排序），全部失敗才回錯誤，回答照實標示是哪個模型答的；失敗過的模型 10 分鐘內直接跳過。每次故障記成一筆「故障事件」（模型、開始與最後失敗時間、失敗次數、受影響學生數、改由哪些模型代答幾次、恢復時間），通知每位管理員，同一個模型 24 小時只通知一次並附累計人數。8 拍腳本與 recut 不自動換模型，直接回錯誤並通知管理員 | 學生的問答不中斷；跳過期避免每題都先等逾時；通知限次數避免洗版，累計人數讓管理員判斷急迫程度。腳本與 recut 由教師手動觸發、可以重試，提示詞也只針對 Gemini 調過 |

### 學生額度

| # | 決策 | 理由、取捨與來源 |
|---|---|---|
| 18 | 改用**實際 token** 計算：每次回答取 provider 回傳的輸入加輸出 token，乘上模型的計算倍率（Gemini Flash 為 1），存進 `usageLog`；命中快取記 0。設**每日、每月**兩個上限，依台灣時間重置。學生只看到百分比與重置時間（例「今日已用 40%，明天 00:00 重置」），網頁問答頁與 LINE「本月額度」都顯示。用量已達上限才擋，讓用量超過上限的那一題可以答完。取代現有的每日題數與估算配額；全站每月總預算 `QA_MONTHLY_TOKEN_BUDGET` 留在環境變數當最後防線 | 使用者要求像 Codex、Claude Code 那樣計算 token，但改成每日與每月限額。現有每月配額是「提問次數 × 每題估 1000 token」，月份以 UTC 計算（[成本控制](../../../backend/src/services/costControl.service.js)）；Gemini 回應附有實際 token 數，但目前沒有保存。倍率讓價格不同的模型可以放在同一個額度裡比較 |
| 19 | 初始上限：實作時先跑一次 QA_Evaluation 資料集，記下每題的實際 token，以「平均 × 5 題」當每日上限、「平均 × 100 題」當每月上限；這次評估會呼叫 Gemini、產生少量費用，跑之前先徵詢使用者。上線時先只記錄 token，保留每日 5 題的限制；累積 1～2 週實際資料校正後，再切換成 token 計算 | 目前沒有 token 資料，無法直接訂出合理的數字；用評估資料集一小時內就能估算，不必空等。上線後用真實資料校正 |
| 20 | 額度用**原子預扣**：提問前用單一條件更新扣掉預估用量（「已用 + 預估 ≤ 上限」才扣），答完依實際 token 多退少補，失敗則退回；每位學生**同時只能有 1 題在處理** | 現在是先數用量再放行，學生同時送出 20 題時全部會通過（[提問限制](../../../backend/src/services/askLimits.service.js)，資安審查第 1 項）。把條件放進更新指令一步完成，是資料庫處理並行的標準做法（[MongoDB 複合操作](https://mongodb.com/docs/drivers/java/sync/upcoming/crud/compound-operations)），例如電商扣庫存；先預扣再結算，和刷卡的預授權、請款相同 |
| 21 | **重置券**：管理員可以發給單一學生（使用者頁）、一門課或全部學生，填理由並記錄。學生用完今日額度時，網頁與 LINE 顯示「你有 1 張重置券，要使用嗎？」，按下後今日用量歸零；做法是記下重置的時間點、不刪除紀錄。只重置當天，不影響每月上限；當月底失效。兌換用單一條件更新（屬於本人、未使用、未過期）。每月額度用完時，由管理員在使用者頁調高該學生的個別每月上限 | 使用者要求學生自己就能用券繼續問。月底失效，避免累積多張後一次用掉。單一條件更新能防止同一張券被並行或重複兌換（資安審查第 1、3 項）。個別上限沿用 `dailyAskLimitOverride` 的位置與做法 |

## 接受的風險

| 風險 | 為什麼暫時接受 | 什麼時候必須處理 |
|---|---|---|
| 同一家的大小模型（例 Flash 與 Pro）共用快取答案 | 換取較高的快取命中率，回答會標示原本由哪個模型產生 | 若試用回饋指出答案風格不符所選的模型 |
| 限流計數存在記憶體，重啟就歸零 | 只有一個 pm2 程序，重啟不頻繁 | 改成多程序或多台部署時 |

## 待討論

- **recut 成本設定的實作細節**：兩項上限與費用資訊已依第 40 項定案，鍵名、合法範圍及估算費用的方法在實作時定義並驗證；不再把原 Q10 列成未答題，也不先假定新的日／月總預算。
- **換向量模型**：要重算所有片段並建新索引；之後可以在管理員頁提供「用新模型重跑所有影片」的按鈕。使用者認為目前還不需要。
- **對外的存活檢查端點**：若要用外部監控服務（例 UptimeRobot），再加一個只回「ok」的公開端點。
- **`/health` 精簡**：日後若讓 nginx 對外轉送 `/health`，必須先把詳細內容移到 admin 專用的狀態 API（資安審查第 7 項）。
- **圖文選單依學生狀態切換**：例如未綁定的學生看到「綁定帳號」；與 LINE 綁定的新流程一起決定。
- **LINE 帳號綁定改用官方流程**（網頁的 LINE Login 加好友、Bot 端的 Account Link）：另案設計討論中。
- **8 拍腳本與 recut 改用其他 provider**：需要重新調整提示詞與驗證。
- **admin 改用 TOTP**：手機驗證 App 每 30 秒產生一組 6 位數字，比信箱驗證碼安全、不依賴信箱。佈展前先上信箱驗證（第 32 項），之後再評估是否改用或並用。
- **Passkey**：等系統主要功能都完成後再考慮。
- **管理員建立教師帳號**（來源：複評 1-1）：**已納入第一版（第 41 項），細節在工單定案。**使用者頁提供單筆新增與 CSV 匯入教師，沿用學生名單匯入的檢查與第 34 項「首次登入驗證信箱並改密碼」。現況是教師先自行註冊、再由管理員改角色，複評當場說「老師也用同樣方式匯入」不正確。可與 Notion「名單匯入改掉『初始密碼＝學號』」合併處理；接學校單一登入列為未來工作。
- **自接模型連線**（來源：複評 2-2，2026-10-25 使用者同意方向）：**已納入第一版（第 41 項），細節在工單定案。**管理員新增連線，填名稱、類型（OpenAI 相容／Gemini／Anthropic）與端點網址；金鑰參照環境變數名稱，不存資料庫（第 1 項）；端點必須在環境變數的主機白名單內，只允許 http／https、不跟隨轉址、設逾時，新增前重新輸入密碼（第 29 項）並寫入 `adminAuditLogs`；模型清單用 `/v1/models` 抓取，開放前同樣通過第 13 項格式測試。其他格式由營運方自架 LiteLLM 轉接。vLLM、自架 Ollama（v0.5 起）的 OpenAI 相容 API 支援以 `json_schema` 限制輸出格式。現有 OpenAI 呼叫把網址寫死為 `api.openai.com`（[回答生成](../../../backend/src/services/answerGeneration.service.js)），實作時要改。**向量維持 `gemini-embedding-2`**：文字、影像、聲音在同一空間，地端缺少可商用的同等多模態向量模型與算力（查證見[複評後續處理總表](../../01_系統手冊/審查與修訂/2026-10-22_複評回放/後續處理總表.md)）；對外說法是「回答可改用學校自己的模型，向量仍由 Gemini 產生」。
- **送出外部模型前遮罩個資**（來源：複評 2-2）：**已納入第一版（第 41 項），細節在工單定案。**學生提問中的學號、Email、電話，在送給外部模型（生成與查詢向量）前先遮掉；Jev 送 TypeSafe 前套用同一套規則（[Jev 決策](../Jev_Judgment/decisions.md)）。這是評審所說「資料清洗」的最小可行版，規則與測試資料在討論時定案。
