# 教授會議（Phase2 規劃與上線部署討論）

- 會議日期: 2026-07-07
- 會議類型: 教授會議（規劃討論）
- 與會者: 邱偉豪、張庭語、鍾百陶、張家瑜、蒯思齊(教授)

## 討論內容

1. 系統生命週期與上線觀念

- 背景：第一階段展示後，後續重點從單次 demo 轉向能否長期運作與持續迭代。
- 內容：
  - 老師提醒系統「開發完成」只是起點，上線後的持續運作、狀態監控與迭代才是重點。
  - 系統需要真實使用者持續使用，才能暴露穩定性、效能、流程與體驗問題。
  - 後續評審、比賽與求職展示中，上線後的完整系統能力會越來越重要。
- 結論傾向：Phase 2 不只補功能，也要加入可觀測性、真實測試與營運成本控管。

2. 部署策略與外部存取

- 背景：系統需要提供老師、學生或測試者實際使用，需決定部署環境與連線方式。
- 內容：
  - 建議先將系統部署至系上虛擬機測試，優點是免費，缺點是網速與硬體效能可能受限。
  - 若系上虛擬機效能不足，再遷移至公有雲，例如 Google Cloud。
  - 目前系統部署到系上虛擬機後，連線仍可能需要切換到學校內網或 VPN。
  - 可詢問系上技師能否申請固定 DNS；若不行，再評估 ngrok 付費固定網域或其他替代方案。
- 結論傾向：先用系上虛擬機做低成本驗證，再依效能與外部存取需求決定是否上雲。

3. API 費率上限與使用量控管

- 背景：AI API 若未設定上限，真實使用或惡意濫用可能造成不可控成本。
- 內容：
  - 老師提醒務必在雲端平台設定每月 API 費率上限。
  - 若開放學生測試，使用量與提問次數難以事先預估。
  - 系統需限制每位使用者的 token 用量，並設計定期重置機制。
  - 實際用量資料可回頭支撐商業模式與損益平衡估算。
- 結論傾向：成本控制需納入 Phase 2 系統功能，不應只依賴人工監控帳單。

4. 影片分段、Chunk Overlap 與多層向量索引

- 背景：影片問答品質取決於切段與召回策略，若切段不佳會造成語意遺失或回答片段不完整。
- 內容：
  - 單一長段向量容易過度平滑，細節會被平均化。
  - 切得太細雖保留細節，但使用者問較高層次問題時，系統可能只回傳局部片段。
  - 固定時間切段可能把一句完整語意截斷，導致單段內容不完整。
  - 老師建議加入 Chunk Overlap，讓相鄰片段保留部分重疊內容。
  - 後續可建立短期、中期、長期多層向量索引，以提升模糊問題或範圍較大問題的召回率。
- 結論傾向：Phase 2 的 RAG 前處理需從單層切段升級為有 overlap 與多層索引的設計。

5. 各成員 Phase 2 規劃

- 背景：第一階段完成後，需收斂暑假與第二階段各模組改善方向。
- 內容：
  - 影片上傳：實作老師上傳本地影片後，自動推送至 YouTube；圖片 embedding 與黑板文字讀取列為後續規劃。
  - AI 處理：支援批次處理多支影片、提升回答品質、降低幻覺、提升片段召回精準度，並維護詞彙修正字典。
  - 後端：統一資料結構格式，優化找不到答案時的回覆邏輯，整理上線環境設定與安全設定。
  - 前端：整合 YouTube Shorts 至系統頁面，修正手機版首頁與課程進度顯示問題。
- 結論傾向：Phase 2 以部署可用、資料結構收斂、召回品質提升與前端展示修正為主軸。

6. 短影片功能與常見問題資料庫

- 背景：可將高頻問題轉成短影片，提高學生複習效率並降低重複生成成本。
- 內容：
  - 定期收集使用者常問問題，生成 YouTube Shorts 並放在課程首頁。
  - Shorts 直接上傳至 YouTube，系統以 iframe 引用，不自行開發串流播放器。
  - 短影片可由原始課程影片剪輯，也可評估用生成式 AI 產生補充影片。
  - 需注意影片權限，若課程影片不應公開，應設定為不公開或 Unlisted。
  - 建立常見問題資料庫，相同問題可直接回傳既有短影片，減少 token 與製作成本。
- 結論傾向：短影片與 FAQ 資料庫可作為 Phase 2 的延伸功能，但要先處理權限與成本問題。

7. 比賽報名與後續文件

- 背景：專題可參加大專院校競賽與經濟部臺灣數創大賞，需要確認報名類別與文件時程。
- 內容：
  - 參賽類別建議選擇數位運算科技相關組，志願序以 4、3、2 為方向。
  - 7/10 前需完成比賽報名，8/7 前需繳交出賽文件。
  - 決賽可能需要準備海報與系統展示。
  - 撰寫計畫書或報告書時，需請 AI 協助找出相關學術參考文獻並列入報告。
- 結論傾向：比賽報名與文件整理需與 Phase 2 技術規劃同步推進。

## 決議事項

1. 系統先部署至系上虛擬機測試，若效能不足再評估遷移至公有雲。
2. 務必設定雲端 API 每月費率上限。
3. 系統需實作每位使用者 token 上限與定期重置機制。
4. 新增系統狀態監控功能，觀察穩定性、並發負載與上線後使用狀況。
5. 影片分段處理加入 Chunk Overlap，並規劃短期、中期、長期多層向量索引。
6. 短影片統一上傳 YouTube Shorts，系統以 iframe 引用。
7. 建立常見問題資料庫，避免相同問題重複生成。
8. 比賽報名選數位運算科技相關組，志願序以 4、3、2 為方向。
9. 7/10 前完成比賽報名，8/7 前繳交出賽文件。
10. 撰寫計畫書與報告時補入相關學術參考文獻。
