# recut 預覽與選段說明的體驗設計決策

這份文件收錄教師預覽示意圖與評估素材的確認題，讓設計討論以 repo 文件接續。產製規則與既定決策以 [recut 設計決策](recut-design-decisions.md)為準，本頁不重複建立另一套編號。功能完成與驗收只看[目前狀態](../../current-status.md)。

## 已定案與前提

- 第 57 項已定目的：實作前用靜態示意圖做啟發式評估，技術試跑後找 2～3 位代理使用者測操作；不能當成真實教師驗收。
- 第 68 項已定：有未套用修改就停用核准，須先套用或全部復原。
- 第 69 項已定：重配圖可取消；取消或失敗回原版、保留未套用修改，核准維持停用。
- 第 5 項限制冷開場：同一視窗、最多一次、3 秒內，其餘按原時間順序。第 50 項已允許點任一句試聽，包含跳過句；具體互動依 UX-19 與下方 Q3 定案，實際媒體仍須驗證。
- 2026-10-23 使用者補充介面要求：不能預設教師有資訊技術背景，試聽與預覽的操作必須直覺、減少切換與記憶負擔。片頭控制已由 UX-11 確認；試聽方式後續已配第六輪畫面依 UX-19 定案，仍須實作驗證。

## 畫面與操作名詞

本討論是 **recut 短影片的教師講稿與成品審閱介面**：用授課原音剪成 30～65 秒，配字幕與動畫圖卡。第一版由 AI 先選段並整理完整講稿，教師先審稿；通過後製作 MP4，再審成品。沒有系統初稿時從零手動選句已依 UX-6 延後。

- **選段說明**：教師進入修改或查核時，看這一段錄音轉錄後、逐句排列的文字，含保留／跳過與理由；可聽原音查核，不能因有逐字稿就假定辨識必定正確。新版圖②左側呈現修改已有選段，右側是原音試聽；圖④已移除從零手動挑句入口。
- **手動調整既有選段**：教師決定加回或移除哪些原話，系統仍負責配字幕、圖卡與動畫，不是要求教師寫完整施工單。沒有預覽時從零挑句另屬延後的進階流程。
- **完整講稿**：按這支短片的實際播放順序，顯示老師將說出的全部文字；供教師像讀文章一樣審閱。不把原課程整段逐字稿、字幕精簡版或圖卡參數混進閱讀版。這是原 Q5 經使用者修訂後的 UX-2。
- **可播放的瀏覽器預覽**：依第 6、38 項，在瀏覽器把切好的老師原音與動畫圖卡同步播放，讓教師看見、聽見預期效果；不是只有文字腳本，也還不是 worker 渲染完成的 MP4。依 UX-9 可作輔助，不要求講稿與成品之間多一次核准；新版圖①以完整講稿為主，不再放看似已完成的成品播放器。
- **成品**：教師核准講稿後，worker 渲染成 MP4，再交教師看實際成品；確認後才能發布。製作失敗或尚有修改時不進入發布。圖⑥是正常看片與決定的狀態；圖⑦是同一個成品審閱頁按「查核這段原話」後暫停短片、聽原音的狀態。⑦不是獨立頁面流程，也不是第三次審核。

2026-10-23 新版圖②的「聽老師原話」與右側試聽區呈現講稿階段；圖⑦呈現成品暫停後試聽、回原位置與播放狀態的提案。兩張都補上暫停、停止及返回說明，仍是靜態畫面；Q3 設計已依 UX-19 定案，不以畫出按鈕當成互動已驗證。

2026-10-23 使用者指出舊圖只突出核准、修改入口不明顯，且不能要求非剪輯背景的教師先理解時間軸與來源句編號。新版圖①直接呈現完整講稿與「修改內容」入口，依 UX-2 把逐句工具放在需要修改或查核時；具體畫面仍須確認。

**三種動作需區分**：套用 AI 建議已由 UX-3 定案；依 UX-9，講稿通過是確認此版可製作 MP4；成品核准後才可進入發布。不能把講稿上的「通過」等同已看過 MP4 或直接發布。AI 改動後須審新版對應內容，舊版成品核准不得沿用；是否需重新通過講稿依 UX-10 按修改類型判斷。

UX-4 的 Animate UI 局部比較應配合新順序：先完成講稿審閱頁，成品出來後仍可對照完整講稿；不為保留原分頁示例而把兩階段重新改回自由選一種首審。

## Animate UI 2 工具選型查證（2026-10-23）

使用者詢問 Animate UI 2.0 是否比目前工具更好、是否應更換；本輪只查官方資料與本機程式，未安裝、遷移、執行元件原型或量測效能。

- [官方更新紀錄](https://animate-ui.com/docs/changelog)：2.0.0 於 2026-10-18 發布，查閱時已列到 2.1.2（10/19）；v2 改為 npm 套件，動畫以 Motion 為基礎，支援 Radix UI、Base UI、React Aria。這是網站更新紀錄，不等同已查 npm registry 的最新版本。
- [套件文件](https://animate-ui.com/docs/react)：React 19 與 Motion 是共用依賴，其他底層元件庫按實際使用安裝；可逐元件匯入並自訂樣式，不必為此改整站視覺。[安裝文件](https://animate-ui.com/docs/installation)的 CLI 自動替換針對已存在的 shadcn 元件與 components.json。
- [無障礙文件](https://animate-ui.com/docs/accessibility)：官方描述有減少動態效果、鍵盤與焦點處理；實際 FocusFlow 整合仍須驗證，不能直接視為已通過無障礙測試。
- 本機 [frontend package](../../../frontend/focus-flow/package.json)為 React 19.2.4、自製 CSS／元件，另有 GSAP 與 Three.js，未列 Motion 或上述底層元件庫，本輪也未找到 components.json。因此 React 主版本符合不代表可以直接一鍵遷移；需新增依賴並適配元件、樣式與測試。
- 本機 [short_render package](../../../short_render/package.json)使用 GSAP 3.15.0 與 HyperFrames 0.8.153；[動畫 HTML](../../../short_render/src/render/html.js)建立受控 GSAP timeline。Animate UI 的主要用途是網頁互動元件，沒有本輪已查證的原音對時、施工單驗證或 MP4 渲染替換方案，因此不建議用它替換 recut 產製核心。

**取捨與確認範圍**：UX-4 已確認先用「看短片／看完整講稿」分頁做局部比較，保留短片渲染核心；AI 建議展開區、對話框與提示只列為比較後可能擴大的候選。潛在收益是統一互動與動效、減少部分自行維護工作；成本是額外套件、元件適配與回歸驗證。沒有實測前不宣稱更快、更輕或更好用，也不把同意比較解讀為整站導入。

## 本輪已定案明細（2026-10-23）

使用者看過第六輪修訂後回覆「OK，目前先這樣定案了」，本輪依 UX-19 收束為以下設計基準。第四輪淺色方向仍不採用；功能完成與驗收另依[目前狀態](../../current-status.md)及後續實測證據判定。

### Q3：試聽與短片預覽的互動

**決策**：採原頁「聽老師原話」，使用同一個可見的播放控制區，不跳頁或另開播放器。講稿階段試聽後保留閱讀位置；成品階段先保存 MP4 位置並暫停，標示正在聽原話，結束後回原位置與原播放狀態。若教師主動暫停或停止試聽，保持暫停，不自動接播。提供暫停、停止及返回控制；保留與跳過句均可查核，原音與成品不能同時播放。

**理由**：讓教師只需表達要聽哪句，系統處理來源切換並保存上下文，減少重新找位置的負擔；同時清楚顯示目前聲音來源，保留教師的控制權。

**後續驗證**：實際音訊結束事件、播放位置與狀態恢復、雙音源互斥，以及自動恢復是否造成混淆，須接入媒體後測試。設計定案不代表操作已驗證。

### Q4：七張圖與兩份評估文件的整體確認

**決策**：採 2026-10-23 第六輪七張 PNG、HTML 原型、啟發式評估檢查表與代理使用者測試腳本，作為第 57 項的評估素材。靜態評估可使用圖片；代理操作測試須待具備真實媒體的可操作版本，仍揭露測試者身分與模擬範圍。

**理由**：整組素材已依使用者逐輪回饋調整並取得本輪定案；將設計基準固定，後續評估才能對照同一版，不能把素材確認當成正式功能或教師驗收。

### Q12：AI 建議入口與成品頁資訊配置

**決策**：AI 建議入口移到內容上方，顯示數量並隨內容捲動保持可見；講稿與建議一次看一種內容。成品頁以「看短片／完整講稿／AI 建議」切換，右側只呈現目前任務的操作。查核原音時同一位置改放原音控制，結束後恢復。品質建議可不採納，不新增強制閱讀門檻；可信度錯誤沿用 recut 第 18 項。常駐資訊依 UX-18 精簡。

**理由**：避免長講稿底部的有用建議被漏看，以及右側同時堆積教學、建議與原音工具；讓教師一次專注一個主要任務，實際直覺程度仍由操作測試判斷。

### Q13：步驟列是否採小節點加細連線

**決策**：保留第六輪既有系統深色風格、小節點、完成勾號、簡短名稱與細連線，以及清楚講稿層級與集中的審閱操作。修改／套用時分別標示「修改講稿／更新講稿」，仍在第一階段；轉場節制並尊重減少動態效果偏好。線段不假裝工作百分比，不新增核准階段。

**理由**：以細長版面呈現教師審稿、系統製作、教師審片的離散關卡，兼顧目前階段辨識與 FocusFlow 既有視覺，不讓流程裝飾壓過閱讀內容。
