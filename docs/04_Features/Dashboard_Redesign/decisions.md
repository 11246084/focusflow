# 管理員介面與教師儀表板重調設計決策

這份文件記錄管理員七個頁面與教師儀表板重調的討論：現況、可用的資料、已定案的方向，以及要逐題定案的問題。它讓接手的人或 AI 不用重讀對話就能接續；目前第一輪題目還沒回答，請 Weihao 逐題回覆。功能是否完成只看[目前狀態](../../current-status.md)。

範圍是管理員的系統總覽、使用者、課程、影片、YouTube 上傳、問題回報、使用統計，以及教師的總覽頁。不含學生端、短影片製作與管理頁（見[短影片決策](../Short_Video/decisions.md)）與對話欄（見[對話功能優化](../QA_Conversation/decisions.md)）。

## 名詞

- **儀表板**：登入後第一眼看到、用來掌握狀況的頁面。這裡指管理員的系統總覽、使用統計，與教師的總覽。
- **洞察**：從學生的提問與觀看紀錄整理出來、能讓教師決定下一步的資訊，例如「這一段很多人問、而且常答不出來」。
- **待辦提醒**：需要這個人動手處理的事，例如處理失敗的影片、等待確認的短影片。
- **答不出來的提問**：系統找不到足夠的課程內容而回覆無法回答的題目，問答紀錄的狀態是 `no_match`。

## 目前這一輪待答題目

第一輪只問會決定整體方向、而且不需等其他答案的題目。各頁的版面、指標的計算方式、API 的格式、五個表格頁的逐頁檢視，依本輪答案在下一輪提出。

### Q1：教師可以看到個別學生的哪些資料

**問題**：教師追蹤個別學生時，是否可以看到「這位學生的姓名、他問過的問題原文、看完哪些影片、最近的活動時間」？

**建議答案**：可以，但有三個條件：

1. 只限教師自己授課的課程，而且只看得到該課程內的紀錄。
2. 上線前在學生端加上告知，讓學生知道授課教師看得到他在這門課的提問與觀看紀錄。
3. 不顯示學生的 Email、LINE 帳號，也不顯示他在其他課程的紀錄。

**理由**：這是整個設計的前提，所以先問。你要的「追蹤個別學生」一定要能對到人，匿名的話只能做到課程層級的洞察。但這是系統第一次讓教師看到個別學生的提問原文：學生可能問得很基礎，知道老師看得到之後有人會不敢問。告知是最低限度的做法；是否需要指導教授或學校同意，請你判斷，我無法替你確認。

**替代方案**：教師只看得到每位學生的數字（提問次數、看完幾支影片、最近活動），提問原文只在課程層級以不具名的方式顯示。隱私風險低很多，但教師無法知道某位學生到底卡在哪裡。

### Q2：教師儀表板要回答哪幾個問題

**問題**：教師儀表板是否以下面四個問題為主軸，依序由上往下排？

**建議答案**：是。

1. **有什麼事等我處理？** 處理失敗的影片、等待確認的短影片。沒有待辦時這一區不出現。
2. **學生在問什麼？** 依課程切換；顯示這段期間的提問量與變化、問題的主題（相近的問題歸在一起，顯示幾個人問）、答不出來的題目。
3. **哪些內容需要補強？** 最常被問的影片段落、答不出來的題目集中在哪幾支影片。
4. **哪些學生需要關心？** 選了課但近期沒有活動的學生、提問很多或常得到「答不出來」的學生；點進去看個別學生（依 Q1 的結論決定看得到什麼）。

現在的「課程數量、影片數量、AI 片段」三個總數拿掉或縮到不顯眼的位置。

**理由**：這四個問題都對應到教師可以採取的行動（處理、補充教材、重錄某一段、聯絡學生）。課程與影片的數量教師自己就知道，放在最顯眼的位置沒有幫助。所需的資料都已經在資料庫裡。

### Q3：管理員系統總覽要回答哪幾個問題

**問題**：管理員系統總覽是否改成以下面三個問題為主軸，並把「使用統計」頁併進來？

**建議答案**：是。

1. **系統現在有沒有問題？** 服務狀態，異常與降級的項目排最前面並放大，正常的項目收成一行；包含已定案的 Gemini 狀態。
2. **有什麼事等我處理？** 尚未處理的問題回報、YouTube 即將到期或被隔離的原片、等待驗證過久的帳號。
3. **系統有沒有人在用？** 這段期間的活躍人數、提問量、影片觀看量，附上和前一段期間的比較與每日變化。

使用統計頁的四個數字併入第 3 點；原始事件表改成可以依事件類型與課程篩選的紀錄頁，或直接拿掉。導覽從七項減為六項。

**理由**：管理員打開總覽是為了確認「有沒有事」。現在最需要注意的服務異常排在右下角，累計總數反而最顯眼。總覽和使用統計兩頁都在講使用量，分成兩頁只是讓人多點一次。

### Q4：其餘五個管理員頁面要改到什麼程度

**問題**：使用者、課程、影片、YouTube 上傳、問題回報這五頁，是否採「統一表格頁的做法，不重新設計各頁的功能」？

**建議答案**：是。五頁共用同一套做法：搜尋與篩選放在同一列、表格欄位與列的動作位置一致、空白、載入中與錯誤三種狀態一致、樣式改用設計文件的變數。各頁現有的功能不增不減。逐頁要調整什麼，等我截圖檢視後在下一輪列出。

**理由**：這五頁是「找到某一筆並對它做事」的工具頁，價值在一致與好找，不在版面新穎。YouTube 上傳頁有 561 行，功能最多，要不要另外處理也等檢視後再提。

### Q5：分幾批做、先做哪一批

**問題**：是否分成三批，順序為「①教師儀表板 → ②管理員總覽（含併入的使用統計） → ③五個表格頁」？

**建議答案**：是，每一批各自定案細節、實作、審查、上線。

**理由**：教師儀表板是你最在意、也是對使用者價值最高的一項，而且前後端都要改，先做可以先確認「洞察」這條路走得通。五個表格頁只改前端，風險最低，放最後。

### Q6：洞察的時間範圍與更新方式

**問題**：儀表板的數字是否預設看「最近 7 天」，可以切換成 30 天或整個學期，而且每次打開頁面時即時計算，不另外建彙整資料？

**建議答案**：是。

**理由**：目前的資料量很小（六支影片、幾百筆提問），即時計算不會慢，也不必新增資料表或排程。等資料量大到變慢再改成預先彙整。這一題先定，是因為它決定後端 API 要不要新增資料表；新增資料表與索引屬於共用資料庫的變更，要另外授權。
