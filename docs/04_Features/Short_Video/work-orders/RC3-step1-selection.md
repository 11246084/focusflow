# 工作說明：recut RC3（第一步選段）

分支 `wip/recut-rc3-selection`，從 `feat/recut` 切出（RC1 已合併）。先讀 `AGENTS.md` 與 [HANDOFF.md](../HANDOFF.md) 的「必守規則」。

這張工單讓 Gemini 從編號句子中挑出回答學生問題需要的範圍，並由程式驗證。**不呼叫真的 Gemini**，測試一律用假的 `fetchImpl`。

## 先讀

1. [recut 設計決策](../recut-design-decisions.md)第 4、5、17、18、25～27、34、44、47～49、53、56、59、64、72、87 項，「階段與檢查」表的「①選段」列。
2. [體驗設計決策](../decisions.md) UX-1、UX-8、UX-11、UX-12。
3. 系統設定的 `getSetting`：[S1 工單](../../System_Settings/work-orders/S1-settings-core.md)與[系統設定決策](../../System_Settings/decisions.md)第 3、40 項（recut 模型存 `{ provider, model }`，初次生成與套用建議的呼叫上限預設各 5 次）。
4. 8 拍生成的 Gemini 呼叫與重試寫法：`backend/src/services/shortScriptGeneration.service.js`（只參考，不改）。
5. RC1 回報中的句子清單格式、任務紀錄與步驟介面。

## 要做

1. **設定讀取**（第 53、59 項）：recut 的模型與兩個呼叫上限一律透過 `getSetting` 讀取。系統設定 S1 還沒合併進 `dev` 時，寫一個只讀環境變數、函式簽名與鍵名與 S1 相同的轉接函式，並在回報中說明之後怎麼移除。
2. **Gemini 呼叫**（第 44、49 項）：用 `responseSchema` 固定輸出格式，**不帶 temperature、topP、topK**；判斷集中在可替換的判斷點介面（第 44 項）。每次嘗試依第 64 項存輸入、輸出、驗證結果、模型 ID、`usageMetadata`、耗時。
3. **共用呼叫額度**（第 34 項、UX-8、UX-12）：任務開始時固定上限；每次呼叫從同一個池子扣；重試時附上一次的輸出與錯誤說明，只重做出錯的步驟。
4. **第一步的輸入與輸出**（第 26、47 項）：輸入代表題、提問次數最多的 5 個同義問法、編號句子（命中的加 ★）；輸出 `from`／`to` 範圍（可多段，播放依時間順序）、需要時的 `startAt`／`endAt` 原話片語、視窗內每一句的理由標籤（保留：結論或定義、理由、例子、冷開場；跳過：複習、離題、指畫面、重複）、片頭重點句（第 5 項：同一視窗、最多一次、3 秒內）。
5. **無法回答**（第 27、56、72 項）：Gemini 可回報無法回答與原因，此時每句仍標跳過類標籤；任務停止、不重試，原因存給教師看。第一版不提供教師從零手動選句。
6. **程式驗證**（第 4、18、25、48 項）：`startAt`／`endAt` 只在那一句內比對，找不到算可信度錯誤；標籤與範圍必須一致、每句都有標籤；總長用逐字時間算，必須在 30～65 秒；片段頭尾標成「指畫面」的句子由程式自動剪掉（第 18 項），中間的不自動剪。不通過時依第 34 項退回第一步。
7. **指示文字**（待答 R1、決策第 87 項）：第一步的指示、八種理由標籤的定義與正反例，放在單一檔案（程式內常數或範本），並在 `backend/docs/` 附一份給人看的版本。完成後另開子 agent 依決策逐條檢查指示與 `responseSchema`、驗證器的要求是否一致，依結果修正，檢查結果附在回報。
8. 依第 70 項記錄選段驗證與總長計算的方法。

## 測試

全部用假的 Gemini 回應。至少涵蓋：正常選段；多段範圍；`startAt` 找不到；標籤與範圍矛盾、漏標；總長不足與超過；頭尾「指畫面」句自動剪除後重算總長；無法回答時停止且不重試；重試附上前次錯誤；額度用完時任務失敗並保留紀錄；請求不含取樣參數；模型 ID 來自設定讀取函式。

## 完成時回報

commit 清單、測試結果、和本工單不同之處、轉接函式的移除方式、指示文字的位置與子 agent 的檢查結果，以及給 RC4 的介面（選段結果格式、額度與紀錄函式）。
