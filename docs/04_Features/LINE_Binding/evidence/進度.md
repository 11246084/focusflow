**已確認並修復**

- 停用的帳號仍可在 LINE 提問：網頁登入會擋 `isActive === false`（`auth.middleware.js`），LINE 沒有檢查。現在 `processWebhookEvent` 對已綁定但停用的帳號一律回停用提示，不提問、不切換課程、不查額度；綁定資料保留，重新啟用後照常使用。`bindLineAccount` 也拒絕停用的帳號（`user_inactive`），LINE Login 對應 403 `USER_INACTIVE`（已補進 OpenAPI），沒有對應的失敗原因不再變成 500。停用的帳號重新加好友時，歡迎訊息改為停用提示。
- 回答卡第一筆引用可能連到別段：`clip` 取自回答的第一筆證據，那筆證據沒有可播放來源被濾掉時，第一筆引用會換成別段，按鈕卻沿用 `clip` 的連結。現在只有 `clip.segmentId` 與該筆引用相同時才沿用（`citationLink`）。
- 對話歷史寫回：等回答的十幾秒內學生解除綁定、改綁或切換課程時，舊課程的對話會寫回已清空的歷史。現在寫回前比對 `lineUserId` 與 `activeCourseId` 沒有改變。
- webhook 簽章改用固定時間比較（`crypto.timingSafeEqual`）。
- 網頁回呼頁：LINE 導回的 `error` 不是 `access_denied` 時不再顯示「你取消了授權」；`LINE_BINDING_CHANGED` 有自己的文案，不再顯示「帳號沒有變更」。
- 以上修正由另一個獨立的審查逐項複核，沒有發現阻擋性問題；複核後補的停用帳號加好友文案與 OpenAPI 描述也另外複核通過。
- 回歸測試：`backend/tests/line.routes.test.js` 的「LINE 審查修正回歸」16 項、`frontend/focus-flow/tests/lineLogin.test.js` 2 項。

**待確認（需要百陶或實機）**

- LINE 後台是否開啟 webhook 重送。問答在 webhook 回應前同步執行（十幾秒），重送開啟時同一題可能被處理兩次、提問次數也算兩次；程式沒有用 `webhookEventId` 去重。先在 LINE Developers Console 確認設定，開啟的話再補去重。
