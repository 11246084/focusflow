# 上傳影片到產出短片的彩排檢查表

這份檢查表用來在正式站模擬決評現場的要求：教師上傳一支新影片，系統處理完後學生立刻提問，最後把提問做成短影片。照著做一次，就能知道每一段要花多久、哪一段會失敗，再決定現場要展示到哪一段。結果填在每一段的「實際」欄。

## 先知道的限制（2026-11-19 查證程式與文件）

- **多模態向量不會自動完成**。上傳後的多模態處理要在 VM 設定 `UPLOAD_MULTIMODAL_MODE=gemini` 等付費設定才會跑；跑完之後寫入 Atlas 還要人工執行指令並核准（[多模態接手說明](../04_Features/Multimodal_Retrieval/HANDOFF.md#新上傳影片)）。這次彩排先確認 VM 目前的設定，**不在彩排中開啟付費模式**；要開的話另外決定。
- **新影片多模態處理中時，整門課會退回只用文字**，FAQ 快取也暫停。所以上傳到 AI入門基礎課這類主要展示的課程，會影響整門課的回答。
- **短影片的選題要至少 2 位不同學生問過相近的問題**才會出現。新影片沒有任何提問，所以彩排要用兩個學生帳號提問。
- **recut 今天的失敗率很高**（見[正式站實測](2026-11-19_決評demo實測.md) A1），這一段最可能卡住。

## 彩排步驟

依評審在現場的順序進行。每一段失敗就記下畫面上的訊息與截圖，然後**繼續做下一段能做的**，不要整個停下。

| # | 步驟 | 怎麼做 | 通過標準 | 實際（時間、結果） |
|---|---|---|---|---|
| R1 | 教師上傳 | 教師帳號在「上傳影片」選 P2 的課程，上傳 P1 的影片 | 上傳完成，影片出現在課程裡，狀態變成處理中 | |
| R2 | 轉文字與建立索引 | 在課程管理或管理員「影片」頁看狀態，每分鐘看一次 | 狀態變成「完成」、片段數大於 0。記下從上傳完成到「完成」花了幾分鐘 | |
| R3 | 多模態處理 | 看影片的處理狀態裡有沒有多模態那一項 | 依 P4 的結果判斷：沒設定就記「未啟用」；有設定則記下它停在哪個狀態 | |
| R4 | 學生提問 | 學生 A 進入課程，選這支影片，問 3 題影片裡講過的內容，並按一次「這段在講什麼」 | 回答切題，來源指向這支新影片，時間點合理；記下每題等待秒數 | |
| R5 | 第二位學生提問 | 學生 B 問 2 題和學生 A 相近的問題 | 回答切題 | |
| R6 | 選題 | 教師到「短影片管理」→「製作新短片」，選這門課 | 候選清單出現 R4、R5 的題目，顯示 2 人提問 | |
| R7 | 產生講稿 | 用原片剪輯（recut）開始製作，等講稿產生 | 講稿產生成功，總長 30～65 秒；記下花了幾分鐘與是否需要重試 | |
| R8 | 製作短片 | 確認講稿後開始製作 | 成品產生，可以在工作區播放；記下花了幾分鐘 | |
| R9 | 上架 | 核准上架 | 上傳到 YouTube 成功並變成可播放 | |
| R10 | 學生看到短片 | 學生 A 打開「教學短片」 | 看得到新短片且能播放 | |

## 收尾

- 彩排產生的課程、影片、提問與短片要不要保留，由 Weihao 決定。保留的話可以直接當作現場「接續展示」用的那一份。
- 彩排會產生 Gemini 與 YouTube 的實際用量，也會出現在教師與管理員的統計裡。
