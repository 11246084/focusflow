# recut 教師審閱啟發式評估檢查表

建立：2026-10-21；本版修訂：2026-10-23 第六輪。資料夾與既有 PNG 檔名保留，畫面已依「先審講稿，再審影片成品」重製。

這份檢查表讓沒參與 recut 設計的組員，在寫程式前對照 Nielsen 十大可用性原則找操作問題。依 [recut 設計決策](../../recut-design-decisions.md)第 57、73～75 項及[體驗決策](../../decisions.md)，本版檢查講稿審閱、修改與成品審閱；不是教授實測，也不是功能驗收結果。

## 怎麼做

1. 找 1～2 位沒參與設計的組員，各自獨立評估，預留每人約 40 分鐘。
2. 先讀情境，依①→②→③→⑤→⑥→⑦檢查主線，再看④的例外情境；順序是評估導覽，不代表每次操作都必經所有畫面。
3. 每張先說出「現在要確認什麼、下一步按什麼」，再看下表。不能操作的地方只記錄預期，不能據此宣稱操作成功。
4. 每個問題記最主要的原則，給 0～4 嚴重度；獨立填寫後再合併重複問題、討論分歧。
5. 3、4 級問題應先改設計；實作後另依[代理使用者腳本](proxy-user-test.md)驗證操作。

**情境**：你是教 OpenCV 的老師。系統為「OpenCV 跟 YOLO 差在哪」選取你課堂的原話，整理成完整講稿。你先確認要說什麼，通過後才製作短片；影片完成後再確認聲音、字幕與畫面，決定修改或核准發布。

| 嚴重度 | 意思 |
|---|---|
| 0 | 不認為是可用性問題 |
| 1 | 外觀小問題，有空再修 |
| 2 | 小問題，修的優先度低 |
| 3 | 大問題，應優先修 |
| 4 | 嚴重問題，實作前一定要修 |

## 檢查問題

| 原則 | 主要看 | 檢查問題 |
|---|---|---|
| 1 系統狀態要看得到 | ①②③⑥⑦ | 分得清待審講稿、未套用、更新中、成品待發布嗎？⑦知道短片暫停在哪裡、目前聽的是原音嗎？ |
| 2 用使用者熟悉的話 | 全部 | 「完整講稿」「修改內容」「片頭重點句」「聽老師原話」是否容易理解？是否仍需要先懂剪輯、編號或時間軸？ |
| 3 使用者能控制、能反悔 | ②③⑦ | 找得到復原、取消、暫停與停止嗎？取消／失敗後知道原版與未套用修改都保留嗎？主動停止後是否會擔心突然播放？ |
| 4 一致性與慣例 | ①⑤⑥⑦ | 「套用建議」「通過講稿」「核准發布」的對象是否清楚且一致？同樣的試聽狀態與控制是否用相同名稱？ |
| 5 預防錯誤 | ②③⑤⑥ | 有未套用修改時核准是否確實停用並說明原因？是否知道刪除片頭句會改變開場？是否會把套用建議或通過講稿誤認為發布？ |
| 6 看得到，不用記 | ①②⑤⑦ | 完整講稿能否直接讀懂？修改時流程是否顯示「修改講稿」？新增／移除、建議影響與試聽返回位置是否清楚？ |
| 7 彈性與效率 | ①②⑥⑦ | 不修改的老師能否直接審稿？只在需要時才展開逐句工具嗎？試聽後能否保留閱讀位置或播放狀態？ |
| 8 簡潔，不放多餘資訊 | ①②⑤ | 是否移除重複的審閱順序說明框？AI 建議入口與數量是否在長講稿上方且捲動可見？⑥右側是否聚焦單一任務？ |
| 9 幫使用者看懂錯誤並復原 | ③④ | 看得懂失敗原因、保留了什麼、下一步可以怎麼做嗎？④是否讓人誤以為還能從零手動挑句？ |
| 10 說明與文件 | ②⑥⑦ | 片頭重點句與原音試聽有沒有必要的白話說明？只改字幕與改講述內容的回審差異能否理解？ |

## 已定案設計與待驗證項目

- **Q3 試聽互動**：②示範講稿階段原地聽原音、保留閱讀位置；⑦示範成品先暫停、試聽後回原位置與原播放狀態。主動暫停或停止不得再自動接播。設計已依 UX-19 定案，仍需用具備實際媒體的可操作版本測試是否順暢。
- **Q12 資訊配置**：①⑤的講稿／AI 建議分頁、⑥的精簡操作區與按需要查核原音已定案。檢查入口會不會漏看、內容切換是否增加負擔；不新增強制閱讀建議的門檻。
- **Q13 步驟方向**：本輪在既有系統深色風格內保留小節點、細連線與內容層級；淺色方向已否決，第六輪已定為本輪設計基準。
- **Q4 整體素材**：第六輪整組素材已定為評估基準；素材確認不等於功能已驗收。
- 未套用時停用核准、可取消更新、取消或失敗保留修改、從零選句延後及片頭控制已有定案，不再列為未定事項。
