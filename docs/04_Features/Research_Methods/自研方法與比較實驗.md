# FocusFlow 自研方法與比較實驗

這份文件回應 2026-10-22 複評評審 2-3「有沒有自己的模型或演算法」，整理團隊在檢索、選段、驗證與評測上的具體工作。每項分開說明程式證據、設計與實驗缺口，供評審判讀及教授選定後續研究題目。證據核對日期為 2026-10-25；功能可用範圍與驗收情形仍以[目前狀態](../../current-status.md)為準。

## 給評審的回答

FocusFlow 使用現成模型產生向量及回答，團隊自行設計檢索範圍、上下文組合、引用驗證、快取重用與評測流程。這些方法讓模型依課程影片作答，並讓學生能回到來源，而不只是把問題直接送給模型。

目前沒有自行訓練或微調模型的完成證據。分層檢索有程式與隔離驗證，但還不能說已證明優於一般檢索；recut 的選段設計與本機渲染原型也必須分開看。運用通用檢索、快取及驗證方法，不等於提出學術上全新的演算法；若要主張研究貢獻，仍需基準線與比較實驗。

問題來源：[評審問答 2-3](../../01_系統手冊/審查與修訂/2026-10-22_複評回放/評審問答.md#2-3-自有模型與演算法)、[後續處理總表](../../01_系統手冊/審查與修訂/2026-10-22_複評回放/後續處理總表.md)。以下的「已有證據」只涵蓋各份紀錄所列的日期、資料與環境，不代表本次重新執行實驗或正式部署驗收。

## 一、分層檢索：先找主題段落，再取可引用片段

### 解決什麼問題

逐字稿切成小片段後，定義、理由與例子可能分在不同片段。只按向量相似度取前幾筆，容易找到例子的開頭，卻漏掉後面的解釋；模型沒有拿到的內容，無法只靠修改提示詞補回。

### 現成 API 之外，自行處理什麼

分層檢索先搜尋較大的主題段落（Parent），再依其子片段編號找回可引用的逐字稿（Leaf）。程式檢查課程與影片範圍、去除重複片段，限制上下文的片段數與字數；Parent 搜尋或展開失敗時，依設定退回一般 Leaf 檢索。

輸入是問題向量與允許存取的影片；輸出是帶有影片、時間與逐字稿的小片段。這是團隊實作的檢索組合與安全規則，向量本身仍由外部模型產生。

### 已有證據

- [分層檢索入口](../Hierarchical_Retrieval/README.md)收錄資料契約與隔離驗證紀錄。
- [檢索主流程](../../../backend/src/services/hierarchicalRetrieval.service.js)串接 Parent 搜尋、子片段展開、上下文組合與退回機制；[子片段展開](../../../backend/src/services/childExpansion.service.js)與[上下文組合](../../../backend/src/services/leafContextAssembly.service.js)處理範圍、去重及容量限制。
- [服務測試](../../../backend/tests/hierarchical-retrieval.service.test.js)與[QA 整合測試](../../../backend/tests/hierarchical-retrieval.qa.integration.test.js)涵蓋關閉時沿用 Leaf、允許範圍、Leaf 引用及失敗退回；有測試程式不等於本輪已重跑。
- [2026-08-09 審查快照](../Hierarchical_Retrieval/evidence/Phase2-2_Hierarchical_Retrieval_Gate_Review.md)記錄 1 支影片、3 筆 Parent、9 筆 Leaf、4 個隔離問題；18/18 引用的編號與時間有效。這只支持該樣本的引用完整性；同份紀錄也指出，3 個相關問題中有 2 個回傳資料不足。

### 還缺什麼實驗

以同一批影片、題庫、向量與回答模型，比較一般 Leaf 檢索及分層檢索；兩組都停用 FAQ 干擾，固定上下文預算並記錄實際使用量。量測正確片段覆蓋、回答率、回答品質、引用正確性、退回比例與延遲，才知道分層是否值得額外成本。

需先確認 Parent 資料覆蓋與契約相容；歷史快照中的資料筆數不代表今日 Atlas 現況。現有證據不足以宣稱分層提高正確率、適用全課程或已正式啟用。

## 二、recut：可追溯的選段、剪接與內容檢查

### 解決什麼問題

短片不能只挑幾句看似相關的話。定義、理由與例子要接得起來，剪接不能切掉半個字，字幕與圖卡也不能出現老師沒講過的數字；否則畫面流暢仍可能傳達錯誤內容。

### 現成 API 之外，自行處理什麼

[recut 設計決策](../Short_Video/recut-design-decisions.md)第 25、27、47、48 項採用「句子編號＋句內微調」：Gemini 看整段錄音內容選連續範圍，為每句加保留或跳過的理由，程式檢查標籤與實際選段一致。不能回答原問題時停止，不強行湊片；第 18、33、34 項再分開處理引用、數字等可信度錯誤及需人工判斷的品質問題。

句子間的連貫性由 Gemini 看整段判斷，並由教師審閱；沒有證據顯示已完成獨立的逐句依賴圖或片段最佳化演算法。這些設計不能寫成團隊已實作一套能自動求出最佳選段的演算法。

### 已有證據

- [本機工具說明](../../../short_render/README.md)明列與後端的整合界線：已有 plan 驗證與渲染原型，後端呼叫、模型自動產生 plan 及教師操作介面不能據此判定完成。
- [plan 驗證器](../../../short_render/src/plan/validators.js)檢查引用是否存在、文字錨點是否出自證據、畫面數字是否有出處或可重算，以及對齊後的時間；[對齊程式](../../../short_render/src/plan/resolve.js)把文字錨點轉成時間，並將剪點移到合適的靜音處。
- [驗證測試](../../../short_render/tests/plan.validate.test.js)含不存在的引用、無出處數字等負面案例。本機工具說明另記錄 2 份手寫 plan 的對齊、預覽與渲染試跑；其證據來自原型 ASR，並非資料庫實際 chunk。
- 上述原型不等於新版逐句標籤設計已完成；數字與錨點通過檢查，也不能證明整段語意正確。工具說明仍列有成品未實聽、模型能否穩定產生合法 plan 未驗證等限制。

### 還缺什麼實驗

依設計第 40、41、52 項完成 10 個主題試跑，包含可能無法回答的題目；相同輸入各跑 3 次，量測選段秒數重疊與理由標籤差異。與人工選段及簡單連續取段比較，檢查答案完整性、語意連貫、剪點及引用錯誤。

另記錄講稿審閱、成品審閱與等待製作的時間，以及教師加回／移除句子的次數。設計中的秒數、重疊比例或修改量門檻是待驗證目標，不能當實測成果；成品仍需實聽與人工確認。

## 三、Jev 與 Gemini：比較方法的設計及採用界線

### 解決什麼問題

模型的信心值、格式正確或與另一模型答案一致，都不直接代表判斷正確。若以 Gemini 的答案當標準再評 Jev，量到的主要是兩者是否一致，無法知道誰比較符合教師的選段需求。

### 現成 API 之外，自行處理什麼

[2026-10-19 Jev 證據整理](../Short_Video/evidence/2026-10-19_jev-independent-evaluation.md)區分廠商自報、獨立驗證與個人心得，並提出用人工標註比較的辦法。方法重點是相同輸入、固定版本、重跑檢查，以及以相關句子組成的「視窗」計算不確定性，不把同段的每一句當成互相獨立的樣本。

### 已有證據

- 該文件「技術試跑時建議怎麼比較」提出至少 20 個視窗、約 800 句的人工標註，包含部分雙人重疊標註；每個視窗跑 3 次，記錄保留句的精確率、召回率與 F1、能否回答、延遲及成本。**這些是建議的樣本量與方法，沒有本專題完成的比較結果。**
- 證據文件仍留有「試跑時比較 Jev」的舊提案；較新的 [recut 決策](../Short_Video/recut-design-decisions.md)第 46 項已明確取消 recut 的 Jev 逐句版本及比較，改採 Gemini。不能把舊提案當成尚須執行的 recut 任務。
- Jev 的另一應用方向是[問題守門與 LINE 意圖分類](../Jev_Judgment/decisions.md)，屬不同任務，應按其決策另行驗證；這份論述不據此宣稱已整合或已優於規則／Gemini。

### 還缺什麼實驗

若教授選定模型判斷比較為研究題目，先確認適用任務及授權，再建立該任務的繁體中文人工答案、雙人一致程度與未參與調整的測試集。recut 的舊比較規劃不因此自動恢復。

外部測評只能協助提出假設，不能代替本課程口語逐字稿的實驗；原文件的外部模型版本、價格與勝負數字本輪未重新查證，這裡不轉列為目前事實。

## 四、問答評測：用課程題庫找出生成與檢索缺口

### 解決什麼問題

回答通順不代表有課程依據；同樣地，模型誠實拒答也可能是檢索漏掉正確片段。必須把「答對」「忠實引用」「答完整」分開評，才能決定下一步改檢索還是生成規則。

### 現成 API 之外，自行處理什麼

團隊依逐字稿建立[50 題題庫](../QA_Evaluation/datasets/question-bank.json)，記錄應包含的要點、正確影片及時間範圍。[評分方法](../QA_Evaluation/README.md)分正確性、忠實性、完整性、引用與時間戳、清晰度、拒答恰當性六面向；忠實性或引用分數過低時，總分上限設為 2，避免通順文字掩蓋嚴重錯誤。

### 已有證據

- 題庫涵蓋 AI 入門基礎課 6 支影片，分單片段、跨片段、跨影片、名詞、時間定位、課程外負向與口語錯字 7 類，共 50 題；資料來源及限制見[評測說明](../QA_Evaluation/README.md)。
- [2026-08-24 首輪](../QA_Evaluation/reports/2026-08-24-評測結果.md)與[2026-09-03 第二輪](../QA_Evaluation/reports/2026-09-03-第二輪評測結果.md)使用同一份 50 題、memory 檢索模式，FAQ 命中皆為 0。加權分數由 4.35/5 變成 4.68/5，完整性由 3.62 變成 4.30，假拒答由 5 題變成 1 題。
- 第二輪同時包含回答提示規則與問答契約修正，量到的是合併效果；不能把差異歸因給某一條提示、分層檢索或新模型。X02 原始請求曾連線失敗而走替代回答，報告評分採用補跑結果，原始紀錄保留。
- [第二輪原始結果](../QA_Evaluation/runs/2026-09-03T10-20-49-416Z/results.json)保存問題、回答與命中片段。報告對 D01、M04 的核對發現相關內容未進入提示，修正了首輪「都是生成問題」的診斷；D05 仍有檢索失敗。

### 還缺什麼實驗

現有資料未提供已完成的獨立盲評與評分者一致率；只在單一課程反覆使用同題庫，也可能逐漸針對已知題目調整。需增加未見題與其他課程，將調整用資料及最終測試資料分開，並讓第二位評分者獨立評部分重疊題。

後續比較固定檢索、模型及其他規則，一次只改一個因素，記錄重跑差異與失敗／補跑處理。上述分數是兩次歷史紀錄，不代表目前版本、Atlas 檢索或學生實際學習成效。

## 五、FAQ 快取與成本控制：減少重算並限制估計用量

### 解決什麼問題

學生常問相同問題，全部重新檢索及生成會增加等待與模型呼叫；但把依賴上一輪對話的答案拿給另一位學生，又可能答錯。快取必須同時考慮課程範圍、來源有效性與上下文。

### 現成 API 之外，自行處理什麼

[FAQ 服務](../../../backend/src/services/faqCache.service.js)先正規化問題文字，再做同課程精確比對；未命中時，可用問題向量的餘弦相似度找近義題。這是兩層通用快取方法的系統實作，另加容量淘汰及內容變更失效處理。

[問答主流程](../../../backend/src/services/qa.service.js)在重用前檢查存取權限、影片範圍與答案證據版本；有對話歷史時不讀寫共用 FAQ，降級或無法回答的結果也不寫入。精確命中省掉該次新問題向量及回答生成；語意命中時問題向量已經計算，不能說兩種命中都零成本。

### 已有證據

- 問答主流程的 `respondFromFaqCache` 與 `shouldSaveFaq` 分開控制重用及寫入；儲存的是回答實際使用的文字證據，舊快取缺證據版本時會略過重算。
- [FAQ 測試](../../../backend/tests/faq-cache.service.test.js)涵蓋文字正規化、同題更新、語意門檻、容量淘汰及課程內容變更失效。測試案例可支持規則存在，不能當作學生真實命中率或付費節省比例。
- [成本控制程式](../../../backend/src/services/costControl.service.js)以 UTC 月份統計提問事件，再乘上每問估計 token 數，檢查全站及個人額度；[問答測試](../../../backend/tests/qa.service.test.js)有額度不足回傳 `QA_QUOTA_EXCEEDED` 的案例。
- 這是事件數推估，並非逐次供應商實際 token 計費；精確快取命中先於該額度檢查，不能把此機制描述成所有請求一律被限制或帳單的硬上限。

### 還缺什麼實驗

用固定問題集比較停用、精確快取及語意快取三種情況，區分首次與重複提問，記錄命中率、近義誤命中、過期答案、模型呼叫數與延遲。來源或對話條件改變時，也要檢查是否正確重算。

實際費用需以供應商回傳的用量、模型版本及對應價目核算，再與帳單核對；另驗證併發下的額度行為。現有程式能說明如何減少重算，還不能量化正式環境節省多少錢。

## 與教授討論的研究順序

1. **先比較一般檢索與分層檢索**：沿用題庫的影片及時間標註，補足 Parent 覆蓋後量正確片段覆蓋與回答品質；多模態融合比較依[複評後續處理總表](../../01_系統手冊/審查與修訂/2026-10-22_複評回放/後續處理總表.md)另行設計，不把尚未接入的聲音檢索列為成果。
2. **量 FAQ 的收益與誤重用風險**：從呼叫數、近義題誤命中及實際費用開始，確認省下計算是否犧牲答案正確性。
3. **完成 recut 選段與人工審閱實驗**：將合法 plan、連貫答案與教師修改負擔分開量，避免只用渲染成功判定教學品質。

需請教授決定：比較研究要回答哪一個問題、誰提供獨立人工標註、如何保留未見測試集，以及是否另做模型微調。若要微調，訓練資料與評測資料必須隔離；沒有訓練、對照與驗證紀錄前，不稱有自有模型成果。

本文件整理可追溯的方法與實驗缺口，不替代原始證據、功能狀態或人工驗收；後續新增數字時，應同時附上日期、樣本、環境、比較條件與限制。
