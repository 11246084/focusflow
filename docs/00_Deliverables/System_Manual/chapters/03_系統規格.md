## 3-1 系統架構

FocusFlow 採前後端分離，並將耗時的影片知識化流程置於獨立 Python Pipeline。整體可分為使用者介面、後端應用服務、AI Pipeline、資料層及外部服務五個部分。

### 使用者介面

- **一般網頁入口：** React 單頁應用程式提供學生與教師登入、註冊及角色頁面。
- **管理員入口：** `/admin` 使用獨立的管理員登入元件；管理員不開放自助註冊。
- **角色式操作頁面：** 學生可查看已指派課程、觀看影片、進行多輪問答、查看短影音、LINE 綁定、通知與個人資料；教師可管理自己的課程、修課名單、影片、批次處理、短影音腳本／成品及個人資料；管理員可管理使用者、課程、影片、事件、統計、通知與個人資料。
- **LINE Bot：** 作為學生的外部問答入口，處理一次性帳號綁定、課程選擇及提問。LINE 不取代網頁的影片管理與完整播放介面。

### 後端應用服務

後端以 Express 提供 REST API，內部遵循 `routes → controllers → services → models` 的分層方向：路由組合驗證與角色中介層，控制器轉換 HTTP 輸入輸出，服務層負責權限與業務規則，Mongoose 模型負責資料結構。

主要模組包括：

表3-1-1　後端主要模組與用途

| 模組 | 在本系統中的用途 |
| --- | --- |
| Auth | 登入、學生／教師註冊、目前使用者、個人資料、密碼重設／修改及私有頭像 |
| Course／Enrollment | 課程 CRUD、課程狀態、教師所有權、修課指派／匯入／撤銷、觀看進度與 FAQ 管理 |
| Video／VideoBatch | 本機影片與 YouTube 來源、單支／多檔上傳、狀態機、重試、課程間 attach／detach 及 YouTube 上傳紀錄 |
| QA／Conversation | 課程範圍檢索、FAQ 快取、答案生成、引用、對話與訊息重試 |
| LINE | Webhook 簽章驗證、一次性綁定、有效課程切換及共用問答服務 |
| Notification／Stats／Admin | 個人通知、已讀狀態、角色統計、系統公告、使用者／影片／事件管理 |
| Shorts／Short Script | 修課限定短影音 feed、YouTube 可用性同步，以及功能開關控制的證據腳本與人工成品審核流程 |

課程、影片 metadata、問答、FAQ、短影音、課程通知與 LINE 課程範圍等應用 API 採伺服器端預設拒絕：學生必須同時符合「Enrollment 有效」與「Course 已發布」。教師只能管理自己的課程，管理員具有跨課程管理權限，前端隱藏功能不是授權依據。惟 `backend/src/app.js` 目前將 `/uploads` 直接掛為匿名靜態目錄；知道本機媒體 URL 者可繞過 JWT／Enrollment 取得檔案。這是已確認但本次不修改程式的安全缺口，因此本手冊不得宣稱所有影片內容已受修課權限保護。

### AI Pipeline

本機影片或可處理的來源進入 Pipeline 後，主要流程為：

1. 使用 FFmpeg 擷取音訊。
2. 使用 Faster-Whisper 產生帶時間資訊的逐字稿。
3. 執行逐字稿正規化、術語處理及 Leaf Chunk 切分。
4. 以 Gemini embedding 建立文字向量產物。
5. 由 uploader 將符合契約的資料銜接至 MongoDB。
6. 透過內部 processing webhook 回報開始、完成或失敗狀態。

單支入口為 `STT_Whisper/src/main.py`；批次入口為 `batch_main.py`。批次流程使用 manifest、execution lease、checkpoint 與 resume，隔離個別影片失敗並支援續跑。後端與前端已有 VideoBatch 契約，但真正使用 Pipeline batch 的功能開關預設關閉；正式環境的長時間處理與外部模型呼叫仍須另外驗收。

選用的 Parent／Child 階層式檢索已有程式與資料契約，但 `HIERARCHICAL_RETRIEVAL_ENABLED` 預設關閉。沒有有效 generation、索引、資料與唯讀端到端證據時，不可視為正式服務路徑。`video_segments_video` 僅支援初步視覺引用，不代表具備畫面字幕理解或自動短影音製作。

### 資料層與外部服務

MongoDB 保存 User、Course、Enrollment、Video、VideoBatch、Question、FAQ、Conversation、Message、Notification、UsageLog、ShortScript、ShortAsset 及影片分段等資料。應用資料、Pipeline metadata 與歷史欄位仍有過渡邊界，因此實際 collection 與索引狀態須由當次環境查證。`database/` 目錄提供初始化、索引及匯入工具，不是獨立的線上服務。

外部服務包含 Gemini、LINE Messaging API、YouTube、SMTP 及 MongoDB Atlas。任何一項的程式碼或設定範本存在，都不等於部署環境已具備有效憑證、配額、資料或可用性。

## 3-2 系統軟、硬體需求與技術平台

### 技術平台

下表的版本以目前套件清單可確認的主要版本為準；`^` 或 `>=` 代表相依套件允許的範圍，不代表正式主機已固定於表中某一修補版。

表3-2-1　系統技術平台

| 層級 | 技術 | 在本系統中的用途 |
| --- | --- | --- |
| 前端 | React 19、React DOM 19、Vite 8 | 建構單頁應用程式、開發伺服器與正式前端產物 |
| 前端互動 | GSAP、Three.js、qrcode.react | 首頁視覺效果與 LINE 綁定 QR Code |
| 後端 | Node.js、Express 4 | REST API、檔案上傳、外部 Webhook 與業務流程 |
| 資料存取 | Mongoose 8、MongoDB Driver 7 | Schema、驗證、索引及 MongoDB 操作 |
| 身分與安全 | JWT、bcryptjs、CORS、Multer | 驗證 token、密碼雜湊、來源控制及檔案接收 |
| AI Pipeline | Python、Faster-Whisper、FFmpeg、yt-dlp、NumPy、rapidfuzz | 來源取得、音訊處理、STT、正規化與資料前處理 |
| AI 服務 | Google Gen AI／Gemini；後端可設定 OpenAI 或 mock 回答供應者 | 文字向量與依檢索內容生成回答；mock 僅供隔離測試 |
| 向量檢索 | Memory mode、MongoDB Atlas Vector Search | 本機／隔離測試與部署環境向量搜尋；Atlas 模式須先確認索引及資料契約 |
| 外部整合 | LINE Messaging API、YouTube Data API、SMTP | LINE 綁定／問答、影音上傳／狀態、密碼重設郵件 |
| API 文件 | OpenAPI 3、Swagger UI | 提供主要對外 API 規格；少數內部或較新端點仍須以 route files 交叉確認 |

### 使用者端需求

表3-2-2　使用者端軟硬體需求

| 項目 | 需求與限制 |
| --- | --- |
| 裝置 | 可執行現代瀏覽器的桌上型電腦、筆記型電腦、平板或智慧型手機 |

| 顯示與輸入 | 介面可因螢幕寬度調整，但尚未完成全裝置、全瀏覽器與無障礙正式驗收 |
| 本機儲存 | 只需瀏覽器正常運作所需空間；登入資訊會使用瀏覽器儲存，私有頭像與應用資料由後端管理 |

初評原稿列出的 Android、iOS、Windows、macOS、LINE App 與解析度最低版本尚未找到完整實測矩陣，因此本次不把特定版本寫成已保證相容。

### 伺服器與處理端需求

表3-2-3　服務端需求

| 項目 | 需求與限制 |
| --- | --- |
| Backend runtime | 可執行目前 Node.js 相依套件的環境；本機預設 API port 為 4000，正式環境可由反向代理對外服務 |
| Frontend build／serve | 可執行 Vite build 的 Node.js 環境；本機開發預設 port 為 5173 |
| AI Pipeline | Python 環境、FFmpeg、足夠的 CPU／GPU、記憶體與暫存空間；影片長度、模型與併發會影響需求 |
| 資料庫 | MongoDB 或 Atlas；向量檢索需相符的 collection、向量維度、generation metadata 及索引 |
| 外部憑證 | Gemini、LINE、YouTube、SMTP 等功能各需對應設定；缺少時只能停用、降級或回報未設定 |
| 檔案空間 | 本機影片、音訊、checkpoint 與 Pipeline 產物會占用空間；清理、保留與備份政策須由部署端訂定 |
| 安全與網路 | HTTPS、正確的 CORS allowlist、Webhook 驗簽、防火牆／反向代理及 secret 管理；目前公開站點可存取不等於已完成全部上線驗收 |

由於 repository 未提供以特定課程量、影片時數、同時使用人數測得的正式容量報告，本手冊不設定未驗證的 CPU、GPU、記憶體或回應時間保證。正式規格應由負載測試與成本試算補足。

## 3-3 使用標準與工具

FocusFlow 使用的標準與工具不是名詞清單，而是各自支援特定工程目的。

表3-3-1　標準與實作方式

| 類別 | 採用方式 | 在本系統中的用途 |
| --- | --- | --- |
| HTTP API | REST 風格、JSON、統一成功／錯誤回應 | 讓前端、LINE controller 與管理功能以一致方式呼叫後端 |
| API 規格 | OpenAPI 3、Swagger UI | 說明主要外部端點；變更時仍須同步核對 routes 與消費端 |
| 身分驗證 | JWT Bearer Token、bcrypt 密碼雜湊 | 驗證已登入使用者；角色及資源關係由伺服器重新判斷 |
| Webhook 安全 | LINE `X-Line-Signature` HMAC-SHA256 驗證、內部 processing webhook 驗證 | 拒絕未通過來源驗證的外部或 Pipeline 回報 |
| 檔案驗證 | Multer、類型／大小檢查、內容 hash | 控制影片與頭像輸入、偵測課程內重複影片 |
| 版本控制 | Git、GitHub | 保存程式與文件歷史；commit 數不能單獨代表個人貢獻 |
| 前端品質 | ESLint、Node test、Vite build | 檢查程式規則、輔助函式與可建置性；不取代瀏覽器端到端測試 |
| 後端品質 | Node test、分層服務測試、隔離資料庫測試 | 驗證路由契約、權限與狀態轉換；本機結果不代表共享 Atlas 或正式環境 |
| Pipeline 品質 | Python unittest、checkpoint／manifest 驗證 | 驗證處理階段、產物契約、續跑與批次狀態；外部模型 smoke 另計 |
| 架構與文件 | Markdown、PlantUML、Mermaid、Diagrams.net | 撰寫手冊及繪製 UML／架構圖；圖面需與現況程式共同維護 |

開發期間使用 Visual Studio Code、MongoDB Compass、Microsoft Word／PowerPoint、Notion、Canva、Google Drive 及 AI 程式輔助工具等，屬團隊工作工具；它們並非 FocusFlow 執行時的必要服務。工具使用、授權版本與團隊實際分工仍須由全體成員於定稿前確認。
