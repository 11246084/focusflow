# 工作說明：recut RC11a（單題試產指令與本機資料庫）

分支 `wip/recut-rc11a-run`，從 `feat/recut` 切出（RC1～RC5 已合併）。先讀 `AGENTS.md` 與 [HANDOFF.md](../HANDOFF.md) 的「必守規則」。

這張工單讓團隊在 11/5 用一行指令從一個主題做出一支真的短片，並在本機網頁上審閱。工具本身用假資料測試；**實際從 Atlas 複製資料與呼叫 Gemini 時，由使用者當次授權並確認目標**，不在開發過程中自行執行。

## 先讀

1. [recut 設計決策](../recut-design-decisions.md)第 40、64、92 項，「整體流程」與「階段與檢查」兩節。
2. RC1～RC5 的回報（背景工作、視窗與辨識、選段、圖卡與施工單、渲染指令）。
3. `backend/.env.example`、`backend/src/config/env.js`（資料庫連線設定）、`backend/scripts/` 的既有腳本寫法。

## 要做

1. **本機資料庫**（第 92 項）：用 Docker 中已有的 `mongo:7` 映像檔，提供啟動與停止本機 MongoDB 的指令（資料存在具名資料卷，可整個刪除）；在 `backend/README.md` 寫明怎麼把本機後端連到這個資料庫。不下載新的映像檔。
2. **從 Atlas 唯讀複製**（第 92 項）：一支腳本只讀取指定的 2 門課所需的集合與文件（課程、影片、片段、問題等 recut 用得到的），寫進本機資料庫；預設只列出會讀哪些集合、各幾筆（dry-run），加參數才真的複製。程式要擋下「寫入目標是共用 Atlas」的情況；連線字串從環境變數讀，不印出、不寫進任何檔案。
3. **單題試產指令**：指定課程與主題（或從候選題中挑），依序跑視窗與辨識（RC2）→ 第一步選段（RC3）→ 第二、三步（RC4）→ 用 short_render 在本機渲染成 mp4（RC5），不經過 worker 佇列。輸出：mp4、完整講稿文字檔、施工單、每一步的紀錄（第 64 項，含 Gemini 呼叫次數與 token 用量）。Gemini 呼叫前印出預估次數，需加明確參數才真的呼叫。
4. **網頁審閱**：產出的資料寫進本機資料庫，讓 RC8、RC9 完成後可直接在本機網頁審閱；RC8、RC9 還沒合併時，先輸出文字檔與 mp4 即可。
5. **文件**：`backend/README.md` 寫明完整操作步驟（啟動本機資料庫 → 複製資料 → 試產一題 → 在網頁審閱），以及每一步需要的授權。

## 測試

假的資料庫與 Gemini 回應。至少涵蓋：dry-run 不寫入任何資料；寫入目標是共用 Atlas 時被擋下；連線字串不出現在輸出與紀錄；沒有加呼叫參數時不呼叫 Gemini；單題流程依序串起各步驟；任一步失敗時停在該步並說明原因。

## 完成時回報

commit 清單、測試結果、和本工單不同之處、11/4 實際試產要執行的指令清單，以及需要使用者授權的項目（複製哪些集合、預估筆數、每題預估 Gemini 呼叫次數）。
