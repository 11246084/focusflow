# 教授會議（初評檢討）

- 會議日期: 2026-06-16
- 會議類型: 教授會議（成果檢視）
- 與會者: 邱偉豪、張庭語、鍾百陶、張家瑜、蒯思齊(教授)

## 討論內容

1. 初評評審提問檢討

- 背景：初評後需整理評審提問，判斷複評前哪些內容必須補強。
- 內容：
  - 評審追問影片問答範圍、合作對象、影片存放與權限、成本收益、STP 市場區隔、產品定位等議題。
  - 系統核心部分需補強特徵值與相似度演算法說明。
  - 分析類別圖與設計類別圖差異、類別圖加號意義、程序圖流程、課程選擇設計、伺服器承載與 LMS 整合等也需準備回答。
- 結論傾向：複評前需針對評審問題整理成可直接回答的版本，並挑出重點在報告中主動回應。

2. 影片上傳與處理流程調整

- 背景：評審關注影片存放、YouTube 權限與教師上傳流程。
- 內容：
  - 影片改由老師直接上傳到系統，移除原本貼 YouTube 連結的介面。
  - 上傳邏輯統一為：老師上傳影片 → 伺服器 → 系統自動轉傳到綁定的 YouTube 頻道 → 爬取切分後送入 RAG。
  - 本地上傳功能先關閉，統一走上述流程。
  - 目前手動上傳 YouTube 再爬取的流程，未來需改為自動化。
  - 大規模使用 YouTube 影片可能涉及平台限制與合作條件；若自建串流，儲存與頻寬成本會明顯提高。
- 結論傾向：影片處理流程改為老師上傳導向，並將 YouTube 轉傳與 RAG 前處理自動化列為後續重點。

3. 影片切分、Embedding 與相似度說明

- 背景：特徵值與相似度演算法是系統核心，複評時必須講清楚。
- 內容：
  - 需說明完整流程：轉錄（Whisper）→ 切段 → 特徵 / Embedding → 相似度比對 → 門檻判斷 → 回傳片段。
  - 查詢回傳相似度最高的前三個片段與時間戳。
  - 資料不足時需回覆「目前資料不足以回答」。
  - LINE 或前端回覆需讓使用者可直接跳到影片片段；目前仍需補強可直接跳轉播放的按鈕或連結。
  - 評審追問的特徵值可說明為 Gemini Embedding 2 產出的向量。
  - Gemini Embedding 2 可說明其語言與畫面對齊能力，讓文字與影像片段具備可比對性。
- 結論傾向：複評需以簡潔流程圖或口說方式清楚說明 Embedding 與相似度比對機制。

4. 架構圖、設計圖與文件修正

- 背景：評審針對系統分析與設計圖提出多項問題。
- 內容：
  - 類別圖加號代表 public，可被外部調用。
  - 分析類別圖著重概念與職責，設計類別圖應呈現類別的屬性與方法。
  - 程序圖需補上影片上傳至 YouTube / 資料庫的流程。
  - 課程選擇設計需重新檢視單門與多門課程的情境。
  - 管理員刪除教師資料需準備倫理面回應，可從平台規範、教師離職與資料下架權限等合理情境說明。
- 結論傾向：複評前需修正程序圖，並準備分析類別圖與設計類別圖差異的說明。

5. 商業模式、成本與 LMS 整合

- 背景：評審要求補充成本、收益、擴展性與 LMS 掛接可能性。
- 內容：
  - 需依使用量區間估算伺服器、儲存、API、轉錄與維護成本。
  - 系統可包裝成 API 供 LMS 調用，也可作為可掛接 LMS 的模組。
  - LMS 掛接、授權或模組化銷售可成為潛在商業模式。
  - 自架伺服器需評估存取頻率、效能、儲存與成本。
- 結論傾向：複評需至少準備成本估算方向與 LMS 整合說法，不一定展開成完整商業計畫。

6. 知識圖譜與未來發展

- 背景：評審建議可建立知識架構以降低重複處理成本。
- 內容：
  - 知識圖譜可依時間點與 keyword 建立知識節點。
  - 可應用於企業訓練，依職位與學科背景安排不同課程與知識路徑。
  - 目前超出專題範疇，暫不實作。
- 結論傾向：知識圖譜列為未來發展方向，不納入現階段實作範圍。

7. 初評現場問題與複評應對

- 背景：初評現場設備與記錄不足，影響展示與回答品質。
- 內容：
  - 使用評審電腦與轉接設備時，影片播不出來、文件開啟很卡。
  - 現場無法即時翻到評審指定頁數，也沒有專人記錄評審問題。
  - 評審可能一次問多題，需安排專人即時記錄。
  - 複評需自備電腦、測試設備、確保影片可播放，並準備可快速翻頁的文件。
  - 合理問題盡量修改或回應；若問題超出題目範疇，可在複評時選擇不列入主要回應。
  - 報告開頭或結尾可整理初評約 20 題提問，挑出約 15 題主動回應，展現團隊有重視評審意見。
  - 教授認為市場區隔與成本費用問題偏細，可待系統完成後再細算，複評先準備方向即可。
  - 評審對本組 idea 給予正面評價，可視為題目具有創意與實用性的佐證。
- 結論傾向：複評需強化現場設備準備、問題記錄與文件查找速度。

## 決議事項

1. 影片改由老師直接上傳，移除貼 YouTube 連結介面。
2. 上傳流程統一為老師上傳 → 伺服器 → 自動轉傳綁定 YouTube → 爬取切分 → RAG。
3. 影片採整部丟入處理，知識圖譜列為未來方向，暫不實作。
4. 暑假先專心期末考，系統暫不大改。
5. 後續會議改為週二上午 10 點，以 Google Meet 遠端進行，報告時間約 1 小時。
6. 複評需補強特徵值與相似度演算法、分析 / 設計類別圖差異、成本收益估算、LMS 整合與伺服器承載說明。
