## 三、證據缺口（依嚴重度）

| 缺口 | 影響評分 | 現況 | 能否在 11/7 前補 |
|---|---|---|---|
| 沒有 GitHub Issue，鏈中斷 | T | 0 個 Issue | 不建議補建（會被看出是事後建立）；改說「Notion 任務卡即需求單，PR／commit 回連任務」 |
| 沒有 CI Gate、自動回滾 | P | workflow 不跑測試 | 可補一個 PR／push 觸發的測試 workflow，但需授權且要在凍結前驗證；否則列為下一步 |
| 學生試用回饋無數字 | A | 試用對象未記錄 | 可用唯讀報表補人數與提問數（需授權）；拿不到就不提數字 |
| 沒有回顧會議（Retrospective） | A | 無獨立紀錄 | 不要宣稱有；用「每週教授會議兼回顧」＋ 08-17 自我審查頁、10-25 總表當回顧證據 |
| 任務無負責人 43% | T | 多為 3～4 月與 7～9 月早期卡 | 不要回填歷史資料；簡報挑有負責人的卡展示 |
