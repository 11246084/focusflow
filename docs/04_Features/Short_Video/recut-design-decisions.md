# recut 短影片設計決策

recut 是把老師上課錄影的**原音**剪成 30～65 秒短片、配上程式產生的動畫圖卡的產片方式，和現有「AI 數位分身」並存。這份文件記錄 2026-10-14～17 與使用者逐題討論後**已定案的設計**與**還沒討論完的問題**，讓接手的人或 AI（Claude、ChatGPT、Codex）不用重讀對話。實作前先讀完「已定案」與「待討論」兩節；功能是否已完成只看[目前狀態](../../current-status.md)。

## 名詞

- **施工單（plan）**：描述一支短片的 JSON：選哪幾段老師的話、字幕、每段配什麼圖卡、圖卡何時出現。格式 `recut-v1`，定義見 [short_render](../../../short_render/README.md)。
- **錨點**：施工單不寫秒數，而是寫「老師講到某個詞」；程式依語音辨識的逐字時間換算成秒數。
- **連續視窗**：同一支影片中，學生問題的命中片段所在的一段連續 2～3 分鐘逐字稿。
- **worker**：在組員電腦（之後是 VM）上常駐的渲染程式，向後端領取工作。

## 整體流程（例）

學生常問「OpenCV 跟 YOLO 差在哪」→ 教師在選題後選「recut」→ 系統凍結連續視窗 → 對視窗做逐字辨識 → AI 第一步選段、第二步配圖卡 → 程式驗證 → 教師在瀏覽器預覽並核准 → worker 渲染 → 教師審成品 → 上架。

```
選題（共用）→ 教師選產片方式
  ├─ 生成模式（avatar，現有）：分散證據 → 8 拍口白＋隱喻 → ComfyUI（系統外）
  └─ recut：連續視窗 → 視窗辨識 → AI 選段 → AI 配圖卡 → 驗證 → 瀏覽器預覽 → worker 渲染
教師審核、成品上傳、成品審核、上架（共用）
```

| 1 | 素材取自命中處擴出的**連續視窗**；找不到就放棄，之後再優化成擴大檢索 | 跨時間拼接會明顯跳接（第 1 支原型）。2026-10-16 唯讀實測 6 門課前 10 題，共 60 題，57 題找得到視窗。2026-10-17 唯讀複查：這 6 門課中有 4 門已不在 `courses`（問題紀錄仍在），現存 2 門屬同一位教師 |

| 10 | 第二階段預設版面：**全版動畫＋老師原音**；「上動畫下老師」與 Gemini 找老師畫面位置延後 | 一次避開裁切位置、人臉隱私、Zoom 小視窗畫質三個問題 |

| 14 | **先對視窗做高品質語音辨識，再讓 AI 依辨識結果寫施工單**；兩關驗證（結構、引用、數字；錨點、總長）都在生成當下完成 | 原型實跑時錨點常因兩次辨識用字不同而對不上（200 張／兩百張、個／各） |
| 15 | 視窗辨識的目標位置是 **VM**（沿用 `STT_Whisper` 的 faster-whisper，用 small 模型），一次只跑一個；開發與試跑階段先在使用者本機 | 只辨識 2～3 分鐘；不必等組員電腦開機 |
| 16 | recut 生成改成**背景工作**（教師按下後顯示「處理中」，完成後通知）；8 拍生成維持同步；前端「處理中」畫面一併實作 | 辨識＋生成＋重試可能超過 nginx 預設 60 秒；部署重啟會中斷同步請求。沿用影片處理與 YouTube 上傳的啟動恢復模式 |
| 17 | AI 寫施工單**分兩步**：①選段（程式立刻用逐字時間算總長）②配圖卡與字幕；各自驗證、各自重試 | 任務單純較易寫對；錯哪步重試哪步 |
| 18 | 加**第三步整段檢查**：Gemini 只列出問題與類型、不直接改施工單，程式依類型退回第一或第二步修正；每次生成最多 5 次 Gemini 呼叫。問題分兩類：**可信度錯誤**（引用不存在、數字無出處、錨點對不上語音、總長超出、格式錯）必須修好否則生成失敗；**品質問題**（指涉畫面句、段落接不起來、圖卡與話不符、字幕走樣）盡量修，修不完照樣產出交教師判斷。片段頭尾的指涉畫面句由程式自動剪掉，中間的不自動剪 | 一處不完美就整支做不出來太嚴；直接讓 AI 改會繞過驗證 |
| 19 | 品質問題**不在預覽畫面上標記**；預覽旁放預設收起的「AI 檢查建議（N 項）」，**核准按鈕永遠可按**；建議一律存進資料庫，供試跑統計「AI 指出的問題教師是否認同」 | 教師認為不影響理解就可直接發布；但有些問題（如指涉畫面句）教師在動畫預覽中不易察覺，系統仍應提示 |
| 20 | 全版動畫預設色系 **N2 藍紫夜**（深藍到梅紫的漸層底 `#151C3F → #1C1A40 → #28173A`、白字、黃色 `#FFC93C` 當重點）。教師不滿意時可在預覽改選備選主題：**N1 深海軍藍、C 深梅紫、B 淺紫、G 中性淺灰**；換主題只改畫面顏色，主題選擇和施工單內容分開存，不必重新生成施工單。D 品牌漸層只用在片頭、片尾卡。左上角標籤底色加深為 `#C2410C`。深色主題的字幕用白字黑邊，淺色主題（B、G）用白色半透明卡片＋深色字 | 2026-10-17 改用 Fluent 原色物件（第 22 項）後比較四種底色：淺紫底和彩色物件搶顏色；N2 主文字對比 16.6:1、重點色 10.8:1，帶一點梅紫保留和品牌色的關聯。原本標籤底色 `#F14F21` 上的白字只有 3.6:1，改成 `#C2410C` 後是 5.2:1（[色系比較](evidence/2026-10-17_theme-palette-comparison.png)、[底色比較](evidence/2026-10-17_background-color-comparison.png)、[單一畫面示意](evidence/2026-10-17_frame-mockup-n2.png)）。實作注意：`short_render` 目前把 C 深梅紫的色碼寫死在 `src/render/style.css` 和 `src/render/html.js` 的動畫裡，要改成主題變數 |

| 25 | 第一步選段用**句子編號＋句內微調**指出剪接點：程式先把視窗辨識結果切成短句並編號（例 `s12 [41.2–44.8] 你想要做一個大語言模型的話`；暫定在停頓 0.3 秒以上或標點處切開、每句最長約 8 秒），AI 輸出 `"from": "s12", "to": "s15"`，需要從句中開始或結束時加 `startAt`／`endAt`（原話片語），程式只在那一句裡比對；找不到算可信度錯誤，退回第一步。`recut-v1` 的文字錨點保留，由程式依編號填回 | 原型最常見的錯誤是 AI 抄的原話和辨識結果差一點就對不上；改成編號後時間由程式直接查，句內微調的比對範圍只有一句，幾乎不會錯，又保留從句中下刀的彈性 |
| 26 | 第一步選段的目標是**回答學生的問題**：AI 看到代表題、提問次數最多的 5 個同義問法，以及編號句子（檢索命中的句子加 ★）；只挑回答問題需要的句子，優先順序為結論或定義、理由、例子，複習與離題段落跳過；冷開場用最直接回答問題的那一句。優先順序不是硬性結構，播放仍依時間順序（第 5 項） | 主題本來就是從學生常問的問題選出（選題程式的 `question` 與 `variants`）。例：學生問「OpenCV 跟 YOLO 差在哪」，留「OpenCV 是工具箱」「YOLO 是訓練好的模型」「OpenCV 是工具、YOLO 是會辨認的大腦」，跳過複習與交作業提醒 |
| 27 | 錄音沒有回答學生的問題時，AI 可回報**「無法回答」與原因**，不硬選；該次生成停止，不進入重試。教師看到原因後可改用數位分身、換主題，或**由教師自己提供解釋**（方式見第 28 項）。試跑時統計被判定無法回答的主題數，作為之後擴大檢索的依據 | 與第 1 項「找不到就放棄」同一原則；現有 8 拍生成也有 `SHORT_SCRIPT_ARC_NOT_APPLICABLE` 類似機制。使用者補充：由教師親自解釋，能確保內容是教師對這個問題的想法 |
| 28 | 教師提供解釋可選**錄音**或**打字**：錄音直接當作新的視窗走 recut 流程；打字則用**通用合成語音**（不複製老師聲音）照教師文字一字不改地唸，AI 只能建議縮短、需教師同意，片中標示「AI 合成語音」（沿用上架時的 AI 揭露勾選），教師預覽時可改字重唸以修正專有名詞或破音字。錄音與打字都**在試跑之後實作**。語音引擎採 **Azure 台灣中文神經語音**（正式 API），**Gemini TTS** 為備選（用現有金鑰；語言清單列有繁體中文文字，但口音是否為台灣腔待實測）；實作前先以同一段文字小測專有名詞（OpenCV、YOLO）與破音字（行、重），並到 Azure 官方頁面確認聲音、地區與免費額度。不採用瀏覽器內建語音（OpenWebUI 的「網頁 API」）。不自己做完整數位分身，分身影像維持教授主機 | 分身的影像與隱喻畫面需大 GPU，組員電腦跑不動；雲端影片生成要把老師照片送出且寫不準中文字與數字。語音複製涉及聲紋個資，CPU 上也很慢（CosyVoice 舊版約 38 倍實際時長）。通用合成語音不需 GPU、沒有聲紋問題，也能讓「無法回答」的主題仍有聲音。Azure 有台灣口音語音，第三方與 Microsoft 問答區資料顯示免費額度每月 50 萬字（一支短片旁白約 200 字），超過後每 100 萬字 16 美元；Gemini 3.8 Flash TTS 的語言清單由使用者 2026-10-17 查得。瀏覽器內建語音無法依網頁標準存成音檔、聲音隨觀看者的作業系統而變，公開發布的授權也不明 |
