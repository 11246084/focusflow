# 教授會議（簡報方向建議與商業模式強化）

- 會議日期: 2026-09-17
- 會議時間: Notion 未記載
- 會議類型: 教授會議（決策會議）
- 與會者: 邱偉豪、張庭語、鍾百陶、張家瑜、蒯思齊（教授）

## 討論內容

1. 評審重點與個人貢獻的呈現

- 背景：教授指出隨著 AI 工具能力大幅提升，做出東西已不是評審的關鍵，評審想看的是學生學到什麼、做了什麼。
- 內容：
  - 評審預設每組都用了 AI，重點在展示你教 AI 做了什麼、你的角色是什麼。
  - 簡報要多寫開發過程與踩到的坑，例如一開始用 BERT 轉詞向量效果很差、後來改用 Gemini Embedding（多模態）才改善，以及 UI/UX 由 AI 生成的版本不符需求、需多次重新定義。
  - 可把 AI 對話紀錄交給 AI 分析，建議如何在投影片中凸顯自己的貢獻；並用 GitHub 提交紀錄與各版本差異佐證學習歷程。
- 結論傾向：簡報加入個人觀點、技術瓶頸與解法，並以 GitHub 紀錄作證。

2. 文件與簡報格式

- 背景：教授檢視簡報與計畫書的章節排版。
- 內容：
  - 每個章節開頭必須是文字說明，之後才放圖，再放表；章節一開始不可直接出現表格或圖片。
  - 系統直接當成全新系統介紹，不提 FocusFlow。
  - 架構圖不可用 AI 直接生成，建議用 PlantUML 程式碼生成：可修改、可複現，符合近期國際會議與期刊的規範。
- 結論傾向：格式改為文字、圖、表的順序；架構圖改用 PlantUML，程式碼存 GitHub。

3. 商業模式強化

- 背景：原商業模式在前次比賽被評審認為偏弱。
- 內容：
  - 金融機構合作：協助銀行做使用者風險評級（教授提到台灣銀行目前已有使用者調查 QA 機制），收取服務費，並可與銀行流程評估綁定。
  - KOL 合作：開放財經 KOL 在平台上架課程、平台抽成；對 KOL 的好處是課錄一次、不用煩惱短片更新，RAG 又能持續回答學員問題，不是一次性買賣。
  - 訂閱制：平台自有課程依訂閱金額給予不同時數。
  - 差異化：相較九妹等現有數位課程平台，本系統可用模糊問題搜尋課程片段，解決找不到特定段落的問題。
  - 韓國案例：韓國要求新散戶買槓桿 ETF 前，須先完成 5 個交易日的模擬交易與 3 小時線上課程，可作為市場需求的背景，並引出與銀行合作、要求使用者先學金融知識的場景。
- 結論傾向：商業模式需重新規劃，納入銀行風險評級、KOL 分成與訂閱制。

4. 複評簡報與影片準備

- 背景：複評前需確認開場、展示方式與影片長度。
- 內容：
  - 複評開場播放約 1 分半的情境短片（劇情演給評審看）；比賽用的三分鐘影片維持三分鐘，可微調但不加長。
  - 功能展示由一人在台上說明、另一人持平板或筆電實際操作，也可現場隨機輸入問題，讓評審看到系統真實回應。
  - 教師端以 URL 帶隱藏參數的方式與學生端區分。
- 結論傾向：複評開場放短片，展示採一人說明、一人操作。

5. 其他技術討論

- 背景：討論憑證、AI 工具費用與文件撰寫工具。
- 內容：
  - SSL 憑證：個人開發用途申請免費個人憑證即可，不需商業等級；若用 ngrok 提供服務，到一定流量也需付費。
  - GPT-6：教授表示 200 美元月費方案才確保有使用權，20 美元方案不一定有，且有 Agent 五小時流量限制。
  - 文件撰寫：Claude skill（斜線輸入 `/project document`）可引導文件撰寫，底層整合 OOAD/UML skill，適合用於副評文件與比賽計畫書；第一版已上傳 GitHub。
- 結論傾向：副評文件以此工具輔助撰寫，後續依教授回饋修改。

## 決議事項

1. 投影片與計畫書格式改為文字、圖、表的順序，章節開頭不放圖表。
2. 文件與簡報一律當全新系統介紹，不再提 FocusFlow。
3. 簡報加入個人觀點與技術瓶頸的解法，搭配 GitHub 紀錄佐證。
4. 架構圖改用 PlantUML 生成，程式碼存 GitHub。
5. 商業模式重新規劃，加入銀行風險評級、KOL 分成、訂閱制，並以韓國案例說明市場需求。
6. 複評開場放 1 分半短片，比賽三分鐘影片不加長；功能展示一人說明、一人操作。
7. 教師端用 URL 隱藏參數與學生端區分。
8. 副評文件以 Claude skill 輔助撰寫，第一版已上 GitHub，後續依教授回饋修改。
