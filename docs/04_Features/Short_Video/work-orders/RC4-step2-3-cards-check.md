# 工作說明：recut RC4（第二、三步：圖卡、字幕與整段檢查）

分支 `wip/recut-rc4-cards`，從 `feat/recut` 切出（RC3、RC5 已合併）。先讀 `AGENTS.md` 與 [HANDOFF.md](../HANDOFF.md) 的「必守規則」。

這張工單把選段變成完整的 `recut-v1` 施工單，並做整段檢查。**不呼叫真的 Gemini**。

## 先讀

1. [recut 設計決策](../recut-design-decisions.md)第 5、17～20、24、29～34、65、67、87 項，「階段與檢查」表的「②」「③」列；[素材開放與排除清單](../recut-asset-exclusions.md)。
2. [體驗設計決策](../decisions.md) UX-3、UX-7。
3. RC3 回報的選段格式、額度與紀錄函式；RC5 回報的施工單格式（句子編號錨點、`icon`、主題、增益、版本欄位）與圖卡目錄的位置。

## 要做

1. **第二步配圖卡與字幕**（第 17、29～33 項）：一個重點一張圖卡，全片約 5～10 張；每張 3～12 秒，只在句子交界換卡；卡片內元素出現時間（`cues`）用「句子編號＋片語」；圖卡從 RC5 的目錄挑選，`icon` 只能用開放清單內的物件（第 24 項）。字幕可改寫，但數字與專有名詞必須出現在對應的老師原句。
2. **圖卡目錄給 AI 的說明**（第 31 項）：用 RC5 在 `short_render/src/plan/components.js` 旁維護的目錄（用途、參數、小例子、什麼時候不要用）。「放不進去、合不起來、層層包含」三種新圖卡，依 RC5 子 agent 的檢查結果決定是否放進給 AI 的目錄（待答 R2、決策第 87 項）。
3. **第三步整段檢查**（第 18、33、34 項）：Gemini 只列出問題與類型，不直接改施工單；程式依類型退回第一或第二步。可信度錯誤（引用不存在、數字無出處、錨點對不上、總長超出、格式錯）必須修好，否則任務失敗；品質問題（指涉畫面句、段落接不起來、圖卡與話不符、字幕走樣）有額度才修，沒修完的存成 AI 檢查建議（第 19 項）。可信度錯誤優先使用額度。
4. **組成施工單**（第 5、20、65、67 項）：依 RC5 的格式輸出 `recut-v1`，填入 RC2 算出的增益、模型 ID、素材套件與 short_render 版本；主題與施工單分開存，預設 N2。用 short_render 的驗證器檢查通過才存成新版本。
5. **指示文字**（待答 R1、決策第 87 項）：第二、三步的指示與問題清單格式，和 RC3 一樣放在單一位置並附給人看的版本；完成後另開子 agent 檢查與 `responseSchema`、驗證器一致，結果附在回報。
6. 依第 70 項記錄換卡時機、字幕與數字對證的方法。

## 測試

全部用假的 Gemini 回應。至少涵蓋：圖卡太短太長、在句中換卡；`icon` 不在開放清單；字幕出現原句沒有的數字或專有名詞；第三步回報的每一類問題各退回正確的步驟；額度只剩一次時先修可信度錯誤；品質問題沒額度修時存成建議且照樣產出；施工單通過 short_render 驗證器；版本與增益欄位正確。

## 完成時回報

commit 清單、測試結果、和本工單不同之處、指示文字位置與子 agent 的檢查結果，以及給 RC8 的介面（重跑第二、三步的入口、AI 檢查建議的格式）。
