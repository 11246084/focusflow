## 2-1 可行性分析

本節將從技術可行性、教育應用可行性、經濟與營運可行性、法律與資料使用可行性、操作可行性五個面向，分析FocusFlow是否具備實際開發與應用的可能性。由於本系統並非單純概念構想，而是以第一階段MVP為基礎進行實作，因此可行性分析將同時說明系統目前已採用的開發工具、技術方法與後續擴充方向。

技術可行性

FocusFlow第一階段MVP採用前後端分離與AI Pipeline架構。前端以React與Vite建立單頁式應用程式，後端以Node.js、Express與Mongoose提供RESTAPI，資料庫使用MongoDB Atlas儲存使用者、課程、影片、segment、LINE綁定與使用紀錄等資料。AI Pipeline則以Python執行音訊抽取、語音轉文字、segment切分、embedding建立與資料匯入，形成可被檢索的教學影片資料。

表2-11 FocusFlow核心功能與技術對應表

| 核心功能 | 對應技術／工具 | 可行性說明 |
| --- | --- | --- |
| 課程影片上傳與管理 | React、Node.js、Express、MongoDB Atlas | 教師可建立課程並上傳影片或管理影片資料，系統可記錄影片處理狀態。 |
| 影片音訊抽取 | FFmpeg | 將課程影片中的音訊抽出，作為後續STT語音轉文字輸入 |
| 語音轉文字 | STT/Whisper/faster-whisper | 將教學影片轉換為逐字稿，使影片內容可被後續切分與檢索 |
| 影片段落切分 | Segment切分邏輯 | 依時間、語意或逐字稿內容將影片切成可搜尋片段 |
| 影片內容向量化 | Gemini Embedding | 將影片段落與文字內容轉換為向量資料，建立語意檢索基礎 |
| 問題與片段比對 | Cosine Similarity | 比對學生問題與影片segment的向量相似度，找出最相關內容 |
| 回傳影片時間點 | Timestamp設計 | AI回答可對應原始影片時間碼，讓學生回到影片確認教師講解 |
| 使用者發問管道 | LINE Messaging API、Web介面 | 學生可透過LINE Bot或網頁介面進行課程問答 |
| 影片播放與頻寬控制 | YouTube iframe | 課程影片可嵌入前端播放，降低系統直接負擔大量影音串流成本 |

從表2-11可看出，FocusFlow的核心功能皆有對應的實作技術與工具。系統並非僅提出「AI能理解影片」的概念，而是透過STT將影片轉為文字資料，透過Gemini Embedding建立影片內容向量，並使用Cosine Similarity進行語意比對，使學生問題能對應到最相關的影片片段。此流程可具體支撐「影片可搜尋、可提問、可回溯」的系統目標。

目前FocusFlow已完成基礎端到端流程規劃，可展示登入與課程列表、教師上傳影片與處理、QR Code綁定LINE、LINE Bot提問與timestamp跳轉等主要功能。後續技術挑戰主要包含AI回答品質穩定性、embedding檢索準確度、影片處理狀態管理、錯誤處理、資料安全與正式部署效能等。整體而言，本系統已具備原型驗證可行性，後續可在MVP基礎上逐步優化與擴充。

教育應用可行性

FocusFlow的應用場景主要聚焦於長篇教學影片的課後複習、翻轉教學與線上課程自學。現行教學環境中，教師錄製課程影片、學生課後觀看影片已相當常見，但長影片不易搜尋、重點片段難以定位、學生無法即時提問等問題仍未被完全解決。

本系統以「問題導向查找」取代單純拖曳時間軸。學生可直接針對想複習的概念提問，系統再協助找出相關segment與影片時間位置，使學生能快速回到原始影片確認教師講解。此設計能降低學生尋找重點的時間成本，提升課後複習與考前整理效率，因此具備實際教育應用價值。

對教師與助教而言，FocusFlow也能協助減少重複性問題回覆。例如學生常詢問「這個概念在哪一段影片有講」、「某個操作步驟如何完成」、「考前應優先複習哪一段」等問題，若能由系統先協助完成基礎查找，教師與助教便可將更多時間投入進階說明、課程設計與個別輔導。本系統不主張以AI取代教師，而是將AI定位為影片教材的輔助索引與初步問答工具，並透過timestamp保留原始課程脈絡。

經濟與營運可行性

FocusFlow第一階段不以快速營利為主要目標，而是以教育展示、校內試用與需求驗證為主。系統採用既有開發框架、雲端資料庫、LINEAPI與AI模型服務，可降低自行開發大型影音平台或訓練模型的成本。在影片儲存與播放方面，本系統可支援將課程影片上傳至YouTube，並透過iframe方式嵌入前端播放。系統本身主要儲存課程資料、影片metadata、逐字稿、segment、embedding與timestamp，不直接承擔大量影音串流成本，因此能降低伺服器頻寬與儲存負擔。

未來若系統穩定度與使用成效逐步提升，可進一步評估校園授權、課程平台模組、教師進階功能或教育機構方案。此模式不一定以一般商業營利為唯一方向，也可定位為教育科技服務、校內教學輔助工具或MOOCs平台外掛，具備與現有教育平台整合的潛力。

法律與資料使用可行性

FocusFlow涉及課程影片、逐字稿、學生提問紀錄與AI回答內容，因此在資料使用上需注意教材授權、個人資料保護與AI回答揭露。

在課程影片方面，系統應以教師授權影片、公開可使用影片或校內課程教材為主要來源，避免未經授權處理他人教材。若使用YouTube影片，應遵循其嵌入播放與使用規範，並避免將影片另行下載或作為未授權用途。

在學生資料方面，系統僅保存必要的使用紀錄與提問資料，並應避免公開個別學生問題內容。若未來導入學習歷程分析，應進一步明確告知資料使用目的與保存方式。在AI回答方面，系統應標示回答為學習輔助內容，並透過timestamp讓學生回到原始影片確認教師講解，降低AI回答與課程內容脫節的風險。此設計可提升系統可信度，也符合教育場域中對教材來源與學習脈絡的要求。

操作可行性

FocusFlow的操作設計以降低學生與教師使用門檻為原則。學生端可透過Web介面或LINE Bot以自然語言提問，不需學習複雜操作流程；教師端則可透過課程管理介面建立course並上傳影片，系統會顯示影片處理狀態，讓使用者了解影片是否已完成AI Pipeline處理。此設計讓不同角色能以熟悉的方式使用系統。

學生可透過LINE快速提問，教師可透過網頁管理課程影片，Admin則可透過後台查看使用者、影片與系統資料概況。整體流程符合教學影片複習與課後問答情境，具備實際操作可行性。

## 2-3 市場分析－STP

本節以STP架構分析FocusFlow的市場定位。由於本系統主要解決長篇教學影片不易搜尋、學生無法即時提問，以及教師與助教重複答疑等問題，因此將依市場區隔、目標市場與產品定位三個面向進行說明。

市場區隔（Segmentation）

學生與線上學習者：學生是長篇教學影片最直接的使用者，特別是在課後複習、考前準備、缺課補學或線上課程自學時，經常需要回到影片中尋找特定觀念或操作步驟。當影片時間較長或內容密度較高時，若只能依靠章節標題或手動拖曳時間軸查找內容，容易造成時間浪費，進而降低複習效率與學習意願。

課程教師與課程助教：教師與助教經常需要回覆學生相似的基礎問題，例如某個觀念位於影片哪一段、操作步驟如何完成，或考前應優先複習哪些片段。這類問題雖然屬於正常學習需求，但重複性高，容易增加教學支援負擔。因此，若能透過系統協助學生先完成基礎查找，教師與助教便可將更多時間投入進階教學、課程設計與個別化輔導。

教學單位與線上課程平台：學校教學單位、MOOCs平台、LMS平台、補習教育單位與企業內訓單位，通常擁有大量課程錄影、線上講座、研討會錄影或訓練影片。這些教材內容完整但時間較長，若缺乏語意搜尋與片段定位功能，教材再利用價值會受到限制。因此，此類平台需要能提升影片可搜尋性、互動性與學習支援效率的輔助工具。

目標市場（Targeting）

大專院校學生與線上課程學習者：FocusFlow初期主要鎖定大專院校學生，以及需要觀看長篇教學影片進行複習的線上學習者。這類使用者最常面臨影片重點難找、課後無法即時提問、考前整理效率低等問題，因此對AI問答找片段與timestamp回溯功能的需求較明確。

課程教師與課程助教：教師與助教是系統導入課程場域的重要關係人。透過FocusFlow，教師可將既有課程影片轉換為可搜尋、可提問的學習資源；助教則可減少重複回答基礎問題的負擔。雖然教師與助教不一定是最頻繁的直接使用者，但他們對系統是否能導入教學情境具有重要影響。

LMS、MOOCs、補習教育與企業內訓平台：當系統功能與問答品質逐漸穩定後，本系統可進一步作為現有LMS、MOOCs、教育或訓練平台的輔助外掛。這些平台通常已具備影片播放與課程管理功能，但較缺乏針對影片內容的AI問答、語意檢索與原始片段回溯功能，因此具備後續合作與擴充潛力。

產品定位（Positioning）

AI問答與重點查找工具：FocusFlow定位為長篇教學影片的AI學習輔助系統，協助學生以自然語言提問，快速找到課程影片中的相關片段與重點內容。相較於一般影音平台只能提供播放、章節或標題瀏覽，本系統更強調影片內容本身的可搜尋性與互動性。

可回到原始課程脈絡的學習工具：FocusFlow並非單純提供AI文字回答，而是透過segment與timestamp設計，使學生能回到原始影片片段確認教師講解內容。此定位能降低AI回答與教材內容脫節的風險，並維持課程學習的完整脈絡。

現有教育平台的輔助外掛：FocusFlow不以取代現有LMS、MOOCs或線上課程平台為目標，而是作為輔助外掛，補足現有平台在影片內容檢索、自然語言問答與片段回溯上的不足。透過此定位，本系統能與既有教育平台整合，提升影片教材的再利用價值，並強化學生在翻轉教學、線上課程與自主學習情境中的學習效率
