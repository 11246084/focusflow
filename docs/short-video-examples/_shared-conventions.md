# 課程觀念解說・共用規範

本目錄的十支範例**全部是同一種內容類型：課程觀念解說**，而且用的是**同一個觀念、同一組資料庫來源**。差別只在呈現手法。

這樣設計是為了可比較：同一份知識用十種方式講，可以直接 A/B 哪一種對學生有效，而不是在比題目好不好。

- 版本：**v7（2026-08-14）**
- 上位文件：[Phase2_Short_Video_Production_Spec_v1.md](Phase2_Short_Video_Production_Spec_v1.md)（已升到 v2）

> **v6 變更：跟上 Phase2 v2 的架構轉向——從「禁止生成」改為「生成 + 驗證」。**
>
> | | 舊 | 新 |
> |---|---|---|
> | 畫面帶文字 | 禁止 | 可以，須通過 **G2 字面驗證** |
> | 字卡 | 一律程式化渲染 | 可生成，程式化渲染降為 fallback |
> | 人物出鏡 | 只能實拍教師 | 可用**虛擬講解員**（標示 + 不得冒充） |
> | 語音 | 原生音軌一律剝除 | 可用生成語音，須通過 **G3 語音驗證** |
> | 工具 | 綁 Veo + Nano Banana | 寫能力需求，不綁模型 |
>
> **「知識點必須來自資料庫」沒有放寬**，改由 G1 溯源保證。
>
> **v7 追加**：拿掉導流（Shorts 定位為獨立學習單元）、成功指標改完播率+重播率、音效與配樂一律自製、字型與調色統一、新增發布規範。十支已同步。

## 1. 共用素材（十支都用這一份）

**以下全部是 2026-08-14 從共用 Atlas `focusflow` database 實查出來的真實資料**，不是示意值。

```yaml
courseId: 69f82564736febac6db8e97b          # 影像處理導論
sourceVideoId: 6a67ffd295668cc2b904f3c4     # aiA10_1140123_2，全長 1800.1s
question: "說明token是什麼?"                  # questions.question 原句，2026-07-28 由學生透過 api 提出
primaryStartSec: 56                          # 原片 00:56，僅供溯源記錄，不做成導流
```

> **v7 起不做導流。** Shorts 定位為**獨立的 30 秒學習單元**，學生在這裡看完就學到了，不需要被帶回原片。
>
> `primaryStartSec` 仍然保留，但用途只剩**溯源記錄**（這段內容出自原片哪裡），不會出現在畫面上。
>
> **成功指標因此改成：完播率 + 重播率。** 原本的回流率沒有導流就量不到，而且與新定位不符。這個改動讓 03（無縫循環）從「有趣的變體」變成真正有價值的一支。

### 學生原問句（`questions` collection 實錄）

> 說明token是什麼?

同一課程另有一題 `說明文本、斷詞以及Token分別是什麼?`，系統回答「目前資料庫片段不足以回答這個問題。」——**這種題目不能拿來做短影音**，沒有可溯源的內容。

### QA 答案（`faqs` / `questions` 實錄）

> Token 通常是指將原本的句子拆成碎片化之後的東西，包含句子中的各個部分以及最後的句點都是 token。它是自然語言處理中的一個詞彙，且 ChatGPT 等語言模型的計費方式基本上都與 token 有關。

### 可用要點與對應片段

| 代號 | chunkId | 時間 | 要點 |
|------|---------|------|------|
| **A** | `6a67ffd295668cc2b904f3c4_chunk_0004` | 37.34–54.68s | token 是自然語言處理裡一個特別的詞，介紹 ChatGPT 時會一再看到 |
| **B** | `6a67ffd295668cc2b904f3c4_chunk_0005` | 56.18–68.04s | token 通常是指把原本的句子拆成碎片化之後的東西 |
| **C** | `6a67ffd295668cc2b904f3c4_chunk_0006` | 68.14–90.8s | 拆開後的每一個碎片都是 token，**包含最後的句點也是** |
| **D** | `6a67ffd295668cc2b904f3c4_chunk_0007` | 90.9–110.17s | 不只 ChatGPT，其他語言模型的計費方式基本上也都跟 token 有關 |

**十支範例只能從這四點裡挑、刪、重排，不可新增。** 任何一句指不回 chunkId，就是 `ai_added`，發布前必須教師逐句勾選（Phase2 規格 §3.5）。

### 實查時發現的三個限制（會影響製作）

**① 逐字稿是簡體字，而且有 STT 錯誤。** 實際存進 `video_segments_text.text` 的內容長這樣：

> 这一个一个东西这个就叫token 啊这个也是token 啊包含最后的这个句点他也是token

其中「济费方式」應為「計費方式」、「自然与人处理」應為「自然語言處理」、「chat gbd」應為 ChatGPT。

**這直接打到第 06 支（原片剪輯 + 字幕強化）**：它的賣點是字幕 100% 用老師原話，但原話的逐字稿是簡體且有錯字。要嘛字幕改成手動校正（就不再是純 `verbatim`，需標註為 `corrected`），要嘛這一支不適用於這批影片。**06 的規格需要據此修訂。**

其餘九支不受影響——它們的旁白本來就是 `rewritten`，AI 從逐字稿重寫時會自然修正。

**② 片段沒有 `courseId` 欄位、`segmentId` 是 `null`。** 實查這批 Leaf 只有 `videoId` 與 `chunkId`。溯源驗證要用 `chunkId`，不要用 `segmentId`。

**③ 同一支影片在兩個課程各上傳了一份**，`videos._id` 不同（`6a67ffd2…` 在影像處理導論、`6a682a7b…` 在 Pipeline Bridge Course），片段也各存一份。做範例時**要指定是哪一份**，否則溯源會記到另一個課程的影片。

> 另外，課程名稱是「影像處理導論」，但影片內容是 NLP／ChatGPT。這是資料本身的狀況，不是筆誤——做對外影片前要先跟老師確認課程歸屬。

## 2. 分鏡腳本表（十支共用的格式）

腳本與分鏡**寫在同一張表**，拍攝時不用左右對照兩份文件找對應。

格式是業界 **two-column A/V** 的變形：外層維持「畫面／聲音」兩大欄，shot-list 的細項（景別、焦段、運鏡、構圖、光影、字卡）收進畫面欄當標籤行；鏡號、秒數、Beat 拉出來當索引欄。

| 欄位 | 內容 | 備註 |
|------|------|------|
| 鏡號 | `S1`、`S2`… | 生成鏡的 prompt 用這個編號索引 |
| 秒數 | `0–4s` | 累計時間，不是單鏡長度 |
| Beat | 這一鏡的目的或情緒 | 例：`拋出困惑`、`給結論`、`收束重述` |
| **畫面** | 景別／焦段、運鏡、構圖、光影、字卡 | 五個標籤行，缺項寫 `—` |
| **聲音** | 旁白、**語氣**、字幕、**配樂**、音效、收音、來源 | 旁白帶唸法標記（§4.1）；`來源` 是 chunkId + level，溯源就靠這一格 |

### 標準寫法

```markdown
| 鏡號 | 秒數 | Beat | 畫面 | 聲音 |
|------|------|------|------|------|
| S1 | 0–3s | 鉤子・反常識 | 景別：中近景・35mm<br>運鏡：固定<br>構圖：置中偏右，眼睛在上 1/3 線<br>光影：主光左前 45°／高 30°，明暗比 3:1<br>字卡：`不是一個字` 96px，0.3s 彈入 | 旁白：「一個 token／**不一定**是一個字↘」<br>語氣：平述不催促，重音落在「不一定」，句尾下沉<br>字幕：逐字同步<br>配樂：ambient pad，−30 LUFS，0.5s 淡入<br>音效：字卡彈入輕點 −24dB<br>收音：領夾麥 20cm／HPF 80Hz／安全軌 −12dB<br>來源：`chunk_0005`・`rewritten` |
```

### 三條規則

1. **一列 = 一個鏡頭**，不可一列塞兩鏡
2. **`來源` 欄不可留空**：不是 chunkId 就是 `template` 或 `ai_added`。留空代表溯源驗證會失敗，流程第 ④ 關會中止
3. **生成鏡的 prompt 不寫在表格裡**，表格只放鏡號，prompt 以 `### S1` 的形式放在表格下方

### 焦段與收音的寫法

| 項目 | 寫法 | 說明 |
|------|------|------|
| 焦段 | `35mm`、`50mm`（等效） | 手機拍也要寫，對應到 1x／2x |
| 收音 | `領夾麥 20cm／HPF 80Hz／安全軌 −12dB` | 安全軌是防爆音的第二軌，教師講到激動處會用到 |
| 生成鏡收音 | `無（原生音軌剝除，走腳本鎖定語音）` 或 `原生對白（須過 G3）` | 見 §11.1 |

## 3. 吸引力規格（前 3 秒與留存）

教學短影音一樣要先被看完才有教學效果。這一節是十支的硬性下限，**不是可選的加分項**。

### 3.1 前 3 秒要同時做三件事

| 工作 | 意思 | 沒做到會怎樣 |
|------|------|-------------|
| Pattern interrupt | 打斷滑動的手 | 直接被滑掉，後面拍再好也沒人看到 |
| 承諾 | 讓他知道看完能拿到什麼 | 停三秒但不知道為什麼要留下 |
| 好奇缺口 | 只有看完才能解決 | 看懂第一句就走了 |

**口說鉤子必須在 3 秒內講完，約 10–14 字。** 超過就是寫太長。

### 3.2 三個鉤子公式（十支共用）

同一份知識可以寫出三種開場，每支都寫了三種，但**第一階段只用預設那句**，見下方測試設計。

| 公式 | 做什麼 | Token 版本 | 來源 |
|------|--------|-----------|------|
| **反常識** Contrarian | 否定他相信的事 | 「一個 token，不一定是一個字。」（13 字） | `chunk_0005` |
| **錯誤警告** Mistake Warning | 指出他正在犯的錯 | 「你在算 ChatGPT 要花多少錢，但單位可能算錯了。」 | `chunk_0007` |
| **清單預告** List Tease | 預告數量，製造缺口 | 「這句話丟進 ChatGPT，會被拆成幾個東西？」 | `chunk_0005` |

> 這份知識天生就有一個強鉤子：**「連句點都算一個 token」**（`chunk_0006`）。幾乎所有人第一次都以為一個 token 就是一個字，所以三種公式的底層都是同一個反差。

**開場不用學生原問句。** 原問句很真實，但它是「問題」不是「承諾」，放在第 0 秒等於要觀眾自己補完為什麼要看。把它移到第 3–6 秒當共鳴，效果比放開頭好。

> **三種備選開場保留在文件裡，但第一階段不做。**
>
> 十種手法與三種開場**不能同時測**——那是 30 支，而且兩個變數混在一起什麼都測不出來。分兩階段：
>
> | 階段 | 測什麼 | 支數 |
> |------|--------|------|
> | **一** | 十種呈現手法，**開場一律用該支的預設那句** | 10 |
> | 二 | 第一階段前 2–3 名的手法 × 三種開場 | 6–9 |
>
> **現在做的是階段一，只用預設開場。** 備選開場留著給階段二用。

### 3.3 第一格的硬性要求

- **立刻有動態**。極慢推近＝靜止，不算。開場 0.5 秒容許一次明顯的視覺事件（字卡彈入、鏡頭輕微下沉、畫面切換），這是全片唯一可以「用力」的地方
- **大字卡 4–7 字**、高對比、在上下安全區內
- **無聲成立**。多數人第一次看是靜音的
- 字卡內容是**承諾或反常識**，不是問句

### 3.4 Pattern interrupt 的節奏

**每 10–15 秒一次**，否則觀眾的無聊計時器會走完。

教學片用**溫和型**：切鏡、字卡形態改變、局部放大、角度變化。**不要用暴力 zoom、誇張音效、閃爍轉場**——那會拉高認知負荷，畫面熱鬧了但學生反而記不住。

> **原則：注意力由解釋層負責，不是氛圍層。**
> 這條化解了「要吸引人」與 Phase2 §3.6「背景低對比不搶戲」之間的矛盾——背景維持淡，attention 靠字卡動態與剪接點來給。

### 3.5 留存節奏表（十支共用）

| 秒 | 必須發生的事 |
|----|--------------|
| 0–3 | 鉤子：pattern interrupt + 承諾 + 好奇缺口 |
| 3–6 | 共鳴：學生原問句或痛點場景 |
| 10–15 | **第一次 pattern interrupt**（切鏡或字卡形態變化） |
| 15–18 | **Open loop**：埋一句微鉤子重啟承諾，例「但真正麻煩的是第二個」 |
| 20–25 | 第二次 pattern interrupt |
| 25–30 | **收束重述**：把核心那句再講一次 |

**最後 5 秒是重述，不是導流。** 30 秒的教學靠重複建立記憶點——把最反直覺的那句（「連句點都算一個」）再講一次，比塞新資訊或留白都有效。

**不要在最後放新的資訊。** 觀眾在第 25 秒已經準備滑走了，這時候給新東西等於丟掉。

### 3.6 字幕

**逐字同步（karaoke 式）**，講到哪個字就亮哪個字。音訊注意力飄走時，眼睛還有東西可以追。這比字幕一次整句跳出來的留存高。

## 4. 聲音規格

畫面規格寫得再細，**聲音沒設計一樣會被滑掉**。這一節補齊唸法、配樂、音效與混音。

### 4.1 旁白唸法標記

分鏡表的「旁白」欄直接用這套標記寫，配音員或 TTS 照著唸。

| 記號 | 意思 |
|------|------|
| **粗體** | 重音 |
| `／` | 短停，約 0.3 秒 |
| `／／` | 長停，約 0.6 秒（通常用在鉤子與共鳴之間） |
| `↗` | 句尾上揚——留懸念，用在 open loop |
| `↘` | 句尾下沉——給結論，用在結論句與收尾 |
| 〔慢〕〔快〕 | 語速變化，作用到下一個標記為止 |

**一支 30 秒的片，重音不超過 6 個。** 到處都是重音等於沒有重音。

寫法範例：

```
旁白：「一個 token／**不一定**是一個字↘／／〔慢〕連句點都算一個。」
```

### 4.2 TTS 參數（01、03、07、09、10 用）

| 參數 | 值 |
|------|-----|
| 語音 | **台灣中文女聲**（定案）。不要用大陸腔語音包 |
| `speakingRate` | 1.0–1.1。教學內容**不要超過 1.15** |
| `pitch` | 0（不要調高，會變機器感） |
| 停頓 | `<break time="300ms"/>` 對應 `／`，`600ms` 對應 `／／` |
| 重音 | `<emphasis level="moderate">` |

> **TTS 唸英文字與數字最容易出錯。** `token`、`ChatGPT` 合成後必須實聽；05、08 收束句裡的「五個」也要確認沒被唸成「5」。

**用 TTS 的是哪五支**：01、03、07、09、10。02、04、05、08 是真人現場收音，06 是老師原音。

**女聲是定案，不再逐支試聽比較。** 選定一組語音參數後十支共用，這樣五支聽起來才像同一個系列；而且與 02、04 出鏡老師的聲音形成區隔，學生一聽就知道這支有沒有老師本人。

### 4.3 配樂

| 項目 | 規格 |
|------|------|
| 有無 | **一律要有，但一律很小**。完全無配樂的教學片會有「錄音間」的乾澀感 |
| 曲風 | 無旋律的 ambient / textural pad。**有旋律的音樂會跟旁白搶語言處理區**，學生會覺得聽起來很累但說不出為什麼 |
| 音量 | −28 ~ −32 LUFS（比旁白低 18–22 dB） |
| Ducking | 旁白出現時再壓 3 dB |
| 進出 | 0–0.5s 淡入；最後 1.5s 淡出 |
| 禁止 | 鼓點強烈的 trap／EDM、**任何有人聲的音樂**、版權不明的流行曲 |

> **03 無縫循環是例外**：尾端不可淡出，必須淡到與開頭同音量，否則接點會聽出音量落差。

### 4.3b 配樂來源：自製（定案）

**十支共用同一首自製的 ambient pad，長度 40 秒可循環。**

#### 為什麼不用現成音樂庫

**「免費」和「不會被 Content ID 打」是兩件事。** Content ID 靠音訊指紋比對，不看授權文件——曲目被第三方（有時是原作者自己）註冊進 Content ID，拿著合法授權一樣會被聲明，只是申訴會贏。2026 的偵測已能標到 0.5 秒的片段。

而我們要的東西**自製比找現成的更容易**：無旋律、低頻為主的 pad，在任何 DAW 裡用一個 pad 音色加長 reverb 就能做，做一次十支通用。零授權風險、零 Content ID 風險、不用留存證據、不用申訴。

#### 自製規格

| 項目 | 規格 |
|------|------|
| 長度 | 40 秒，首尾可無縫循環 |
| 內容 | **無旋律**、無節拍、單一和聲的持續 pad；低頻為主 |
| 音量 | 輸出 −30 LUFS |
| 動態 | 起伏 ≤ 3 dB。**不可有段落感**（03 循環片會對不上） |
| 檔案 | 保留 DAW 專案檔與 wav 母帶，存在專案 repo 外的共用空間 |

**09 是例外**，它需要有節拍感的 pulse。同樣自製：在同一組 pad 上加一個極簡的低頻脈衝（每拍一下、無音高變化），**仍然不可有旋律**。

#### 備案（自製來不及時）

| 順位 | 來源 | 條件 |
|------|------|------|
| 1 | **YouTube 官方音效庫** | 主要發布在 YouTube 時最安全，不會被自家 Content ID 誤判 |
| 2 | **CC0**（Pixabay Music、FMA 的 CC0 條目） | 免署名、可商用，**但仍要做上傳前預檢** |
| 3 | CC BY | 免費但**必須署名**，描述欄要寫曲名、作者、授權連結 |

**不可使用**：

- **CC BY-NC**——學校頻道不必然算「非商業」，教學用途也不等於 non-commercial
- **CC BY-SA**——ShareAlike 可能要求衍生作品同授權，影片算不算衍生有爭議
- YouTube 上來源不明的「免費 BGM」頻道

用備案時**必須留存證據**：下載當下截圖授權頁，記錄曲目 URL、授權版本、下載日期。授權會被改、曲目會下架，事後補不回來。

### 4.3c 上傳前 Content ID 預檢（所有支必做）

```
① 先以 unlisted 上傳到 YouTube
      ↓
② 等 Content ID 掃描完成（約 15 分鐘）
      ↓
③ 進 YouTube Studio 確認沒有版權聲明
      ↓
④ 確認後才改成正式的可見度
```

**這一步不可省。** 自製配樂理論上不會被聲明，但**生成影片的畫面也可能被打**（若生成內容與某支已註冊的素材相似），預檢是唯一能在對外前發現的方法。

有聲明就先不要公開，查清楚是哪一段被標到再處理。

### 4.4 音效音量表

| 用途 | 音量 |
|------|------|
| 字卡彈入輕點 | −24 dB |
| 鉤子重擊（thud、✕ 落下） | −22 dB |
| 切鏡輕點 | −26 dB |
| 環境底噪 | −32 dB |
| 實拍原音（筆觸、剪紙聲） | 保留原音，必要時 +3 dB |

**一支片的音效種類不超過 3 種。** 種類一多就變成綜藝節目，教學內容會被蓋掉。

#### 音效來源：自製（定案）

跟配樂同一個理由——**自製零授權風險、零 Content ID 風險，而且比找還快**。我們只需要三種，都極簡：

| 音效 | 怎麼做 | 時間 |
|------|--------|------|
| 開場 thud | 60Hz 正弦波 + 0.3 秒指數衰減 | 2 分鐘 |
| 字卡輕點 | 短脈衝（2–3ms）+ 極短 reverb | 2 分鐘 |
| 切鏡輕點 | 同上，音量再低 4dB | 1 分鐘 |

Audacity 免費就做得完，做一次十支共用。實拍原音（筆觸、剪紙）不在此列，那是現場收的。

**備案**：CC0 音效庫（Freesound 篩 CC0）或 YouTube 官方音效庫，同樣要留存授權證據。**不要為了三個 0.3 秒的音效去查一套新工具的授權條款**，不划算。

### 4.5 混音標準

| 軌 | 音量 |
|----|------|
| 旁白 | 基準，−16 LUFS |
| 配樂 | −28 ~ −32 LUFS |
| 音效 | 峰值不超過旁白 −6 dB |
| **成品整體** | **−14 LUFS**（平台標準），真峰值 ≤ −1 dBTP |

沒有做 loudness normalization 的片子在 Shorts 上會被平台自己壓，壓完聽起來會悶。

### 4.6 十支的配樂與音效配置

| # | 配樂 | 音效（最多 3 種） | 特別注意 |
|---|------|------------------|----------|
| 01 | ambient pad，低頻為主 | 開場 thud、字卡輕點、切鏡輕點 | 全 TTS，收束句要先聽過 |
| 02 | ambient pad，極輕 | ✕ 輕擊、字卡輕點 | 真人收音，配樂只是墊底 |
| 03 | ambient drone，**首尾同音量不淡出** | 字卡輕點（僅此一種） | 音效多一種就會暴露接點 |
| 04 | 無配樂或極輕 | 字卡輕點、切鏡輕點 | 對話片有配樂容易顯吵 |
| 05 | ambient pad | **筆觸原音**（主角）、字卡輕點 | 筆聲要清楚，配樂再壓低 3dB |
| 06 | **無配樂** | 無 | 原片有教室環境音，加配樂會打架 |
| 07 | ambient pad + 一個低頻 stab | ✕ thud（僅一次）、切鏡輕點、分割音 | 紅色 ✕ 與 thud 同時到 |
| 08 | 極輕或無 | **剪紙原音**（主角）、無其他 | 開場三聲「喀喀喀」是鉤子本體 |
| 09 | 有節拍感的 pulse（唯一一支，同樣自製） | 字卡輕擊、切鏡輕點 | 在共用 pad 上加低頻脈衝，仍無旋律 |
| 10 | ambient drone | 斷裂聲（僅此一種） | 斷裂聲的變化要跟著隱喻走 |

### 4.7 靜音備援

**多數人第一次看是靜音的。** 所以：

- 字幕逐字同步，講到哪亮到哪
- **每一個音效都要有對應的視覺事件**。有聲沒畫面的音效等於白做
- 驗收時關掉聲音看一遍，看不懂就是不合格

## 6. 人臉政策（`facePolicy`）

| 值 | 意思 | Negative prompt | `personGeneration` |
|----|------|-----------------|--------------------|
| `none` | 生成鏡不得出現可辨識人臉 | `{{NEG_BASE}} + {{NEG_FACE}}` | `dont_allow` |

## 7. 三道驗證關（取代 v5 的紅線）

舊版用「生成畫面一律不准帶資訊」處理風險。**v6 改成：可以帶，但要驗。**

| Gate | 位置 | 檢查什麼 | 不過關 |
|------|------|----------|--------|
| **G1 溯源** | 生成之前 | 每一句都對得回 chunkId，且屬同一課程 | 中止，不花錢 |
| **G2 字面** | 生圖後、生影片後各一次 | 畫面文字 OCR 回讀 **逐字等於** `expectedText`，且無多餘文字 | 重出圖；5 次不過退回程式化渲染 |
| **G3 語音** | 合成之後 | ASR 回讀成品音軌，逐字比對腳本 | 重新合成語音 |

### 7.1 三種畫面 Profile

每一鏡要標定它是哪一種，**同一鏡不可混用**——混用會讓模型同時收到「要有字」與「不准有字」。

| Profile | 用在 | negative | 驗證 |
|---------|------|----------|------|
| **A 帶指定文字** | 字卡、標籤、關鍵詞 | 排除「拼錯、亂碼、重複、多餘的字」，**不排除文字本身** | G2 必過 |
| **B 氛圍／隱喻** | 背景空景、實體隱喻 | `{{NEG_BASE}} + {{NEG_FACE}}`（全面排除文字） | 人工看一眼即可 |
| **C 虛擬講解員** | AI 人物出鏡 | 排除文字、校徽、制服標誌、肢體崩壞 | G3 + 標示檢查 |

### 7.1b G2 失敗時一律退回程式化渲染（定案）

**重試上限 5 次，過不了就退回程式化字卡，不再繼續試。** 並記錄 `fellBackToProgrammatic: true`。

理由：硬拚生成文字會讓成本失控，而退回程式化字卡對教學效果沒有影響——**畫面上的字一樣正確，只是少了「字長在畫面裡」的質感**。這是可以放棄的東西。

累積的 `fellBackToProgrammatic` 次數本身就是有用的資料：若某類字串（例如中文長句）長期退回，就把它從 profile A 的適用範圍拿掉。

### 7.2 仍然直接用程式化渲染的三種內容

不是不能生成，是**重試次數會高到不划算**：

- 數學公式、上下標、希臘字母
- 多行條列、表格
- **收束字卡**（`連句點都算一個`）——它是全片的記憶點，寫錯等於整支白做

短字串（≤ 8 字）與單一詞彙走 profile A 生成。中文長句可以試，但重試上限調低。

### 7.3 虛擬講解員的四條規則

風險不是「畫面裡有 AI 的人」，是**學生誤以為那是授課教師**：

1. **固定角色**：同課程所有短影音用同一個講解員，reference image 鎖住長相
2. **可見標示**：角落常駐 `AI 講解員`
3. **不得冒充**：不取授課教師姓名、不模仿其長相與聲線、不以第一人稱聲稱是授課教師
4. **未經書面同意，不得複製真實師生的臉或聲音**——這一條不放寬，是肖像權與聲音權，不是規格偏好

### 7.4 殘餘風險（要知道）

- **OCR 過了不代表沒錯**：全形半形、形近字（`日`／`曰`）、標點差異可能被判成一樣。所以教師覆核**仍然要看畫面上的字**
- **G2／G3 會拉高重試率**，成本估算需要重算，舊的 NT$130／支只涵蓋舊流程
- **虛擬講解員長相會飄**，跨支一致性靠 reference 鎖，且會失敗

## 8. Prompt 常數

### `{{NEG_BASE}}`

```
text, letters, words, numbers, digits, formulas, equations, charts, graphs,
axes, diagrams, schematics, labels, captions, subtitles, signage, logos,
brand marks, watermarks, user interface elements, any readable content,
extra limbs, deformed hands, warped geometry
```

### `{{NEG_FACE}}`

```
human face, recognizable person, portrait, eyes, facial features, crowd of people
```

### `{{STYLE_CALM}}`

教學氛圍層的美學約束與一般短影音**相反**：學生要同時處理旁白、字幕、字卡，背景越搶戲認知負荷越高。

```
soft natural light, low contrast, muted desaturated palette,
shallow depth of field, generous negative space in the upper and lower thirds,
realistic photography, calm and unobtrusive
```

### `{{FRAME}}`

```
vertical 9:16 aspect ratio, 1080x1920
```

### `{{NEG_TEXT_A}}`（v6 新增，profile A 專用）

Profile A 要**有**文字，所以不能用 `{{NEG_BASE}}`（它把文字整個排除掉，會跟 `Text:` 欄位打架）。改成排除「錯的文字」：

```
misspelled text, garbled letters, duplicated text, extra words,
watermarks, logos, user interface elements, recognizable human faces
```

### `{{NEG_PRESENTER}}`（v6 新增，profile C 專用）

```
text, letters, numbers, logos, watermarks, university crest,
uniform insignia, extra limbs, deformed hands, warped face
```

### `{{TEXT_BLOCK}}`（v6 新增，profile A 的文字欄位）

```
Text: the exact text "{{EXPECTED_TEXT}}" appears, cleanly rendered,
      high contrast, horizontally centred in the upper third,
      no other text anywhere in the image.
```

**一鏡只放一個字串**，兩個以上就分鏡。`{{EXPECTED_TEXT}}` 同時寫進 `ShortAsset.shots[].expectedText` 供 G2 比對。

## 9. 無縫循環（第 03 支專用，其餘可選）

Shorts 播完會自動重播。**若最後一格能接回第一格，觀眾看不出接縫，會多看一到兩輪，完播率與播放數同時被拉高。**

做法三個條件缺一不可：

| 條件 | 規格 |
|------|------|
| 畫面 | 尾鏡最後一格與首鏡第一格**構圖、色調、光線位置一致**。生成時用同一張 `startFrame`，尾鏡的 `videoPrompt` 指定運鏡方向相反 |
| 語句 | 最後一句與第一句在語意上要能接上，不能有「以上」「總結」這種收尾詞 |
| 音訊 | 旁白尾端與開頭之間留 0.2–0.3 秒空白，且背景音在尾端 0.5 秒淡出到與開頭同音量 |

驗收方式：把成品**首尾接起來播三輪**，看得出接縫就是沒做到。

## 10. 生成鏡流程

```
① 展開 prompt 常數，依 profile 選 A / B / C
      ↓
② 生首格靜圖
      ↓
③ G2 字面驗證 ★
      profile A：OCR 回讀 = expectedText？有無多餘文字？
      profile B：有無任何文字？
      profile C：有無文字／校徽／肢體崩壞？
      → 不過關回 ②（一張約 NT$1.5）
      → 連續 5 次失敗 → 退回程式化渲染，記 fellBackToProgrammatic
      ↓
④ 圖生影片（8 秒 / 1080p / 9:16）
      ↓
④' G2 複驗 ★  抽首／中／末格再回讀一次
      → 文字被改動就重生這一段
      ↓
⑤ 立即下載存檔 ❗（伺服器只保留 2 天）
      ↓
⑥ 拼接 → 疊語音 → 燒字幕 → 疊標示
      ↓
⑥' G3 語音驗證 ★  ASR 回讀成品音軌，逐字比對腳本
      → 相似度 < 0.95 或關鍵詞漏掉 → 重新合成語音
```

### 呼叫參數（介面形狀參考，不綁特定模型）

```js
const operation = await videoModel.generateVideos({
  model: META.videoModel,
  prompt: shot.videoPrompt,
  image: shot.startFrame,
  config: {
    aspectRatio: "9:16",
    resolution: "1080p",
    durationSeconds: "8",
    personGeneration: META.personGeneration,
    referenceImages: [ref1, ref2],   // 最多 3 張，鎖住全片風格／講解員長相
  },
});
```

### 選型時要問的三個問題

1. **能不能指定畫面內文字？** 不能的話 profile A 走不了，該模型只能做氛圍層
2. **圖生影片會不會改動首格文字？** 會的話 ④' 複驗必做，重試成本上升
3. **語音是模型自由生成還是吃我們的稿？** 自由生成的一律要過 G3

> **模型與價格請在實作前重新查證。** 這份規格不綁型號，就是為了避免規格比模型先過期。

## 11. FFmpeg（共用）

### 11.1 生成音軌怎麼處理（v6 改寫）

舊版一律剝除。v6 分兩條路，取決於**語音內容是誰決定的**：

| 路線 | 做法 | 驗證 |
|------|------|------|
| **A 腳本鎖定（預設）** | 剝掉原生音軌，改用我們提供逐字稿合成的語音 | G3 仍要跑，確認沒漏字唸錯 |
| **B 原生對白** | 在 prompt 裡指定台詞，保留模型生成的語音 | **G3 必過** |

**沒有第三條路**：讓模型自由生成語音又不驗證，正是舊版一律剝除想避免的事。v6 沒有放寬這一點，只是把「禁止」換成「驗證」。

> 路線 B 的實務風險：多數影片模型對指定台詞的忠實度不穩定，而且重試的是**整段影片**（貴），不是語音（便宜）。**除非有特別理由，預設走 A。**

路線 A 剝音軌：

```bash
ffmpeg -i clip.mp4 -an -c:v copy clip_silent.mp4
```

路線 B 抽音軌送 ASR：

```bash
ffmpeg -i clip.mp4 -vn -acodec pcm_s16le -ar 16000 -ac 1 check.wav
```

G2 複驗抽格：

```bash
ffmpeg -i clip.mp4 -vf "select='eq(n\,0)+eq(n\,120)+eq(n\,239)'" -vsync 0 frame_%02d.png
```

```bash
ffmpeg -f concat -safe 0 -i list.txt -c:v libx264 -crf 20 -preset medium -an joined.mp4
```

```bash
ffmpeg -i joined.mp4 -i narration.wav -c:v copy -c:a aac -shortest with_audio.mp4
```

```bash
ffmpeg -i with_audio.mp4 -vf "ass=script.ass" -c:a copy subtitled.mp4
```

含生成畫面者必須疊可見標示：

```bash
ffmpeg -i subtitled.mp4 -vf "drawtext=fontfile=NotoSansTC-Medium.otf:text='AI 示意畫面':x=w-tw-28:y=28:fontsize=30:fontcolor=white@0.72:box=1:boxcolor=black@0.30:boxborderw=10" -c:a copy final.mp4
```

原片為 16:9 轉 9:16（第 06 支用），用模糊背景填滿而非裁切：

```bash
ffmpeg -i lecture.mp4 -filter_complex "[0:v]scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,gblur=sigma=24[bg];[0:v]scale=1080:-2[fg];[bg][fg]overlay=(W-w)/2:(H-h)/2" -c:a copy vertical.mp4
```

## 11b. 字型、調色與發布規範（v7 新增）

### 11b.1 字型

| 用途 | 字型 | 字級 |
|------|------|------|
| 字卡 | **Noto Sans TC（思源黑體）Bold** | 96px |
| 字幕 | **Noto Sans TC Medium** | 64px |
| 小標（例：`學生提問`） | **Noto Sans TC Regular** | 40px |

**只用這一個字型家族、只用這三級。** 同一家族才像一個系列，字重差異就足以拉出層次。

- 授權：**SIL Open Font License，商用免費、可嵌入**
- 備選：台北黑體（同為開源，字形較方正）
- **不要用微軟正黑體**——系統字型，散布授權有限制

### 11b.2 調色：十支統一

| 項目 | 基準 |
|------|------|
| 色溫 | 5000K |
| 飽和度 | 低（生成鏡由 `{{STYLE_CALM}}` 的 `muted desaturated palette` 保證） |
| 對比 | 低 |
| 輸出 | 十支套同一組最終調整，不逐支調 |

> **統一調色是測試的必要條件，不是美學潔癖。**
>
> 這十支是要比「哪種呈現手法有效」，**呈現手法就必須是唯一的變數**。十支調色不一，結果出來會分不出是「07 的對照結構有效」還是「07 剛好色調比較好看」。
>
> 統一調色不會抹平十支的差異——那些差異在結構不在顏色。

### 11b.3 標題、描述、hashtag

**標題**（Shorts 會截斷，重點放前 30 字）：

```
一個 token 不一定是一個字｜30 秒搞懂
```

公式：`反常識結論｜30 秒搞懂`。前半是鉤子，後半是承諾。

**描述**（三行就夠）：

```
連最後的句點都算一個 token。

這支影片的內容全部出自課程逐字稿，沒有額外補充。

#FocusFlow #AI教學 #token
```

第二句是**溯源聲明**——這是相對其他 AI 影片的優勢，要講出來。

**hashtag 三個上限**：`#FocusFlow`（品牌）＋ `#AI教學`（分類）＋ 一個題目標籤。多了會稀釋。

### 11b.4 檔名

```
SV-<編號>_<主題>_<版本>.<副檔名>
例：SV-07_token_v1.mp4、SV-07_token_v1_S1.png
```
