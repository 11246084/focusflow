## 討論內容

1.  **專題進度報告 - 資料庫與Embedding**
    - 背景：學生報告目前專題進度。
    - 內容：
      - 目前所有資料已準備就緒，所有索引也已完成。
      - Embedding部分針對文字、圖片、語音進行，但圖片Embedding尚未處理。
      - 學生有查詢到老師建議的Python工具(FFmpeg)。

      - 資料庫中刪除了AI處理過程產生的暫存資料表（如SST）。
    - 結論傾向：老師同意現階段以文字搜尋為主，後續再擴充圖片搜尋，符合專題報告的階段性目標。

2.  **專題進度報告 - LINE Bot**
    - 背景：學生報告LINE Bot開發進度。
    - 內容：
      - LINE Bot目前使用一次性驗證碼（token），每次操作需重新執行整個流程。
      - 教授詢問驗證碼用途，學生說明用於認證。
      - 教授說明此機制讓後端能識別發送訊息的聊天室ID。
      - 學生確認現階段採用此方式，並規劃未來前端使用QR Code進行驗證。
    - 結論傾向：老師認可此為現階段可接受的方案，並強調重點在於完整串聯整個工作流程。

3.  **專題展示規劃與優化建議**
    - 背景：教授針對專題報告與展示的重點提出建議。
    - 內容：
      - 教授建議6月2日的報告應著重展示完整的工作流程，即使細節不盡完美也無妨。
      - 教授舉例：若要優化，可加入學生透過網站產生QR Code向助教提問的功能，助教掃碼後透過LINE Bot回覆。
      - 學生補充說明未來展示可能包含：前端展示QR Code，助教掃碼後點擊LINE Bot提問。
      - 教授另舉例：課程系統中學生加入後可看VOD，後端處理VOD內容（音訊、文字、影像）的Embedding。
      - 學生掃描QR Code後，綁定到助教的聊天室。
      - 學生提問後，系統會比對問題與Embedding向量，回傳相關影片片段或答案。
      - 學生確認已實作此功能：提問後可從資料庫取出Embedding，並根據老師提供的影片回傳相關片段。
    - 結論傾向：現階段以展示核心工作流程為主，進階功能如QR Code交互可排入第二階段優化。

4.  **AI程式碼理解與學習建議**
    - 背景：教授指出學生應加強對AI生成程式碼的理解。
    - 內容：
      - 教授認為學生目前對AI生成的程式碼理解不夠深入，不能只說「AI做的」。
      - 教授強調應了解AI代碼的具體功能、運作原理（如向量比對、Cosine Similarity），以及如何計算和判斷。
      - 建議方式：要求AI生成附註解的Python代碼，逐行討論。
      - 教授舉例詢問：何謂「向量比對」？如何計算？為何比對有效？若改用「歐幾里得距離」會有何差異？為何Cosine Similarity在此情境下表現較優？
      - 教授建議AI先提供程式碼架構，學生再依此學習。
      - 學生提及目前AI僅能記錄3回合對話，教授指出NoSQL資料庫可儲存更多對話紀錄，並強調對話記錄規模遠小於影像資料。
    - 結論傾向：現階段最重要是深入理解AI生成的代碼，而非急於優化UI細節。應將AI代碼視為自己的作品，並能解釋其運作原理。

5.  **前端UI設計進度**
    - 背景：學生報告前端UI的設計與AI應用情況。
    - 內容：
      - 學生說明曾嘗試用AI生成UI，但AI產生了「亂碼」，故自行手動製作SVG。
      - 教授提及Figma與Codex/Claude的整合能力，可直接生成UI（可達80%完整度）。
      - 學生說明目前首頁UI已完成，但部分間距、文字、顏色仍需手動調整。
      - 學生使用Flow Design，提供截圖和專題摘要，AI生成兩種相似設計（登入頁、學生/老師/管理員視圖）。
      - 學生認為AI生成UI的完成度高，現階段會先採用。
    - 結論傾向：繼續使用AI生成UI作為初版，手動微調細節。

6.  **LINE Bot互動與影片播放流程**
    - 背景：學生提問LINE Bot與影片互動的具體流程。
    - 內容：
      - 學生詢問掃描QR Code後，課程選擇應在LINE內或網頁上？
      - 教授建議：使用者應先在網頁上選擇課程，點擊「詢問助教」後產生含課程ID的QR Code。
      - 教授建議使用YouTube平台託管影片並嵌入，可追蹤觀看進度、暫停等狀態。影片應設為**不公開（unlisted）**，不出現在搜尋結果，但可透過嵌入碼或連結存取（注意：私人影片無法嵌入）。
      - 教授解釋YouTube嵌入功能可判斷用戶是否正在觀看（即使切換分頁也會停止計時），類似於課堂點名系統。
      - 學生詢問LINE Bot是否能播放影片並直接互動，教授確認LINE Bot能傳送影片連結，YouTube連結可帶上時間戳記。
      - 教授建議不要預先整理所有Q&A，AI應動態檢索。但可分析常見問題。
      - **【補充整理】LINE Bot 核心回覆形式（第一階段）**：當使用者提出與課程相關的問題，Bot 以文字回答並附上可直接點擊的 YouTube 影片連結，連結需帶時間戳參數（`?t=<sec>`），讓使用者點擊後直接跳轉至講述該知識點的時間點，無需自行搜尋。
      - **【補充整理】LINE Bot 進階回覆形式（未來規劃）**：討論由系統自動剪輯關鍵影片片段（數秒至數分鐘），生成短影片直接傳送給使用者，讓使用者無需離開 LINE 即可獲得解答。
      - **【補充整理】回覆觸發情境設計**：Bot 應專注於回應使用者學習過程中真正會提出的具體問題（例如：「OpenCV 怎麼畫正方形？」），而非只回覆課程大綱類資訊，使功能更貼近實際應用場景。
    - 結論傾向：採用網頁上選課、產生QR Code，LINE Bot回覆YouTube影片連結的方式，並利用YouTube嵌入功能追蹤觀看狀態。第一階段以文字回答＋附時間戳記的YouTube連結為主，未來再評估動態短影片剪輯功能。

7.  **AI學習方法與未來挑戰**
    - 背景：教授從宏觀角度分析AI發展對個人學習與社會的影響。
    - 內容：
      - 教授指出AI會加劇社會貧富與能力分化，使中階能力價值降低，中產階級工作底層化。
      - 教授強調人類的價值在於產生AI想不到的創新點子，但這需要扎實的背景知識。
      - 教授提及曾有個AI論壇(Mootbook)，AI在其中創建宗教，但其內容實為模仿人類既有知識，並未產生真正創新。
      - 教授建議「放慢腳步」，重點在於理解AI代碼背後的邏輯與原理，將其轉化為自身知識。
      - 教授指出若只會指令AI，人將會更懶惰，無法思考，最終可能被AI誤導而不自知。
    - 結論傾向：專注於理解AI程式碼的運行原理，而非僅限於指令操作，以培養未來AI時代的核心競爭力。

8.  **學生影片上傳功能**

12. **LINE Bot與網頁整合方案**
    - 背景：學生詢問是否應將整個LINE Bot介面整合到網頁中。
    - 內容：
      - 教授建議不要完全整合，因LINE是主要互動入口，整合會有許多問題（如推播通知）。
      - 教授建議網頁用於影片觀看，LINE Bot用於問答，再將影片連結帶時間戳記回覆。
      - 教授指出直接將LINE Bot整合進網頁的複雜性高，且不符合當前目標。
    - 結論傾向：不將LINE Bot完全整合到網頁，維持網頁與LINE Bot的各自獨立角色。

13. **AI回答內容與細節**
    - 背景：教授詢問AI回答的細節，特別是語音Embedding的內容。
    - 內容：
      - 教授詢問AI回答是否能區分不同老師的講話內容或風格。
      - 學生已進行語音Embedding，並產生文字結果，但不知道語音Embedding是否能理解內容。
      - 教授表示希望了解Gemini的直接語音Embedding能否識別內容，而非僅為語音轉文字。
      - 教授舉例：若將聲音直接丟進Gemini Embedding，它會產生何種結果？是僅識別人聲，還是能理解內容？
      - 教授好奇Gemini的Embedding是否能區分不同老師的講話內容（如A老師的程式設計與B老師的程式設計），並能據此回答。
    - 結論傾向：老師對Gemini的直接語音Embedding能力抱持好奇，但建議現階段專注於主要流程。

15. **代碼理解優先於優化**
    - 背景：教授再次強調理解AI生成代碼的重要性。
    - 內容：
      - 教授建議學生應先將AI生成的代碼徹底理解，而非急於進行優化或增加新功能。
      - 教授舉例：即使是基本流程，也要搞清楚每個環節的程式碼邏輯。
      - 教授強調不能只「看一下」代碼，而是要深入探究每一行代碼背後的原理和目的。
    - 結論傾向：專案的重點應放在深入理解AI生成的代碼，而非僅限於完成功能。

## 決議事項

1.  現階段專注於完成並理解專題的核心工作流程，包括資料庫與Embedding、LINE Bot驗證、影片播放與問答連結。
2.  學生前端介面可繼續使用AI生成的UI作為初版，並手動進行細部調整。
3.  LINE Bot互動流程確認為：使用者在網頁上選課，點擊「詢問助教」後產生含課程ID的QR Code，LINE Bot回覆YouTube影片連結（含時間戳記）。
4.  影片託管採用YouTube，影片設為**不公開（unlisted）**，利用嵌入功能追蹤觀看狀態，不自行建置串流伺服器。
5.  Backend部分需確保資料庫資料的完整性，尤其是非結構化資料的儲存（如LINE對話紀錄）。
6.  鼓勵學生參與全國性專題競賽，此為重要的學習與加分機會。
7.  現階段 API 金鑰的使用成本不需過度擔心。
8.  學生組可考慮報名全國技專院校專題競賽。
