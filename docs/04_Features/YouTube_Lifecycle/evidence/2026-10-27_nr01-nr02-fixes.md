## NR01：清理接管與不可逆邊界

修改 [localSourceCleanup](../../../../backend/src/services/localSourceCleanup.service.js)、[Video 清理](../../../../backend/src/services/youtubeUpload.service.js) 與 [ShortAsset 清理](../../../../backend/src/services/shortAssetCleanup.service.js)：

1. `claimed → deleting` 必須由相同 intent owner 原子轉換，之後沿用既有設定／引用／期限／同步實體與空間檢查，再 unlink。
2. unlink 後 DB 收尾失敗仍保留 intent；舊 owner 停止檔案操作後可標 `repairable`。若連標記也失敗，等待租約過期，沒有把失敗當成功或清掉依據。
3. 恢復程序先用舊 id＋過期或 repairable 條件取得新 id、來源版本及 `recovering`，再查檔案。intent 全程存在，來源補回與短片回 draft 不能穿過空窗。
4. 檔案不存在就補寫清理完成，存在才取消；兩者只接受新 id／版本。舊 owner 的取消／收尾不能移除接管者的 intent。恢復者死亡或 DB 回寫失敗可再次到期接管。

例：A 刪掉原片後停止 → B 接管 → B 補寫 localCleanupAt → Video 開放補回；ShortAsset 保持 archived 且不能當成有原片的 draft。租期仍是 120 秒，並未以延長期限或多讀一次替代所有權轉移。FR06 的最後同步空間檢查沒有重寫。

## NR02：DB 交易與外部待辦

[deleteCourse](../../../../backend/src/services/course.service.js) 使用 Mongoose transaction，將 ShortAsset 封存、Video／兩種 segments／Notification／Enrollment／FAQ 刪除、掛載與 activeCourseId 清除、Course 刪除及待辦寫入一起提交。每個 DB 操作明確傳 session 並循序執行；snapshot 讀取與 majority 寫入確認。影片刪除條件要求無 intent 且非 uploading，短片仍採原狀態／intent 條件。失配、寫入衝突或任一步失敗都 abort，沒有逐筆刪除 fallback。

新增 [CourseDeletionJob model](../../../../backend/src/models/courseDeletionJob.model.js) 與 [待辦執行服務](../../../../backend/src/services/courseDeletionJobs.service.js)。這是 outbox：把不可共同交易的外部工作先保存在 DB，再於成功提交後執行。

- `coursedeletionjobs._id=<courseId>:<youtubeVideoId>`，每支系統上傳影片一筆；沿用既有轉私人條件。
- 同一交易補齊 legacy Video 的 `youtubebackups` 歸屬，保留到刪課後；另一內容不能取得該 ID，避免遲到待辦改到新內容。備份服務只新增可選 session，未重寫 FR01 協定。
- 立即嘗試、服務啟動及每分鐘批次（最多 10 筆）。原子 claim 寫 attemptId／claimedAt，120 秒租約過期可接管；失敗回 pending、稍後重試。完成只接受同一 attempt。
- YouTube 設為 private 成功但回應／DB 確認遺失時，重做同一 private；交易內不呼叫 YouTube，abort 時不用把外部影片改回公開。
- standalone Mongo 回 `503 COURSE_DELETE_UNAVAILABLE`，不刪資料；完整環境需支援交易。新集合關閉 autoIndex／autoCreate，沒有新 secondary index 或 TTL。測試另外移除兩個新集合後首次刪課，確認 Mongo 7 replica set 能在交易內建立並提交。

例：短片忙碌 → 刪課回 409，其他資料不變；DB 提交後程序死亡 → 下次啟動取得 pending 待辦完成轉私人。單支 Video 刪除流程及歷史 UsageLog／Question 政策不變。

## 待獨立複驗與限制

- 本輪測試不能替代獨立判定 FR02／FR05 PASS；請優先重排 NR01 的接管／unlink／回寫順序，及 NR02 的快照／清理 claim／abort 邊界。
- 新增交易需求，未查正式 topology、權限、collection 或 transaction 限額；大型課程若超過交易限制應失敗回滾，尚未做容量或 replica failover 實驗。Mongo 的交易限制見[官方文件](https://www.mongodb.com/docs/manual/core/transactions-production-consideration/)。
- 外部轉私人是延後完成：開關關閉、憑證不足、服務長期離線時待辦會保留，200 不代表 YouTube 已下架；本輪僅驗證假 API 的冪等重試與故障恢復，沒有真實外部驗收。完成待辦及備份歸屬不自動清除，需後續營運政策。
- 檔案與 Mongo 不共用交易，依賴所有 writer 使用新版協定、storage identity 穩定與正常時鐘。未涵蓋舊 binary／外部直接寫入、任意替換檔案，以及原有不參與課程交易的外部 pipeline 寫入；未擴大重構這些系統。
- 未執行 Frontend／瀏覽器、STT／FFmpeg 或正式清理人工驗收；本輪沒有相應介面／pipeline 變更或正式操作授權。
