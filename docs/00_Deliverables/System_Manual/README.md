## 本階段採用的寫作原則

實際閱讀初評 DOCX／PDF、系統手冊規範、專題評分表，以及三份歷屆系統手冊與一份大學範例後，本手冊採用下列可移植做法：

- 需求使用可追溯編號，並區分已實作、受環境條件限制與規劃中項目。
- 使用個案補足前置條件、角色步驟、例外流程與完成條件，不以功能清單代替操作敘述。
- 架構、套件與資料模型說明其在 FocusFlow 中的責任及邊界，不只羅列名詞。
- 程式章以代表性元件說明位置、輸入、輸出、責任、錯誤處理與驗證方式，不貼大量原始碼。
- 測試章分開記錄本機自動測試、隔離整合驗證、外部服務 smoke 與正式環境驗收。
- 操作／使用手冊依角色、成功路徑與常見失敗情境編排，使讀者能由文件理解實際操作。
- 圖表前後應有用途與判讀文字；歷史圖若與現況不一致，明確標示待重繪，不讓舊圖成為現況證據。

參考文件僅用於觀察結構與表達品質，未複製其專案內容。實際閱讀的代表性文件包括「動起來『揪』對了」、「IS Capt. AI 智慧資安管理平台」、「智能校事專家」系統手冊，以及「智慧社區圖書共享與管理平台」大學範例。
