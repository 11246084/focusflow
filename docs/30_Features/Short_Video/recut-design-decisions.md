# recut 短影片設計決策

recut 是把老師上課錄影的**原音**剪成 30～65 秒短片、配上程式產生的動畫圖卡的產片方式，和現有「AI 數位分身」並存。這份文件記錄 2026-10-14～17 與使用者逐題討論後**已定案的設計**與**還沒討論完的問題**，讓接手的人或 AI（Claude、ChatGPT、Codex）不用重讀對話。實作前先讀完「已定案」與「待討論」兩節；功能是否已完成只看[目前狀態](../../current-status.md)。

## 名詞

- **施工單（plan）**：描述一支短片的 JSON：選哪幾段老師的話、字幕、每段配什麼圖卡、圖卡何時出現。格式 `recut-v1`，定義見 [short_render](../../../short_render/README.md)。
- **錨點**：施工單不寫秒數，而是寫「老師講到某個詞」；程式依語音辨識的逐字時間換算成秒數。
- **連續視窗**：同一支影片中，學生問題的命中片段所在的一段連續 2～3 分鐘逐字稿。
- **worker**：在組員電腦（之後是 VM）上常駐的渲染程式，向後端領取工作。

## 整體流程（例）

學生常問「OpenCV 跟 YOLO 差在哪」→ 教師在選題後選「recut」→ 系統凍結連續視窗 → 對視窗做逐字辨識 → AI 第一步選段、第二步配圖卡 → 程式驗證 → 教師在瀏覽器預覽並核准 → worker 渲染 → 教師審成品 → 上架。

```
選題（共用）→ 教師選產片方式
  ├─ 生成模式（avatar，現有）：分散證據 → 8 拍口白＋隱喻 → ComfyUI（系統外）
  └─ recut：連續視窗 → 視窗辨識 → AI 選段 → AI 配圖卡 → 驗證 → 瀏覽器預覽 → worker 渲染
教師審核、成品上傳、成品審核、上架（共用）
```

## 已定案

| # | 決策 | 理由／證據 |
|---|---|---|
| 1 | 素材取自命中處擴出的**連續視窗**；找不到就放棄，之後再優化成擴大檢索 | 跨時間拼接會明顯跳接（第 1 支原型）。2026-10-16 唯讀實測 6 門課前 10 題，共 60 題，57 題找得到視窗 |
| 2 | 教師在**選題之後、建立腳本之前**選產片方式；一個主題一份腳本，生成前可切換 | 兩種方式的證據凍結不同；不動現有 `courseId + topicKey` 唯一索引 |
| 3 | 兩種方式**共用前後段**（選題、審核、上架），中間各自一條；**現有 8 拍生成程式不動** | 8 拍已有測試與實際生成紀錄，避免改 recut 時弄壞它 |
| 4 | 長度依內容彈性（驗證上限暫訂 30～65 秒）；不強求反轉；隱喻與 MiniMax 描述只給生成模式 | 老師講話長度不固定 |
| 5 | **聲音不改**；最多一次冷開場（同一視窗內、3 秒以內的句子搬到開頭），其餘依時間順序；字幕可由 AI 精簡但不得新增內容；段落間可加轉場字卡；通不通順由教師判斷 | 聲音是老師本人的，AI 能修飾的只有畫面文字 |
| 6 | **預覽在教師瀏覽器播放**（動畫網頁＋切好的片段）；渲染由 worker 做；VM 只用 FFmpeg 不重新編碼地切片段 | VM 跑不動渲染；預覽不必先渲染成影片 |
| 7 | VM 渲染預設關閉；環境由管理員人工安裝一次；管理員頁的開關控制 worker「接不接工作」；VM 的啟停按鈕等 VM 升級後才做 | 網頁不能遠端執行需要管理員權限的安裝，否則是安全漏洞 |
| 8 | **Node 20 → 24 升級是獨立任務，必須在 `dev` 合併到 `main` 之前完成**，附檢查清單與退回步驟 | Node 20 已於 2026-04-30 停止支援；HyperFrames 需 Node 22.12 以上。2026-10-16 本機用 Node 24.22 跑後端全套 983/983 通過；未驗證 Atlas 連線、pm2、VM 上前端打包 |
| 9 | 瀏覽器用 `chrome-headless-shell`，不裝完整 Chrome | 放在使用者目錄、可整個刪除；HyperFrames 偏好此版本。記憶體需求差不多，VM 仍需升級 |
| 10 | 第二階段預設版面：**全版動畫＋老師原音**；「上動畫下老師」與 Gemini 找老師畫面位置延後 | 一次避開裁切位置、人臉隱私、Zoom 小視窗畫質三個問題 |
| 11 | 系統內提供 **PoC 版同意條款**（參考網路範本），記錄誰、何時、同意哪一版 | 使用者要求；不代表法律上足夠 |
| 12 | **上傳影片時**詢問是否同意用於短片，預設不勾；舊影片在第一次選 recut 時補問；只有同意的影片能做 recut | 全版動畫只用聲音，同意範圍是「授課錄音與逐字稿用於製作短片並上傳 YouTube（非公開連結）」 |
| 13 | 插畫採 **Gemini 協助建立、人工核准的素材庫＋Phosphor 圖示（MIT）＋程式組合**；產片時不讓 Gemini 即時畫圖 | 2026-10-17 實測：Gemini 畫得較好看，但把「兩張小桌不能合成大桌」畫成大方塊橫跨兩桌，意思相反；每張需 23～44 秒 |
| 14 | **先對視窗做高品質語音辨識，再讓 AI 依辨識結果寫施工單**；兩關驗證（結構、引用、數字；錨點、總長）都在生成當下完成 | 原型實跑時錨點常因兩次辨識用字不同而對不上（200 張／兩百張、個／各） |
| 15 | 視窗辨識的目標位置是 **VM**（沿用 `STT_Whisper` 的 faster-whisper，用 small 模型），一次只跑一個；開發與試跑階段先在使用者本機 | 只辨識 2～3 分鐘；不必等組員電腦開機 |
| 16 | recut 生成改成**背景工作**（教師按下後顯示「處理中」，完成後通知）；8 拍生成維持同步；前端「處理中」畫面一併實作 | 辨識＋生成＋重試可能超過 nginx 預設 60 秒；部署重啟會中斷同步請求。沿用影片處理與 YouTube 上傳的啟動恢復模式 |
| 17 | AI 寫施工單**分兩步**：①選段（程式立刻用逐字時間算總長）②配圖卡與字幕；各自驗證、各自重試 | 任務單純較易寫對；錯哪步重試哪步 |
| 18 | 加**第三步整段檢查**：Gemini 只列出問題與類型、不直接改施工單，程式依類型退回第一或第二步修正；每次生成最多 5 次 Gemini 呼叫。問題分兩類：**可信度錯誤**（引用不存在、數字無出處、錨點對不上語音、總長超出、格式錯）必須修好否則生成失敗；**品質問題**（指涉畫面句、段落接不起來、圖卡與話不符、字幕走樣）盡量修，修不完照樣產出交教師判斷。片段頭尾的指涉畫面句由程式自動剪掉，中間的不自動剪 | 一處不完美就整支做不出來太嚴；直接讓 AI 改會繞過驗證 |
| 19 | 品質問題**不在預覽畫面上標記**；預覽旁放預設收起的「AI 檢查建議（N 項）」，**核准按鈕永遠可按**；建議一律存進資料庫，供試跑統計「AI 指出的問題教師是否認同」 | 教師認為不影響理解就可直接發布；但有些問題（如指涉畫面句）教師在動畫預覽中不易察覺，系統仍應提示 |

## 待討論（實作前需定案）

1. **AI 的輸入與輸出**：三步（選段、配圖卡、整段檢查）各自的指示內容、元件與素材說明、提供哪些範例、失敗時回饋的格式。
2. **素材庫**：第一批要有哪些物件、誰核准、存放位置與授權紀錄。
3. **worker**：身分憑證與權限範圍、工作佇列、逾時與重派、與管理員開關的介面。
4. **同意條款**的文字內容與教師撤回同意後的處理。
5. **瀏覽器預覽**與最終渲染的差異（字型、時間）如何控制。
6. **全版動畫的視覺主題**：沿用深梅紫，或改淺色。
7. **試跑計畫與成功指標**：主題數量（暫定 5～10 個）、合法率、對齊成功率、教師採用率。
