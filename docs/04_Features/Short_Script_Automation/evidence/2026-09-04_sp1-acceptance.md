## 3. 核准前補完的兩項落差

### 3.1 R-03 措辭與實作不一致（已修）

**問題**：R-03 原寫 `questions` 對本功能唯讀，且「該寫入由 QA 既有的 `recordQuestion` 負責，**不由短影片功能寫入**」。但 DR-14 授權的 backfill 腳本屬於本功能，且確實寫入 `questionEmbedding`（OpenCV 課 130 筆、AI 課 130 筆）。

**性質**：文件措辭沒跟上實作，非實作違規——DR-14 已授權該欄位。

**修法**：R-03 改為明列兩條允許的寫入路徑（`recordQuestion` 與一次性 backfill），並限定僅 `questionEmbedding` 欄位，其餘欄位一律不得寫入，也不得新增或刪除文件。

### 3.2 與 V5 的證據比對尚未在對應主題執行（已補）

**問題**：規格書要求驗證「系統撈的證據是否包含人工採用的核心片段」，但系統選中的第 1 名主題是「openCV是甚麼?」（定義題），而 V5 的主題是「跟 YOLO 的差異」（比較題）——**主題不同，證據自然不同**，這樣的比對不成立。

**修法**：驗證腳本新增 `--rank=N` 參數，可對第 N 名候選跑證據而不必等該主題輪到。唯讀，不建立任何 `shortscripts` 紀錄。

## 6. SP-1 之後補完的項目

驗收通過後仍發現一項實作與規格書不一致，已於同日補完：

**DR-12 第 3 層的淘汰行為未實作**。規格書寫的是「依序評估、證據不足者淘汰後換下一名、第一個通過者即選中」，但原實作只取第一名，證據不足就直接回 `SHORT_SCRIPT_EVIDENCE_EMPTY`。已改為逐一評估並換下一名，被淘汰者記入 `selectionReason.rejectedForEvidence`；全部不足時才失敗。新增兩個測試守住此行為。

**第 4 層（弧線適用性判定）仍未實作**——需要 LLM，屬 WO-05 範圍。因此目前的「自動選題」只完成 DR-12 的第 1～3 層。

## 7. 遺留事項（不擋 SP-1，但須追蹤）

- 執行時為 `memory` 檢索模式，與正式環境的 `atlas` 未做對照。
- **提問者極少**：OpenCV 課 75 筆提問來自 **2 人**，AI入門課 164 筆來自 **3 人**。這是測試／示範資料，不是真實學生使用。分群、過濾、證據檢索的驗證不受影響，但「系統選得出學生真正最需要的主題」**尚未被證明**——排名沒有群眾基礎。
  - 已於同日改善：新增 DR-17，排序改為提問人數優先。改版後 AI入門課的第 1 名由「AI 道德問題」（1 人 9 次）換成「什麼是大語言模型」（2 人 5 次），與手寫腳本 V4 的選題一致。
  - 但根本限制仍在：**2～3 人的資料無法證明排序在真實規模下有效**，須待實際學生使用後複驗。
- 兩個驗證樣本都出自同一位教師的課程。
- 與手寫腳本 V4（大語言模型）的證據比對尚未執行；該主題在 AI入門課排名第 2，可用 `--rank=2` 補做。
- 批次 A 期間另有一次事故：merge 時未解決的衝突標記被提交並推上 `main`，導致 backend 一度無法啟動（commit `d344804`，修正於 `8b27eb3`）。原因是在 GitHub Desktop 進行 merge 時於命令列改檔並 `git add`，與其內部狀態不同步。**後續 merge 應在 GitHub Desktop 的介面內解決衝突**。
