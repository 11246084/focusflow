# 教授會議（功能凍結與班級使用者測試啟動）

- 會議日期: 2026-09-10
- 會議時間: Notion 未記載
- 會議類型: 教授會議（進度回報；教授離席後接續組內討論）
- 與會者: 邱偉豪、張庭語、鍾百陶、張家瑜、蒯思齊（教授）

## 討論內容

1. 系統功能進度匯報

- 背景：向教授匯報問答、腳本、短影音與部署的最新進度。
- 內容：
  - 問答與腳本：已整合常見問題聚類，系統依相似度合併不同問法的同質題目並產出對應腳本。RAG 改為寬鬆檢索再收斂、補回前後文片段、依時間排序，並強制綁定回答的引用出處；資料不足時主動提示，避免產生幻覺。14 題測試表現良好。
  - 短影音：審核流程初步完成。系統產出腳本後離線生成影音並上架，自動以不公開（私人）模式上傳 YouTube，教師審核通過後才轉為公開、開放學生觀看。
  - 影音生成算力：雲端 API 限制多（時間短、指令遵循度差），本地端生成 30 秒影音約需 6 小時，因此影像生成採離線（ComfyUI + MiniMax 等模型），尚未整合進線上即時自動化管線。
  - 部署：本地環境正常；學校 VM 因舊版環境設定、Port 443 與 SSL 憑證尚未通過，網頁存取仍跳出安全性警告。
- 結論傾向：短影音離線生成是算力與時間成本的取捨，需向評審清楚說明；VM 的憑證問題待處理。

2. 指導教授回饋

- 背景：專題接近期末，預計 10 月中旬繳交完整文件。
- 內容：
  - 功能收斂：核心功能已足夠，不再增加新功能，重心轉向除錯、流程跑通與穩定性。
  - 使用者實測：盡快開放班上同學測試，並在系統埋入計數器或統計分析（造訪人數、發問次數、點擊觀看數等）。評審很看重使用者回饋與真實數據，須納入書面報告與簡報。
  - 書面與簡報：計畫書與簡報要特別註明問題聚類與語意相似度合併，突顯不是單純字串比對；影音離線生成的原因也要向評審說明。
  - 競賽：先前投件雖未入選，但評分偏高（約 87 至 90 分），多數僅差臨門一腳。建議轉投智服競賽（教育 AI 組）與 FinTech、數位理財類競賽；後者可將現有架構包裝為具人溫度的虛擬理財顧問提案，純比 Idea，不需重新開發後端。
- 結論傾向：凍結功能、啟動班級測試、積極轉投其他競賽。

3. 教授離席後的組內討論

- 背景：教授離開後，組內討論測試帳號、回饋收集、展示備援與文件分工。
- 內容：
  - 測試帳號：為避免開放測試時學生隨意註冊造成混亂，由後端將全班名單（以學號或信箱作為預設帳密）批次匯入資料庫；並清理先前的開發測試資料（刪除命名混亂的測試課程與處理失敗的影音檔，保留基本展示課程）。
  - 回饋機制：製作 Google 表單，分類收集頁面、功能 Bug 與操作體驗回饋。
  - 展示備援：預錄一段完整的系統操作影片放在本機，避免期末 Demo 受網路或雲端主機異常影響。
  - 文件整合：在專案目錄下建立資料夾，以 Markdown 共同撰寫、圖檔一併納入版控，方便之後轉成 Word 統整。
  - 分工：系統完善與 VM 由鍾百陶、前端完善與簡報由張家瑜、專題文件由邱偉豪、FinTech 競賽文件由張庭語。
- 結論傾向：以上為組內分工，非教授核准的正式規格。

## 決議事項

1. 凍結新功能開發：本週起不再新增功能（教師端照片與錄音上傳介面暫不開發，影音流程維持手動搭配），專注於 Bug 修復、上雲部署與文件撰寫。
2. 啟動班級使用者測試：匯入全班預設帳號，並以表單與計數器收集回饋與使用數據（使用人次與問答次數）。
3. 本週優先完成智服競賽（教育 AI 組）報名與文件繳交，另將問答與影音架構包裝為理財問答助手，投 FinTech 相關創意競賽。
4. VM 憑證洽系辦技士處理；若憑證仍未通過，先以跳過警告的方式維持系統可訪問。
5. 分工：系統與 VM 鍾百陶、前端與簡報張家瑜、系統手冊邱偉豪、FinTech 文件張庭語。
