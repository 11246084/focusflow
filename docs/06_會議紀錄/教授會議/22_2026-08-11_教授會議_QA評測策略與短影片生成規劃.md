# 教授會議（QA 評測策略與短影片生成規劃）

- 會議日期: 2026-08-11

- 會議類型: 教授會議（進度回報）
- 與會者: 邱偉豪、張庭語、鍾百陶、張家瑜、蒯思齊（教授）

## 討論內容

1. QA 評測策略與簡報應用

- 背景：期末複評可能追問「如何證明系統回答正確」，團隊需要在展示前掌握 RAG 系統擅長與不擅長的題型。
- 內容：
  - 教授以圖書館聊天機器人為例，示範由 Agent 自動設計題目，再以 Claude 撰寫標準答案，讓系統完成問答後交由 AI 評分。
  - 評測結果可依分數與題型分析系統優缺點，例如確認數字題、跨段題或語意改寫題的表現。
  - 簡報劇本可優先展示系統表現穩定的題型；表現較弱的題型則需先改善，或避免在尚未改善前當成主要展示案例。
  - Notion 已建立「建立 10 個問答」待辦，由鍾百陶負責，作為第一批評測題目。
- 結論傾向：建立可重複執行的自動出題、標準答案與 AI 評分流程，用評測證據說明系統能力，並作為簡報與短影片劇本選題依據。

2. Two-Stage 教學短影片示範

- 背景：短影片除了吸引注意，也需證明內容來自課程教材，避免生成內容看似正確、實際卻脫離老師授課脈絡。
- 內容：
  - 教授展示比較 R-CNN 與 YOLO 的短影片，以雙階段「較準但較慢」及單階段「較快但準度稍低」說明 Two-Stage 與 One-Stage 的差異。
  - 示範影片引用上課 VOD 畫面，讓觀眾可看出回答根據課程內容，而非只由生成式 AI 自行補充。
  - 教授說明影片以 MiniMax 影片生成模型在本地設備執行，語音與嘴型對位也由 AI 生成。會議中提及約需 120 GB RAM，生成一分鐘影片約需 76 分鐘。
- 結論傾向：短影片需保留可辨識的課程來源證據；本地生成可作為雲端 API 成本或效果不理想時的備援方案。

3. Embedding 版本一致性與限制性推出

- 背景：Parent Embedding 原先使用 preview 模型，Query Embedding 已改用正式版 `gemini-embedding-2`，不同向量空間會使相似度比較失去可靠性。
- 內容：
  - 張庭語報告已將 Parent Embedding 統一切換至 `gemini-embedding-2`，並重新處理 47 筆 parent chunk。
  - 會議報告指出，更新未破壞 parent-child 結構，且「使用者提問 → Parent Search → Child Extension → AI 引用」流程及語意改寫問題均有通過測試。
  - 目前測試範圍仍只有 1 支影片、3 筆 parent 資料，不足以證明可全面啟用。
  - 推出方式可保留 Shutdown、部分開啟與全面開啟三種模式，以便控制風險及回退。
- 結論傾向：先採限制性推出並擴大資料與題型驗證；在證據充分前不全面開啟多層檢索。

4. LINE 聊天機器人回答異常

- 背景：同一問題在 LINE 與網頁版得到不同回答，LINE 回覆曾出現 MVP 或 Gemini 暫時不可使用等異常訊息。
- 內容：
  - 會議推測 LINE 端可能尚未同步最新程式或設定，但尚未完成根因確認。
  - Notion 已建立「修復 LINE 聊天機器人回答異常問題」待辦，由張庭語負責。
  - LINE 問題修復後，張庭語可再協助準備競賽文件。
- 結論傾向：先比對 LINE 與網頁版實際使用的程式、設定及回答路徑，確認根因後再修復，不能只以「未同步」作為既定結論。

5. 短影片生成流程、工具與腳本公式

- 背景：團隊需要把 QA 內容轉為有趣且可審核的短影片，同時控制生成成本與教材偏離風險。
- 內容：
  - 初步流程為「審題 → 取得 QA 答案 → 填入腳本 → 產生英文提示詞 → 生成圖片 → 合成語音 → 教師審核 → 發布」。
  - VEO 3 有不同速度與品質方案，但調整流程期間可能需要反覆生成，成本是否划算仍待實測。
  - 邱偉豪負責先嘗試 VEO API 影片生成並留下實作紀錄；若效果或成本不合適，可把劇本交由教授使用 MiniMax 本地設備產生 sample。
  - 張家瑜展示不含人臉的動態圖文方案，以程式渲染與語音文字處理製作；教授認為目前效果與較完整的生成式 AI 影片仍有差距。
  - 團隊需研究成功短影片的腳本公式，可參考「邦尼幫你 3C 科技」Shorts，整理開頭吸引力、敘事節奏、轉場與收尾方式。
  - 目前影片語氣偏向上課，後續劇本需用更有趣、更適合短影音的角度呈現；預計依 QA 內容設計約 10 支劇本，交由教授在本地設備跑 sample。
- 結論傾向：先以小量劇本與 VEO API 驗證效果及成本，保留 MiniMax 本地生成備援；所有成品在發布前都需經教師審核。
