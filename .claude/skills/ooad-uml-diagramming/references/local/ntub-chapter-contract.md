# NTUB 章節 → 圖表契約

> **本層可整層移除**（換學校／換場景）。
> 依據：國立臺北商業大學資訊管理系《115 年系統手冊規範》—「**2. 大學部－系統手冊大綱（物件導向）**」。
> **不採用**「1. 專科部－系統手冊大綱（結構化技術）」的任何內容。

## 使用方式

`[NTUB:MUST]` 在系統手冊脈絡中製圖時，**先查本表**，再回到 SKILL.md 的自由決策樹。

三種欄位語意：

| 欄位 | 來源 | 強制程度 |
|---|---|---|
| **指定** | 官方明文要求 | `[NTUB:MUST]` |
| **建議／延伸** | 官方以「甚至」「最好」等非強制語氣標示 | `[NTUB:SHOULD]` —— **不得升為 MUST** |
| **本地補充** | 官方未要求，來自 `[OOAD]` 或 `[FF]` | 依原標記，缺少不構成缺陷 |

`[NTUB:MUST]` **官方「指定」的圖不得被 heuristic 判定為「不用畫」。** heuristic 僅能影響
拆圖粒度與合併策略，不能否決圖的存在。

## 章節結構

正式章數 **14 章 + 未編號的「附錄」**。

初評以第 1～8 章為主、頁數不限；複評所有章節、50 頁以上。

`[NTUB:MUST]` 四技部一律採「第6章 設計模型」「第7章 實作模型」。
**禁止**出現「程序模型」「資料模型」——那是專科部結構化用語。

## 關鍵條文的精確語意

`[NTUB:MUST]` 下列三處的連接詞決定強制程度，不可誤讀：

| 章節 | 官方原文 | 語意 | 正確處理 |
|---|---|---|---|
| 3-1 | 系統架構：**最好**以圖示方式說明 | **建議** | `[NTUB:SHOULD]`。圖示是建議做法，**不是必要**；以文字或表格說明架構亦符合規範 |
| 6-1 | 循序圖(Sequential diagram)**或**通訊圖(Communication diagram) | **替代** | 擇一即可；兩者都畫同一流程屬反模式 D6 |
| 5-4 | 分析類別圖⋯⋯**甚至**分析物件圖 | **延伸** | 類別圖必要；物件圖選配 |
| 6-2 | 設計類別圖⋯⋯**甚至**設計物件圖 | **延伸** | 類別圖必要；物件圖選配 |
| 7-4 | 狀態機(State machine)，**甚至**時序圖(Timing diagram) | **延伸** | 狀態機**必要**；時序圖選配。不可只畫時序圖 |

## 5-3 的特別規則

`[NTUB:MUST]` 官方原文：「5-3　使用個案描述：**使用活動圖(Activity diagram)描述之**。」

- 5-3 **必須**以活動圖描述使用個案
- **使用個案描述表是補充，不是替代**。只有表格而無活動圖，不符規範
- `[DOC:HEURISTIC]` 「線性無分支流程不值得畫活動圖」**在 5-3 不適用**
- 官方未規定每個使用個案是否各需一張。合規基線為**一 UC 一圖**；同構流程可用一張泛型
  活動圖 + 差異對照表，但**須在文中說明**

## 跨章追溯

```
5-1 FR/NFR ──→ 5-2 UC ──→ 5-3 活動圖（realizes: UC-xx）──→ 5-4 分析類別
                              │
                              └──→ 6-1 循序圖（realizes: UC-xx）
                                        │
6-2 設計類別 ←────────────────────────────┘
     ├──→ 7-4 狀態機（標對應設計類別）
     ├──→ 8-2 集合 Meta data（標對應持久化類別）
     └──→ 9-1 元件清單 ──→ 10 測試案例（標 FR/UC-ID）

內部技術流程：5-1 FR ──→ 6-1 循序圖 / 5-3 以外的活動圖 / 7-4 狀態機 ──→ 9-1 ──→ 10
              （不進 5-2 使用個案圖；系統本身不得為 Actor）

12 章每個操作小節 ──→ 回標 UC-ID（閉環驗證）
```

## 重疊風險與分工

`[DOC:SHOULD]` 下列章節組合最容易寫重複，須明確分工並互指圖號：

| 組合 | 分工 |
|---|---|
| 3-1 系統架構圖 / 7-1 佈署圖 / 7-3 元件圖 | 3-1 = 分層概念（給人看）；7-3 = 元件與介面（給設計看）；7-1 = 節點與 artifact（給維運看） |
| 5-3 使用個案描述 / 12 使用手冊 | 5-3 = 前置條件、例外流程、完成條件（規格）；12 = 截圖、按鈕位置、失敗處置（操作） |
| 6-1 循序圖 / 9 程式 | 6-1 = 訊息順序；9 = 檔案職責。互指，不重述 |
| 6-2 設計類別圖 / 8-2 Meta data | 6-2 = 物件責任與關聯（不列完整欄位）；8-2 = 完整儲存契約 |
| 7-2 套件圖 / 9-1 元件清單 | 7-2 = 依賴方向；9-1 = 檔案職責 |
| 5-1 需求追溯表 / 10-1 測試追溯矩陣 | 同一套編號的不同投影，不得各自編號 |

## 官方未要求的模型

`[OOAD:MAY]` 官方**完全沒有**要求下列模型，**不得因缺少而退圖**：

領域模型、邊界／控制／實體、強健性圖、CRC 卡、使用個案實現、系統循序圖、詞彙表、
互動概觀圖、複合結構圖、輪廓圖。

例外：若專案在 **3-3** 宣告採用 UP／RUP／ICONIX 等方法，B/C/E 與強健性圖從 `MAY`
升為 `SHOULD` —— 由專案宣告，不由本 skill 強制。
