## 工作項目

### D1 後端 API（決策第 18～21 項）

四支唯讀 API，都放在 `/stats/teacher` 底下，都接受期間參數（7 天、30 天、全部，預設 7 天）：

1. **課程概況與待辦**：這位教師每門課的選課人數、期間內有活動的人數、提問數、前一段同樣長度期間的提問數、答不出來的題數；以及待辦（處理失敗的影片清單、處理中的影片數）。
2. **單一課程的洞察**：每日提問數；問題主題（代表問題、幾個人問、幾題、其中幾題答不出來）；答不出來的題目（原文、時間、提問的學生姓名與代碼）；最常被問的影片段落（影片、起訖秒數、次數）。
3. **單一課程的學生名單**：每位仍在選課中的學生的姓名、提問數、答不出來的題數、看完的影片數與課程影片總數、最近活動時間、是否需要關心與原因。
4. **單一學生的明細**：姓名、選課時間、最近活動時間、看完的影片清單、他在這門課的提問清單（原文、時間、狀態、引用的影片段落）。

要點：

- **授權**：教師只能查 `teacherId` 是自己的課程；管理員可以查全部；其他角色回 403。課程不存在或不屬於這位教師時，回應不要洩漏課程是否存在。查個別學生時，還要確認這位學生目前在這門課的選課狀態是有效的。
- **學生的範圍**：只算選課狀態為有效的學生。教師與管理員自己的提問不算進學生的數字。
- **欄位**：學生只回姓名與代碼，不回 Email、LINE 相關欄位。
- **「需要關心」**依決策第 18 項，14 天與 2 題寫成具名常數。
- **「答不出來」**是問答紀錄狀態為 `no_match` 的題目；狀態為 `failed` 的是系統錯誤，不算進去。
- **問題主題**沿用 `shortScriptTopic.service.js`，需要時替它加期間條件；不改它給短影片選題用的既有行為，既有測試要全數通過。
- **期間為「全部」時**沒有前一段期間可比，比較值回空值，前端不顯示比較。
- **時區**：每日提問數以台北時間分日。
- 現有的 `GET /stats/teacher` 與 `getTeacherDashboardStats` 不要改。

測試至少涵蓋：上面「必守規則」列的授權情況；三種期間；沒有提問、沒有學生的課程回空的結構而不是錯誤；「需要關心」兩個條件各自成立與都不成立；已退選的學生不出現；教師自己的提問不計入。

### D2 教師儀表板頁面（決策第 16、22、24 項）

- 整頁改寫 `TeacherDashboard.jsx`，結構依決策第 16 項的六個區塊。
- 待辦列全部為 0 時不出現。等你處理的短影片數量，沿用短影片頁既有的分類方式（`services/recutFlow.js` 的 `describeScript`），不要另寫一套判斷。
- 只有一門課時不顯示課程切換。切換課程或期間時，只重新讀取受影響的區塊。
- 每日提問數用 SVG 自己畫小型長條，要有螢幕閱讀器讀得到的文字替代。
- 和前一段期間的比較用文字與符號表示增減，不能只靠顏色。
- 每個區塊都要處理載入中、沒有資料、讀取失敗三種狀態。沒有資料時說明原因，例如「這段期間沒有學生提問」。
- 問題主題與答不出來的題目，點開後看到原文、提問的學生與時間；點學生姓名進入 D3。
- 最常被問的影片段落可以跳到課程管理的該支影片。
- 拿掉課程數量、影片數量、AI 片段三張數字卡。
- 手機寬度要能完整操作，沒有橫向捲動。

驗收：以模擬資料在 1440 與 390 寬度檢查六個區塊與三種狀態；沒有待辦時待辦列不出現；切換課程與期間後數字跟著變。

### D3 個別學生頁（決策第 17 項）

- 從學生名單點進來，顯示決策第 17 項列的內容。可以做成同一頁內的面板或獨立的畫面，由實作決定，但要能用瀏覽器的上一頁回到名單。
- 提問清單依時間由新到舊，答不出來的題目要一眼看得出來。
- 不顯示 Email、LINE 帳號。

驗收：以模擬資料檢查有提問、沒有提問、沒有看完任何影片三種情況；鍵盤可以從名單進入並返回。

### D4 學生端告知（決策第 23 項）

- 在學生提問欄下方、顯示每日次數的那一行加上「授課教師看得到你在這門課的提問」。
- 只加這一行，不另外跳出視窗，不改對話欄的其他行為。
- 手機寬度下兩段文字不能互相擠壓到看不清楚。

驗收：桌面與手機寬度都看得到這一行；對話欄既有的測試全數通過。
