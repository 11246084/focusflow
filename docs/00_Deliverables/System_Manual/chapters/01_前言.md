## 1-1 背景介紹

數位學習、遠距教學、混成課程、翻轉教學與大規模開放式線上課程（MOOCs）已是高等教育和自主學習的常見形式。教師把課程錄成影片放到線上平台或雲端，學生依自己的時間在課前預習、課後複習或考前回顧。課程影片因此不再只是輔助教材，而是學生自學時最常回頭查看的資料來源。

影片變多、變長之後，查找成本也跟著上升。一堂課的錄影常有 40 至 90 分鐘，學生常碰到「知道自己要找哪個觀念，卻不知道它在哪一支影片的哪一段」。學校課程錄影多半只有播放時間軸、章節標題與手動拖曳可用，學生只能憑印象來回搜尋；搜尋成本一高，就可能放棄回頭核對，改用片段記憶或其他來源自行拼湊。

生成式 AI 讓學生可以隨時用自然語言提問，但一般 AI 聊天工具的回答不以該門課的教材為依據，也不會告訴學生教師在哪裡講過這個觀念。學生拿到的是一段看似合理的文字，卻無法確認它與課堂說法是否一致。

FocusFlow 針對的正是這個缺口：把教師已經錄好的課程影片，轉換成可以用問題搜尋、並能回到原始時間點核對的學習資源。系統把影片語音轉成帶時間資訊的逐字稿，切分並建立向量索引；學生在網頁或 LINE 上提問後，系統在其修課範圍內找出相關片段，回傳回答、來源片段與影片時間點。FocusFlow 不取代教師，也不取代既有的學習管理平台；教材、課程與修課名單仍由教師掌握，系統提供的是影片處理、語意檢索、問答與學習管理的輔助能力。

## 1-2 動機

影片式教材與線上學習平台仍在成長。依 IMARC Group（2026）的預估，台灣線上教育市場規模將由 2025 年的 7.774 億美元成長至 2034 年的 51.079 億美元，2026 至 2034 年的年複合成長率為 22.57%（圖1-2-1）。

### 教學現場的問題

市場規模只說明影片教材愈來愈多；本專題真正要處理的，是學生與教師在使用這些影片時遇到的具體困難：

1. **片段難以定位。** 長影片中的特定觀念不易找到，學生常須重看整段或反覆拖曳時間軸。
2. **疑問無法即時解決。** 在翻轉教學與線上自學情境中，學生遇到不懂的地方時，未必能立即得到與該門課教材相符的說明，學習因此中斷。
3. **教師與助教重複答疑。** 「這個概念在哪一段影片有講」「這個步驟怎麼做」這類基礎問題反覆出現，占用教師原本可用於進階說明與個別輔導的時間。
4. **AI 回答缺乏依據。** 一般生成式 AI 的回答不一定來自教師實際教材；沒有來源與時間點，學生無法核對答案是否正確。
5. **提問入口受限。** 行動裝置是學生最常用的學習入口，提問管道若只限於網頁，使用門檻仍然偏高。

若系統能先幫學生完成「找到對應影片片段」與「取得有依據的初步說明」，學生卡關的時間可以縮短，教師與助教也能減少重複回答相同問題。基於上述需求，本專題開發以課程影片為核心的 AI 學習輔助系統，取名為「FocusFlow」。

## 1-3 系統目的與目標

FocusFlow 的目的，是把長篇教學影片轉換成**可依課程權限搜尋、提問與回溯**的學習資源，讓學生能從問題直接找到教師講解的片段，並回到原始影片確認前後脈絡。

為達成此目的，本系統訂定下列目標。表1-3-1 列出每項目標在目前實作中的作法，以及仍須另行驗收的範圍。

表1-3-1　系統目標、實際作法與目前範圍

| 目標 | 在 FocusFlow 中的作法 | 目前範圍 |
| --- | --- | --- |
| 建立可檢索的影片知識 | 教師上傳本機影片後，後端自動觸發 AI Pipeline：以 FFmpeg 擷取音訊、Faster-Whisper 產生逐字稿，再經正規化、分段與 Gemini embedding 寫入 MongoDB | 單支處理與失敗重試已可運作；多影片 Pipeline 批次模式由功能開關控制，預設關閉 |
| 依課程內容回答 | 網頁與 LINE 共用同一套問答服務：在學生可存取的課程範圍內做語意檢索，將相關片段交給回答模型生成答案；教材中找不到依據時明確回覆無法回答，而非自行編造 | 已實作；回答品質受逐字稿、檢索與模型設定影響，內部評測結果見第 10 章 |
| 回到原始影片脈絡 | 回答附上來源影片、片段摘要與起訖時間；網頁引用卡可直接跳到影片對應時間點 | 已實作；來源影片沒有可播放的 YouTube 連結時，LINE 僅提示回網站查看 |
| 落實角色與課程授權 | 使用者分為學生、教師與管理員；學生只能存取「有有效修課紀錄且已發布」的課程，修課名單由教師或管理員指派 | 應用程式 API 已依此限制；本機影片檔的 `/uploads` 路徑仍可經 ngrok 通道匿名讀取，影片檔本身尚未受修課權限保護（見第 3 章） |
| 降低影片儲存與播放負擔 | 啟用 YouTube 自動上傳時，影片以「不公開（unlisted）」上傳至專題頻道並以 iframe 嵌入播放；刪除影片或課程時自動轉為私人 | 正式環境已啟用（2026-09-19 查證）；「不公開」代表持有連結者即可觀看，不等於僅限修課學生 |
| 支援教師管理課程與影片 | 教師可建立課程、上傳單支或多支影片、查看處理狀態、重試失敗項目，並管理課程與影片的掛載關係 | 已實作；以 YouTube 網址新增影片的 API 仍保留，但不在教師上傳頁提供 |
| 提供多管道學習 | 網頁提供課程觀看、對話式問答、學習進度、通知與個人資料；LINE Bot 提供帳號綁定、課程切換與問答 | 已實作；LINE Webhook 目前經 ngrok 通道連入，正式對外路徑待定 |
| 控制使用成本與品質 | 相同或高度相似的問題由 FAQ 快取直接回覆；限制單題長度與每位學生每日提問次數 | 已實作；變更模型或提示詞後，舊快取需手動清除 |
| 提供管理與營運資訊 | 角色儀表板呈現課程、進度與問答統計；管理員可管理帳號、影片、事件與全站通知 | 統計反映系統已記錄的資料，不代表已證明學習成效 |

### 與現有線上學習平台的比較

表1-3-2 顯示，「用 AI 回答課程內容、並指回影片段落」已經不是 FocusFlow 獨有的構想。PressPlay 的 AI 助教同樣以課程逐字稿為依據，並能提供對應的影片段落。因此 FocusFlow 的差異不在「有 AI 問答」，而在於服務的情境與範圍不同：

1. **服務的是學校課堂，而不是上架販售的課程。** 商業平台的 AI 助教只涵蓋平台上架、學生付費取得的課程；FocusFlow 讓授課教師直接上傳自己的課堂錄影，系統自動完成語音轉文字與索引，不需要把課程包裝成商品。
2. **問答範圍依修課名單限定。** 商業平台依購買或訂閱權限決定範圍；FocusFlow 由教師或管理員指派修課學生，學生只能查詢自己修習且已發布的課程。
3. **以學生常用的通訊軟體作為提問入口。** 上述平台的 AI 助教以網頁為主，PressPlay 目前僅支援網頁版；FocusFlow 另提供 LINE Bot，學生綁定帳號後可直接在 LINE 上提問。
4. **每個回答都附上可跳轉的影片時間點。** 學生可以從回答直接回到教師講解的原始片段核對內容；教材中找不到依據時，系統明確回覆無法回答。

這些差異只說明設計定位，不代表 FocusFlow 的回答品質或使用體驗已優於上述平台；兩者之間並未做過實際的對照測試。

## 1-4 預期成果

本專題的預期成果分為兩部分：已有程式實作依據的成果，以及仍須透過試用與正式環境驗收才能確認的成果。

### 已完成實作的成果

- **角色與帳號**：學生、教師、管理員三種角色登入；學生與教師可自助註冊，管理員由獨立入口登入；提供忘記密碼、個人資料、私有頭像與連續登入失敗鎖定。
- **課程與修課**：教師建立與管理自己的課程，由教師或管理員指派修課學生；後端 API 統一以「有效修課 ∩ 已發布」判斷學生可存取的課程。
- **影片處理**：教師上傳本機影片（單支或多支）後自動進行語音轉文字、分段與向量化，並可查看處理狀態、重試失敗項目；正式環境會自動上傳至 YouTube，以不公開方式嵌入播放。
- **課程問答**：網頁與 LINE Bot 皆可提問；回答附來源片段與影片時間點，找不到依據時明確拒答；具 FAQ 快取與提問次數限制。
- **學習與管理介面**：角色儀表板、學習進度、站內通知、網頁對話紀錄，以及管理員的帳號、影片、事件與公告管理。
- **短影音複習**：學生可在修課範圍內瀏覽已發布的短影音；教師端提供候選片段、附證據的腳本、人工成品上傳與審核流程（腳本自動化由功能開關控制，預設關閉）。
- **對外存取**：系統部署於學校虛擬機，自 2026-09-10 起可經 `https://focusflow.ntub.edu.tw` 以受信任憑證從校外連線。

### 仍待驗證的成果

- **學習成效**：尚未進行正式學生試用，縮短查找時間、提升複習效率與減輕教師答疑負擔等效益，仍需以試用資料量化。
- **回答品質**：內部評測以固定 50 題題庫評分，第二輪（2026-09-03）加權分數由基準線 4.35 提升至 4.68／5、致命錯誤為 0；但此結果只適用該題庫與執行設定，尚未設定正式通過門檻，也不代表所有課程（詳見第 10 章）。
- **正式營運條件**：LINE Webhook 仍經 ngrok 通道、該通道使 `/uploads` 影片檔可被匿名讀取；Gemini、LINE、YouTube 與語音轉文字在目標環境的長期穩定性、成本與容量尚未驗證。
- **延伸功能**：多影片 Pipeline 批次模式的正式負載驗收，以及短影音的自動剪輯、字幕與 9:16 版型渲染，目前尚未完成。

綜合而言，本專題目前可以主張的是：已建立一套以課程權限為邊界、能把學生問題連回原始影片片段的系統，並部署於可從校外存取的環境。系統尚未正式上線，也尚未完成學生試用驗收；FocusFlow 是否真能提升學習成效，將以後續試用資料為準，而不以本機測試或程式完成度推論。
