# 工作說明：recut RC6（程式碼圖卡）

分支 `wip/recut-rc6-code-card`，從 `feat/recut` 切出（RC4 已合併）。先讀 `AGENTS.md` 與 [HANDOFF.md](../HANDOFF.md) 的「必守規則」。

原本的兩個開工前問題已由決策第 91 項定案：程式碼圖卡的 Gemini 呼叫另外計算、每張最多 2 次；不先抽查 OpenCV 錄影畫面，看不清楚時由驗證器擋下程式碼圖卡、改用其他圖卡。

## 先讀

1. [recut 設計決策](../recut-design-decisions.md)第 34、42、43、64、91 項。
2. RC4、RC5 回報的圖卡目錄與施工單格式。

## 要做

1. **新增第 13 種圖卡 `code`**（第 42 項）：編輯器視窗、語法上色（例：Shiki，MIT，固定版本）、行號、行高亮、在指定行與字上疊方框、編譯錯誤訊息框；一行最多約 36 字、一張最多約 12 行，超過由驗證器擋下；可搭配「層層包含」圖卡。
2. **程式碼來源只用上課畫面**（第 42、43 項）：擷取該時段的畫面，由 Gemini 抄下程式碼，再依逐字稿與相鄰畫面審核修正；畫面沒秀出完整程式時可依老師語境補寫；老師說明故意寫錯的地方保留原樣。程式檢查老師講到的變數名稱必須出現在程式碼中。
3. **逐行來源標示**（第 43 項）：每行標「畫面原樣／AI 修正／AI 補寫」，可對照畫面原文；**只在預覽模式出現**，渲染模式網頁不輸出，用自動測試確認。
4. **額度**（第 91 項）：每張程式碼圖卡最多 2 次 Gemini 呼叫，不佔初次生成的 5 次額度，依第 64 項記錄；畫面看不清楚或抄寫結果通不過驗證時，不使用程式碼圖卡，不讓整支片失敗。

## 測試

假的畫面擷取與 Gemini 回應。至少涵蓋：每張最多 2 次呼叫且不扣初次生成額度；畫面不清楚時改用其他圖卡；行數與字數上限；變數名稱不在程式碼中被擋；故意寫錯的行保留；來源標示只在預覽模式；渲染模式網頁不含標示。

## 完成時回報

commit 清單、測試結果、和本工單不同之處，以及給 RC9 的介面（預覽中修改程式碼與顯示來源標示需要的資料）。
