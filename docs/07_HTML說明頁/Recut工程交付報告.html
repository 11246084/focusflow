教師操作路徑

選一個步驟查看操作、介面與後端狀態。工作成功後必須重讀後端資料；以下文字不是實際教師畫面。

模擬：什麼時候可發布？

勾選假設條件，觀察後端應如何判斷。核准必須綁定目前 recutVersionId / assetId / generationVersion；新成品不能沿用舊核准。此模擬不是實際發布，也不代表外部服務成功。

前端要呈現的差別

核准先到：顯示「已核准，等待發布」。ready 先到：顯示「等待教師審片」。兩者俱足仍應讀回後端發布結果，學生 feed 也由後端重新判斷。

撤回後晚到的遠端 ID 需要持久補償；轉私人失敗會產生管理員待辦，不能顯示全部下架完成。

前端串接順序

以下路徑均以 /api/v1 開頭。完整欄位、權限及錯誤碼以 OpenAPI 與前端串接交接為準。

畫面操作與 API回應與呈現
同意／上傳GET 條款及課程同意；POST courses/:courseId/recut-consent（kind、choice、termsVersion、requestId），再 POST 課程 videos。同意成功後才上傳；缺有效內容同意回 409。保留表單及仍在記憶體中的 File。
選題／生成GET 課程 short-scripts/candidates；POST short-scripts/auto；記錄 voice，PATCH production-mode，再 POST recut/generate。202 的 data.id 是 taskId；查 tasks 與 recut state。取消只表示提出要求，查到終態才算完成。
完整稿／建議GET recut/review；PATCH selection；POST selection/apply、restore 或 suggestions/apply。使用後端 versionId、expectedRevision。區分未套用草稿與現行稿。202 查任務，成功再讀新版；409 保留未送文字並比對新版。
講稿與成品POST approve-script，再 POST render；GET shorts/:shortAssetId 看成品，POST approve-asset 或 reject-asset。核准成品帶 versionId、expectedRevision、assetId、generationVersion；退回帶 scope 與 reasons。新的 MP4 必須重審。
發布／學生教師 GET 課程 short-assets；需要時 POST short-assets/:assetId/upload/retry；學生 GET youtube/shorts。核准與遠端 ready 可任一順序；讀回狀態，不能以核准 200 推定學生可見。
撤回／管理GET withdrawal-assets，再 POST withdrawals；pending 可 POST 同一 withdrawal 的 retry。管理員 GET admin/recut-consent/manual-actions。預設不勾選；選取與全選互斥。pending 或 manualActionRequired 顯示待辦，未選的已發布歷史成品保留。
共通 loading、失敗與取消處理

進行中停用重複操作並保留未送資料；200／201 後讀回狀態，202 保留 taskId 並輪詢。400／422 顯示可修正原因；401／403 處理登入與權限；404 也可能是功能開關；409 依 error.code 顯示版本、同意或來源衝突；503 或網路中斷先查狀態，再決定是否重試。關閉頁面不等於取消背景工作。

管理員、worker 與通知

管理員用 GET/POST /admin/recut-workers 與 PATCH 個別 worker；金鑰建立時只回一次。worker 使用專用 Bearer 與 claim，後續 heartbeat、source、failure、result 使用 X-Recut-Lease；result 為 video 與 metadata multipart。教師 JWT 不可代替 worker 身分。生成任務成功／失敗通知教師並以 taskId 去重；通知失敗不回滾，取消為獨立終態。詳見審閱與 worker 契約。

前端驗收清單
  • 內容同意先於上傳；版本過期、拒絕與改選保留輸入。
  • 離頁後可重讀任務；過期 revision 不自動覆蓋新版。
  • 呈現退回與內容退回分支正確；新 MP4 重新觀看核准。
  • 兩種 ready／核准順序、失敗重試、撤回晚到 ID 與管理員待辦均有明確畫面。
  • 分別用教師、其他教師、學生與管理員驗權限；真實媒體、外部服務及真人驗收各自留證據。

資料與背景工作接點

這些是工程契約導覽；前端不直接寫資料庫。完整欄位及設計取捨見 RC1 資料、狀態機與背景工作。

集合與重要欄位

shortscripts.recut 保存 state、revision、目前 version／asset 與任務；recutsources 保存原片視窗、sentences 與 sourceCheck；recutversions 保存 selection、fullScript、plan；recuttasks 保存工作狀態與額度；recutattempts 保存步驟輸入輸出及用量；recutapprovals 保存核准及成品識別；recutreviewevents 保存修改、建議與計時；shortassets 以 recutVersionId、sourceScriptId、generationVersion 關聯成品。這是程式定義，未建立或查證共用 Atlas。

句子與狀態轉移

句子使用 id/startSec/endSec/text/words/retrievalHit/chunkIds，時間是原片絕對秒數。兩句格式 fixture 不是正式選段範例。狀態從 idle、queued、generating、script_review、script_approved、render_queued、rendering、asset_review 到 published；render_failed 可重排，取消或失敗恢復快照。轉移入口 transitionRecut；狀態與階段常數在 recut.js。

步驟註冊與執行介面

registerRecutSteps 註冊 generate 的 sourceCheck、selection、cards、wholeCheck；registerRecutReviewSteps 註冊修改任務 prepare、cards、wholeCheck。步驟 run({ task, data, runAttempt, checkCancelled }) 依各步需求使用參數，回傳值供後續 data 使用；模型呼叫經 runAttempt 記錄與保留額度。未註冊回 503，不以假工作冒充成功。實際 runtime 與 adapter 以 RC1 文件和RC4 介面為準。
