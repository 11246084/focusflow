# FocusFlow 短影音・重點文件

**這份是給人快速看懂全貌的摘要，不是執行規格。** 要動手做請看 [docs/short-video-examples/](short-video-examples/)。

- 版本：**v2（2026-08-14）**
- 狀態：**規格完成，零支實作**。以下所有數字與判斷都未經實拍驗證。

---

## 1. 一句話

用資料庫既有的問答內容，**在 30 秒內講清楚一個觀念**。

Shorts 是**獨立的學習單元**——學生在這裡看完就學到了，不做導流、不把他帶回原片。**成功指標是完播率與重播率**，不是播放數。

## 3. 素材：全部實查自資料庫

2026-08-14 連共用 Atlas `focusflow` 查證，**十支用的是同一個真實知識**：

```
課程：影像處理導論（69f82564736febac6db8e97b）
影片：aiA10_1140123_2（6a67ffd295668cc2b904f3c4），全長 1800.1s
學生原問句：「說明token是什麼?」（2026-07-28 實際提出）
溯源記錄：原片 00:56（不做導流，不出現在畫面上）
```

| chunkId | 時間 | 要點 |
|---------|------|------|
| `…chunk_0004` | 37.34–54.68s | token 是 NLP 裡一個特別的詞 |
| `…chunk_0005` | 56.18–68.04s | token = 把原本的句子拆成碎片化之後的東西 |
| `…chunk_0006` | 68.14–90.8s | 每一個碎片都是 token，**包含最後的句點** |
| `…chunk_0007` | 90.9–110.17s | ChatGPT 與其他語言模型的計費方式都跟 token 有關 |

**十支只能從這四點裡挑、刪、重排。** 指不回 chunkId 的句子標為 `ai_added`，發布前教師必須逐句勾選。

十支用同一個知識是刻意的——這樣可以直接 A/B 哪一種呈現方式有效，而不是在比題目好不好。

## 4. 核心架構：生成 + 驗證

**規格 v1 用「禁止」處理風險**：畫面不准帶資訊、字卡一律程式化、原生音軌一律剝除、不得生成人物。

那是把兩件事混在一起了——**「由誰產出」與「內容能不能追回資料庫」是兩個獨立問題**。用限制產出方式去解決溯源問題，代價是砍掉大半表現力，也讓短影音失去教學能力（畫面不能帶資訊，等於畫面不能教東西）。

**v2 改成：全部都可以生成，但每一種產出各有一道自動驗證關卡。**

| Gate | 位置 | 檢查什麼 | 不過關 |
|------|------|----------|--------|
| **G1 溯源** | 生成之前 | 每一句都對得回 chunkId | 中止，不花錢 |
| **G2 字面** | 生圖後 **+ 生影片後各一次** | 畫面文字 OCR 回讀 **逐字等於** `expectedText` | 重出圖；5 次退回程式化渲染 |
| **G3 語音** | 合成之後 | ASR 回讀逐字比對腳本 | 重新合成語音 |

**「知識點必須來自資料庫」沒有放寬**，只是改由 G1 保證，與畫面是不是生成的無關。

**教師覆核保留。** G1–G3 擋機器層面的錯，擋不掉「有出處但被斷章取義」。

### 三種畫面 Profile

| Profile | 用在 | 驗證 |
|---------|------|------|
| **A** 帶指定文字 | 字卡、標籤、關鍵詞 | G2 必過 |
| **B** 氛圍／隱喻 | 背景空景、實體隱喻 | 人工看一眼 |
| **C** 虛擬講解員 | AI 人物出鏡 | G3 + 標示檢查 |

**同一鏡不可混 A 與 B**——會讓模型同時收到「要有字」與「不准有字」。

## 5. 三條不可放寬的原則

| 原則 | 為什麼 |
|------|--------|
| **知識點必須追得回資料庫** | 由 G1 保證。這是整套的立足點 |
| **未經書面同意，不得複製真實師生的臉或聲音** | 肖像權與聲音權，不是規格偏好 |
| **生成完立即下載存檔** | 伺服器只保留 2 天，只存 URL 等於沒存 |

其餘的（畫面能不能帶字、能不能有 AI 人物、語音能不能生成）**都已放寬**，改用驗證處理。

## 6. 吸引力規格

前三秒要**同時**做三件事：打斷滑動、給出承諾、留下好奇缺口。口說鉤子 10–14 字內講完。

### 三個鉤子公式

| 公式 | Token 版本 |
|------|-----------|
| 反常識 | 「一個 token，不一定是一個字。」 |
| 錯誤警告 | 「你在算 ChatGPT 要花多少錢，但單位可能算錯了。」 |
| 清單預告 | 「這句話丟進 ChatGPT，會被拆成幾個東西？」 |

**三種都寫在文件裡，但第一階段只用預設那句**——見 §11 的測試設計。

### 留存節奏

`0–3` 鉤子 → `3–6` 共鳴 → `10–15` 第一次 pattern interrupt → `15–18` open loop → `20–25` 第二次 interrupt → `25–30` **收束重述**。

**最後 5 秒是重述，不是導流。** 把最反直覺的那句（「連句點都算一個」）再講一次。30 秒的教學靠重複建立記憶點。

**pattern interrupt 用溫和型**（切鏡、字卡形態變化、局部放大），不用暴力 zoom 與誇張音效。

> **核心原則：注意力由解釋層（字卡、剪接）負責，不是氛圍層（背景）。**

## 7. 聲音、字型、調色

### 唸法標記

`**粗體**` 重音（全片 ≤ 6 個）、`／` 短停 0.3s、`／／` 長停 0.6s、`↗` 上揚留懸念、`↘` 下沉給結論、`〔慢〕〔快〕` 語速。

### 三個關鍵音量

| 項目 | 值 |
|------|-----|
| 旁白 | −16 LUFS（基準） |
| 配樂 | −28 ~ −32 LUFS，**無旋律**的 ambient pad |
| 成品整體 | **−14 LUFS**，真峰值 ≤ −1 dBTP |

**有旋律的音樂會跟旁白搶語言處理區**，學生會覺得聽起來累但說不出為什麼。

### 配樂與音效：一律自製

**「免費」和「不會被 Content ID 打」是兩件事。** Content ID 靠音訊指紋比對，不看授權文件——曲目被第三方註冊過，拿著合法授權一樣會被聲明。

而我們要的東西**自製比找現成的更容易**：

| 項目 | 規格 | 時間 |
|------|------|------|
| 配樂 | 40 秒可循環的 ambient pad，無旋律、起伏 ≤ 3dB | 一次做完，十支共用 |
| thud | 60Hz 正弦 + 0.3 秒衰減 | 2 分鐘 |
| 字卡輕點 | 短脈衝 + 極短 reverb | 2 分鐘 |
| 切鏡輕點 | 同上，再低 4dB | 1 分鐘 |

備案是 YouTube 官方音效庫或 CC0。**不可用 CC BY-NC**（學校頻道不必然算非商業）、**不可用 CC BY-SA**（ShareAlike 對衍生作品的要求有爭議）。

### 字型

**Noto Sans TC（思源黑體）**，SIL OFL 授權、商用免費、可嵌入。

字卡 Bold 96px／字幕 Medium 64px／小標 Regular 40px。**只用這一個家族、只用這三級。**

**不要用微軟正黑體**——系統字型，散布授權有限制。

### 調色

十支統一：5000K、低飽和、低對比，套同一組最終調整。

**這是測試的控制變因，不是美學潔癖**——十支調色不一，結果出來會分不出是手法有效還是那支剛好比較好看。

## 8. 分鏡腳本表格式

腳本與分鏡合在同一張表：**`鏡號｜秒數｜Beat｜畫面｜聲音`**

- 業界 two-column A/V 的變形，shot-list 細項（景別、焦段、運鏡、構圖、光影、字卡、Profile）收在畫面欄
- 聲音欄含旁白、語氣、字幕、配樂、音效、收音、**來源**
- **「來源」欄不可留空**：不是 chunkId 就是 `template` / `ai_added` / `corrected`

## 9. 製作流程

```
① 選題 → ② 取答案 → ③ 填腳本（登記 expectedText） → ④ G1 溯源 ★
→ ⑤ 出提示詞（選 profile A/B/C） → ⑥ 生圖 → ⑦ G2 字面 ★
→ ⑧ 生影片 → ⑧' G2 複驗 ★ → ⑨ 立即下載
→ ⑩ 合成 → ⑩' G3 語音 ★ → ⑪ 落庫 → ⑫ 教師覆核 ★
→ ⑬ unlisted 上傳，等 Content ID 掃完確認無聲明 → 改可見度
```

**第 ⑦ 關是經濟核心。** 一張圖 NT$1.5、一段 8 秒影片 NT$40——**在圖的階段重做二十次，仍比在影片階段重做一次便宜**。

**⑧' 複驗不可省**：圖生影片時模型常把首格的字改掉或糊掉。橫移鏡（04-S5）與推近鏡（09-S1）風險最高。

| # | 手法 | 教師出鏡 | Profile | G2 | G3 | 成本 |

| 01 | AI 氛圍空景 + 字卡 | ✕ | A×1、B×2 | ✓ | ✓ | NT$130 |

| 03 | 無縫循環 | ✕ | B×2 | — | ✓ | NT$90 |
| 04 | 學生提問 × 教師回答 | ✓ | A×1 + 實拍 | ✓ | ✓ | NT$40 |
| 05 | 手寫白板 | 只露手 | 無生成鏡 | — | ✓ | NT$0 |
| 06 | 原片剪輯 + 字幕強化 | ✓（原片） | 無生成鏡 | — | ✓ | NT$0 |
| 07 | 錯誤 vs 正確對照 | ✕ | A×2 | ✓ | ✓ | NT$90 |
| 08 | 實物演示一鏡到底 | 只露手 | 無生成鏡 | — | ✓ | NT$0 |
| 09 | 三個重點・字卡驅動 | ✕ | A×1、B×2 | ✓ | ✓ | NT$130 |
| 10 | 抽象隱喻 | ✕ | A×1、B×3 | ✓ | ✓ | NT$130 |

**05、08 完全不用 G2**（手寫與紙條的字是人決定的）；**02 連 G3 都不用**（真人現場收音）。這三支驗證負擔最低。

**07 最適合 profile A**——兩鏡都是靜態鏡，baked-in 的字最不容易跑掉。
**10 的 G2 失敗率預期最高**——暗場 + 中文。

### 一個一般性的取捨

**要動的字用程式化渲染，要跟畫面融為一體的字用生成。兩者不能兼得。**

baked-in 的字不會推入、不會縮小、不會累積、不會淡出。09 因此定案放棄開場字卡的縮放，換取「字長在畫面裡」。

## 13. 實查才發現的四個限制

| # | 發現 | 影響 |
|---|------|------|
| 1 | **逐字稿是簡體字且有 STT 錯誤**（「济费方式」「chat gbd」「像量」） | **06 規格已修訂**：字幕 level 從 `verbatim` 降為 `corrected`，需人工校正 |
| 2 | 片段**沒有 `courseId`，`segmentId` 是 `null`** | 溯源一律用 `chunkId` |
| 3 | **同一支影片在兩個課程各上傳一份**，`videos._id` 不同 | 必須指定用哪一份 |
| 4 | 課程名稱「影像處理導論」，內容卻是 NLP／ChatGPT | 對外發布前要跟老師確認課程歸屬 |

第 1 項的補救：用第二套 ASR 回讀原音、與人工校正稿比對，**只有不一致的段落需要人看**。這把 06 從「不能自動化」變成「半自動」。

## 14. 現在能不能做

**手工做一支：可以，不用寫任何程式。** 需要生圖、生影片、TTS、剪輯四種工具，腳本裡的 prompt 已展開成可直接複製的形式。

**自動產五十支：不行。** 沒有 pipeline，G1/G2/G3 三道關目前只有規格沒有實作，手工階段靠人眼人耳代替。

### 還缺四樣

| # | 缺什麼 | 誰能決定 | 狀態 |
|---|--------|----------|------|
| 1 | **模型選型**（生圖／生影片／TTS／OCR／ASR） | 你，決定預算後 | 候選見 §14.1 |
| 2 | **配樂與音效實體檔案** | 規格已定，還沒做 | 工具見 §14.2 |
| 3 | **斷詞切法**——05、08 畫面要數出「5 個 token」 | **要問老師**用哪套斷詞工具 | 卡住 |
| 4 | **06 的 ASR 引擎**（要與 pipeline 用的那套不同） | 你，確認 pipeline 現況後 | 候選見 §14.1 |

### 14.1 選型候選

> **2026-08-14 查證，但這一節最容易過期。** 生成模型汰換極快，價格與可用性請在實際採購前重查。規格本身不綁型號，換模型不用改腳本。

#### 生圖——**這是最關鍵的一項**

十支裡有五支要用 profile A（把中文字生進畫面），**選型的唯一硬指標是「中文字渲染準不準」**。這決定 G2 的重試率，也決定 profile A 到底可不可行。

| 候選 | 中文文字表現 | 備註 |
|------|-------------|------|
| **GPT Image 2** | 據稱 CJK 字元準確率約 99% | 目前公開資料裡對中文最強的一組 |
| **Nano Banana Pro** | 同屬第一梯隊 | 原規格 v1 就是選它 |
| **Seedream 5.0 Pro** | 多語排版強，中文原生 | 中國模型，資料落地與授權要另外確認 |
| FLUX.2 | 第三梯隊 | 開源路線，可自架 |

**建議**：先用同一段 prompt（`不一定是一個字`）在 GPT Image 2 與 Nano Banana Pro 各出 10 張，數有幾張逐字正確——**這個數字直接決定 profile A 要不要保留**。花不到 NT$50。

#### 生影片

| 候選 | 價格 | 備註 |
|------|------|------|
| **Kling 3.0** | 約 US$0.10/秒；標準檔約 US$0.84／10 秒 | 目前最便宜的可用選項 |
| **Veo 3.1 Fast** | US$0.15/秒 | 原規格用的，介面形狀已寫在文件裡 |
| Luma Dream Machine | 訂閱制 | 圖生影片的性價比選項 |
| Runway | 訂閱制（Standard 約 US$12–15/月） | 不是按秒計價，量少時反而划算 |

> **Sora 2 不在候選**：OpenAI 已於 2026 年 4 月終止消費者版 Sora。

**選型時要問的**：能不能保留來源圖的文字（`Preserve all text`）？做不到的話 §9 的 ⑧' 複驗會一直失敗。

#### TTS

需求：**台灣中文女聲、支援 SSML 的 `break` 與 `emphasis`**。主流雲端 TTS（Google／Azure／ElevenLabs）都符合，**挑選的關鍵是唸 `token`、`ChatGPT` 這兩個英文字時會不會變調**——這要實聽，規格書上看不出來。

#### OCR（G2 用）與 ASR（G3、06 用）

| 用途 | 候選 | 注意 |
|------|------|------|
| OCR | 任一支援繁中的 OCR API，或直接用多模態模型回讀 | **G2 的可靠度上限就是 OCR 的可靠度**，形近字與全形半形是已知盲點 |
| ASR | Whisper large-v3 或任一雲端 ASR | **06 必須用與 pipeline 不同的引擎**，同一套會犯一樣的錯，比對就沒有意義 |

### 14.2 配樂與音效：不用選型，用免費工具自己做

| 項目 | 工具 | 時間 |
|------|------|------|
| 配樂（40 秒 ambient pad） | 任一 DAW；免費的話 **Audacity** 或 **GarageBand**／**Cakewalk** | 一次做完，十支共用 |
| 三種音效 | **Audacity**（產生正弦波 + 套用衰減） | 合計約 5 分鐘 |

**這一項不需要決定任何事，只需要有人花半小時做。** 做完就少一個阻擋。

## 15. 尚未確認

**v2 架構帶來的新項目**：中文短字串的生成保真度、圖生影片會不會改動首格文字、OCR 對中文的正確率、G2/G3 帶來的實際重試率、虛擬講解員的跨支一致性、G3 的 ASR 中文正確率（相似度門檻 0.95 是拍的）。

**沿用**：`negativePrompt` 是否為所選模型的支援參數、生成內容用於教育場合的授權條款、`referenceImages` 鎖風格的實際效果、`token`／`ChatGPT` 的中文 TTS 唸法。

> **成本數字全部作廢重算。** 表上的 NT$ 只涵蓋舊流程，沒算 G2／G3 的重試與可能的數位人平台費用。實測前不要當預算依據。

**最重要的一項**：十種手法的**教學效果完全未經驗證**。哪一種真的讓學生在 30 秒內學會，只能靠完播率與重播率實測。

## 16. 建議的第一步

**不要從寫程式開始。** 先手工做三支：

| 支 | 為什麼挑它 |
|----|-----------|
| **08 實物演示** | 實拍演示、零生成成本、不用 G2 |
| **02 教師實拍** | 可信度最高、零成本、連 G3 都不用 |
| **01 AI 空景** | 自動化程度最高，代表可量產的那條路線 |

三種路線各一支，比完播率與重播率再決定要不要投資其餘七種。

這一步能實測出三件寫程式前必須知道的事：**G2 在中文字串上守不守得住**、**實際重試率是多少**、**成品能不能真的在 30 秒內教會一個觀念**。

> 在確認成品長相之前寫 pipeline，很可能做完才發現形式不對。

### 更前面的一步：花 NT$50 測中文字

在挑三支之前，先做一件更小的事——**用同一段 prompt 在兩個生圖模型各出 10 張，數有幾張的中文字逐字正確。**

這決定了：

- profile A 到底可不可行（五支受影響：01、04、07、09、10）
- G2 的重試上限 5 次夠不夠
- 生圖模型選哪一家

**成本不到 NT$50，一小時做得完，但它會改寫後面所有的成本估算。** 這是目前投資報酬率最高的一步。
