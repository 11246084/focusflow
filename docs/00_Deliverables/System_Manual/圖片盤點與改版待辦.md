# 圖片盤點與改版待辦

本文件記錄第一階段的圖片盤點與改名結果。本階段已依最終章節位置重新命名 56 個既有圖片檔，並同步更新正文引用；圖片內容與原始副檔名均未修改，也未新增或刪除圖片。第二階段應依下表確認保留、重繪或重新截圖，再為修改後的圖片加入版本號。

## 命名與版本規則

- 檔名格式：`圖{章}-{節}-{流水號}-{圖片名稱}.{原始副檔名}`；既有 `.png`、`.jpg` 與 `.emf` 均保留原始副檔名。
- 圖號依最終章節位置決定；同一節依正文出現順序編流水號。
- 僅改成正式檔名、內容未變時可不加版本號。
- 圖片內容經小幅修改後使用 `-vX-x`，例如 `-v1-1`；重大重製後遞增主版本，例如 `-v2-0`。
- 重新命名不得只改副檔名；本輪保留 53 個 PNG、2 個 JPG 與 1 個 EMF 的實際格式。
- 舊圖在完成替換前一律視為「初評歷史圖」，不能作為目前系統已驗收的證據。

## 盤點結論

- `images/` 目前共有 56 個檔案，均已採繁體中文圖號式名稱；重新命名前的來源範圍為 `initial-review-image2` 至 `initial-review-image58`，其中沒有 image57。
- 56 個檔案都有 Markdown 引用，沒有孤立圖片；本輪也未發現指向不存在檔案的引用。
- 53 個檔案為 PNG、2 個為 JPG、1 個為 EMF；本輪均保留原始副檔名。
- 架構、UML、資料庫與介面圖片反映初評時點。由於目前角色授權、批次處理、通知、頭貼、Shorts、資料模型、部署與 QA 契約已有變動，這些圖大多需要重繪或重新截圖，不能只改檔名。
- 問卷題目與發表證明可保留作歷史佐證，但仍需補圖說、調查方法或證明背景。

## 執行順序

1. 既有 56 張圖片的章、節與流水號已依目前正文完成改名；若後續調整章節結構，須再次核對圖號。
2. 優先重繪第 3、5、6、7、8 章的架構與 UML 圖，避免舊圖傳達錯誤系統事實。
3. 在同一個可驗證環境重新截取第 12 章畫面，遮蔽個資、token、網址參數與其他敏感資料。
4. 核對市場資料、問卷方法、GitHub 日期範圍與發表證明背景。
5. 每次重繪或重新截圖後，同步更新章節引用與圖目錄，再做缺圖、重號與未引用檔案檢查。
