## 1. 這個資料夾是做什麼的

存放 12＋2 題問答驗收的原始證據。

規格書第 4 章與附錄 I 規定的驗收，結果必須存到這裡，並同步歸檔至 Notion。

**沒有存進來的結果，不算驗收通過。**

口頭回報、截圖貼在對話裡、只存在本機的檔案，三種都不算。

## 2. 一次驗收要存哪些檔案

四種都要齊，缺一種就不完整：

| 檔案 | 內容 |
|------|------|
| 題庫 | 本次執行的 12 道正向題與 2 道負向題（N01、N02）原文 |
| 環境變數快照 | 啟動時的 `runtime.flag_snapshot`，見規格書附錄 K.1 |
| 原始結果 | 腳本輸出的 JSON，含每題搜尋 backend、引用 `videoId` 與時間戳 |
| 人工複核表 | 邱偉豪主審正確性、張庭語複核引用與時間戳的結果 |

## 3. 命名規則

```
YYYY-MM-DD_<用途>_<檔案類型>.<副檔名>
```

範例：

```
2026-09-01_baseline_questions.md
2026-09-01_baseline_flag-snapshot.json
2026-09-01_baseline_raw-results.json
2026-09-01_baseline_manual-review.md

2026-09-05_final_questions.md
2026-09-05_final_flag-snapshot.json
2026-09-05_final_raw-results.json
2026-09-05_final_manual-review.md
```

**用途只有兩種，不要自創：**

- `baseline`：調門檻之前的基線證據（附錄 I.2 步驟 2）
- `final`：門檻凍結後的正式證據（附錄 I.2 步驟 4）

基線證據不得對外作為驗收結果引用。

若同一用途重跑多次，在用途後面加序號，例如 `final-2`。舊的不要刪。

上述命名規則只適用附錄 I 的正式 12＋2 題證據。Phase 1 的本機實作與測試紀錄可另用描述性檔名保存，但不得冒充 `baseline` 或 `final`。

## 4. 四項禁止事項

1. **不得放資料庫連線字串、token、API 金鑰或任何密碼。**
   包含 `.env` 內容。環境變數快照只記功能開關的值，不記連線資訊。
2. **不得放可識別到真實學生的資料。**
   學號、姓名、電子郵件一律去識別化。
3. **不得用歷史問答冒充本次證據。**
   資料庫裡那 74 筆歷史問答不計入通過率，見規格書附錄 H.4。
4. **不得事後修改已存入的原始結果。**
   發現錯誤就重跑並新增一份，舊的保留。
