## 要做

1. **共用語音模組**（第 28、80 項）：文字轉語音的介面，第一版實作 Azure zh-TW 神經語音；之後的「教師打字解釋」共用同一個模組。
2. **旁白改寫與把關**（第 79 項）：可適量改寫讓句子通順，保留原意與大部分用字、不得新增內容；數字與專有名詞必須出現在老師原句；第三步列出「旁白走樣」；講稿審閱並排顯示原句與改寫，可一鍵改回。
3. **產片流程**：教師不同意使用聲音時（第 78 項），以合成旁白取代原音，其餘流程相同；片中與 YouTube 說明欄標示「AI 合成語音」。
4. **BreezyVoice 小測**（第 83、85 項）：寫一支本機比較腳本，用同一段文字（含 OpenCV、YOLO 與破音字「行、重」）分別產生 Azure 與 BreezyVoice 的音檔，記錄每支片的產生時間，供團隊盲聽；結果寫進 evidence 並回填第 83 項。
5. **同意條款**：RC10 的條款草稿補上 Azure（文字會送到外部服務）。

## 測試

Azure 一律用假的回應。至少涵蓋：改寫出現原句沒有的數字或專有名詞被擋；改回原句；合成語音揭露出現在成品設定與上架資料；教師同意聲音時不走合成語音。
