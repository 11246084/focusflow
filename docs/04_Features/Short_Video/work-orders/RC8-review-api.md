# 工作說明：recut RC8（審閱流程 API）

分支 `wip/recut-rc8-review-api`，從 `feat/recut` 切出（RC1 已合併；RC4 還沒合併時，重跑第二、三步先接 RC1 的步驟介面與假步驟，RC4 合併後再接上）。先讀 `AGENTS.md` 與 [HANDOFF.md](../HANDOFF.md) 的「必守規則」。

這張工單提供教師審閱介面（RC9）需要的所有後端操作。先把 API 寫進 OpenAPI 並請審查確認，RC9 才能開工。

## 先讀

1. [recut 設計決策](../recut-design-decisions.md)第 19、50、51、54、55、58、63、68、69、73、75～77 項。
2. [體驗設計決策](../decisions.md) UX-1～UX-3、UX-6～UX-12；[評估素材](../evidence/2026-10-21_recut-teacher-ux/heuristic-evaluation.md)的七個畫面狀態。
3. RC1 的狀態轉換函式、任務紀錄；RC4 重跑第二、三步的入口與 AI 檢查建議格式。

## 要做

1. **讀取講稿與選段說明**（第 50 項、UX-2）：完整講稿（依實際播放順序的原話，可自然分段）；整個視窗逐字稿與每句的保留／跳過、理由標籤、片頭重點句；每句的時間供試聽。
2. **整句修改與一次套用**（第 51、54、55、68 項、UX-11）：教師以整句為單位加回或移除，程式立即回傳新總長與 30～65 秒檢查結果；修改先存成「未套用」，此時核准被擋；按「套用修改」排入背景工作重跑第二、三步，教師改過的選段鎖定；移除片頭重點句時回傳提示需要的資訊。每次改動存原本的標籤與選填的修改原因標籤（第 77 項）。
3. **取消與失敗**（第 69 項）：重跑中可取消；取消或失敗都回到原版、保留未套用的修改。
4. **套用 AI 建議**（UX-3、UX-7、UX-8）：教師勾選建議後，整批成為一個新的修改任務，共用該任務固定的呼叫上限；只修改採納的建議所需部分，不推翻教師鎖定的選段（需要時回傳說明，等教師確認）；記錄採納與否供第 19 項統計。
5. **講稿核准與成品回審**（第 63、73、75 項）：核准講稿時記錄版本，之後才可排入渲染；成品修改依第 75 項：只改呈現時保留講稿核准、重製後重審成品，講述內容或順序改變時回到講稿審閱。
6. **操作時間**（第 58、76 項）：記錄講稿審閱、成品審閱、等待製作三段時間。
7. **文件**：OpenAPI 與 API 契約；新增錯誤碼補進 `.claude/rules/api-design.md`。

## 測試

至少涵蓋：未套用修改時核准被擋；總長超出時不能套用；套用後選段鎖定、第三步不改動；取消與失敗回到原版並保留修改；套用建議共用一次任務的額度；推翻鎖定選段需教師確認；只改呈現與改講述內容兩種回審路徑；非該課程教師與學生得 403；操作時間三段分開記錄。
