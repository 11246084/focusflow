# 組內會議（系統架構與開發分工）

- 會議日期: 2026-03-31
- 會議類型: 
- 與會者: 邱偉豪, 鍾百陶, 張家瑜, 張庭語

## 討論內容

1. 系統核心技術探討
  - 檢索增強生成 (RAG)： 團隊深入討論了 RAG 的運作機制，確認將「知識庫」概念導入系統，讓 AI 能根據特定影片內容回答問題，而非僅依賴模型本身的訓練數據。
  - 語音轉文字 (STT)： 決定採用 OpenAI 的 Whisper 模型，將教學影片中的語音精準轉換為逐字稿，作為後續 RAG 檢索的基底資料。
  - 向量資料庫與存儲： 討論如何將文字資料進行向量化 (Embedding) 並存入資料庫。初步選定使用 MongoDB，因其對於處理非結構化資料具有較佳彈性。
2. 系統架構與流程設計
  - 前端與後端分離：
    - 學生/使用者端： 透過網頁前端進行課程選取，隨後跳轉至 Line Bot 進行主要的 Q&A 互動。
    - 教師/管理端： 設計網頁後台頁面，供老師上傳影片、管理課程資訊及查看學生學習數據。
  - 流程優化： 使用者選課後生成 QR Code 導向 Line Bot，AI 接收問題後，串接 API Gateway 調用 LLM，並從向量資料庫中檢索相關影片片段（短影音/時間點）回傳。
3. 架構圖工具與生成
  - 探討如何利用 AI 工具（如 Gemini、ChatGPT、Claude）協助生成 PlantUML 或程式碼形式的架構圖。
  - 參考過往學長姐的優秀範例（如「唐正老師」組別的架構），強調圖表需包含角色層 (Actor)、服務層 (Services) 與數據層 (Data)。
  
  
## 決議事項 


1. 開發工具鏈鎖定：
    - 語音處理：Whisper。
    - 後端架構：基於 Python 的 API 服務。
    - 資料庫：MongoDB (含向量存儲功能)。
    - 介面：Web (管理) + Line Bot (互動)。
2. 架構圖版本： 放棄過於複雜的初始版本，改採由 AI 輔助修正後的「模組化架構圖」，並需明確標註 API 調用流程。
3. 產品階段： 第一階段目標為達成「影片內容檢索與問答」的最小可行性產品 (MVP)。

## 後續行動項目

1. 定稿 MVP 範圍與驗收條件
    - 產出：1 頁 MVP 規格（必備功能清單 + 成功標準）
    - 優先級：高
    - 建議負責：發起人/組長（你）
    - 截止：本週內（避免後續架構反覆）
2. 敲定 STT 流程（Whisper）與輸出格式
    - 內容：決定用哪個 Whisper 版本/部署方式、音訊切段策略、逐字稿格式（含時間戳）、錯誤率目標
    - 產出：STT pipeline 小文件 + 範例輸出（1 支影片跑完）
    - 優先級：高
    - 截止：1 週內
3. 定義「逐字稿切段 + Embedding」策略
    - 內容：chunk size、overlap、是否保留說話人/段落標記、metadata（影片 id、時間點、章節）
    - 產出：切段規則 + metadata schema
    - 優先級：高
    - 截止：1 週內
4. MongoDB 向量存儲與集合（collection）設計定稿
    - 內容：課程/影片/片段/chunk/embedding 的資料結構、索引策略（向量索引 + 一般索引）、容量估算
    - 產出：ER/Schema 圖或文件（以你們討論的 MongoDB 方案為準）
    - 優先級：高
    - 截止：1–2 週內
5. RAG 檢索與回傳格式設計（含時間點/片段）
    - 內容：檢索 top-k、重排序（是否需要）、回答時要回哪些引用（影片、時間戳、片段文字/短影音連結）
    - 產出：API 回傳 JSON 規格 + 1 個示例
    - 優先級：高
    - 截止：1–2 週內
6. API Gateway / Backend service 邊界切分
    - 內容：列出服務清單、責任邊界、主要 endpoints（上傳影片、查詢、問答、管理端數據）
    - 產出：模組化架構圖 v1（你們已決議要標註 API 調用流程）
    - 優先級：中-高
    - 截止：1–2 週內
7. Web 管理端最小功能清單
    - 內容：老師上傳影片、課程管理、查看學生學習數據（先做哪些）
    - 產出：Admin UI 的 MVP 頁面列表 + 欄位/流程
    - 優先級：中
    - 截止：2 週內
8. Line Bot 互動流程（選課→QR→問答）細化
    - 內容：選課如何產生 QR、如何綁定使用者與課程、訊息格式、錯誤處理（找不到答案/檢索不到）
    - 產出：流程圖 + 訊息範本（使用者看到的文案）
    - 優先級：中
    - 截止：2 週內
9. 「端到端」PoC 串接（最小可跑通）
    - 內容：挑 1 支影片 → STT → embeddings 入庫 → Line Bot 發問 → 回答 + 引用時間點
    - 產出：Demo 錄影/截圖 + GitHub README 執行步驟
    - 優先級：高
    - 截止：2–3 週內
10. 分工表與每週里程碑（4 週甘特對齊）
    - 內容：把上面任務分到人（你、張庭語、鍾百陶、張家瑜），定每週交付物
    - 產出：任務追蹤庫更新（Owner/Deadline/Status）+ 週目標
    - 優先級：高
    - 截止：本週內
