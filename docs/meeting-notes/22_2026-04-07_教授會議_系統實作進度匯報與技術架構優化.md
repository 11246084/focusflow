# 與教授開會：系統實作進度匯報與技術架構優化

- 會議日期: 2026-04-07
- 會議時間: 15:00-16:30
- 會議類型: 與教授開會 / 進度回報 / 技術架構調整
- 與會者: 邱偉豪, 張家瑜, 張庭語, 鍾百陶, 蒯思齊(教授)

## 討論內容

1. 技術架構由文字檢索轉向多模態檢索
  - 教授指出原本「影片 -> 抽音訊 -> Whisper 轉文字 -> 文字 embedding」的流程，存在模型過多、向量空間不統一，以及影像資訊流失等問題。
  - 團隊討論後改採 Gemini Embedding 2 作為核心檢索模型，直接把影片的畫面、聲音與文字映射到同一個向量空間。
  - 模型預設維度為 3072，會再評估是否以 MRL 壓縮至 1536，以平衡資料庫成本與搜尋速度。
2. 影片切段與多模態索引策略
  - 因 Gemini Embedding 2 對影片輸入長度有限制，長影片需要先做規則式切段。
  - 會議中決定先將課程影片切為 15 至 30 秒的片段，讓每個片段都能建立獨立的多模態向量。
  - 這樣的切法不只符合模型限制，也有助於問答結果精準跳轉到對應知識點發生的時間。
3. 資料庫與 AI pipeline 調整
  - `video_segments` 需新增多模態 embedding 相關欄位，並保留 `startSec`、`endSec` 等時間資訊。
  - Whisper 不再是搜尋主力，而是轉為字幕顯示與術語校正的輔助流程。
  - 既有 `query_embedding.service.js` 需要把 embedding 呼叫來源從 OpenAI 改為 Google Vertex AI 的 Gemini Embedding 模型。
4. 影片處理與播放的雙軌化架構
  - 團隊確認將系統分為「地端運算軌」與「雲端播放軌」。
  - 地端運算軌負責 FFmpeg 音訊抽取、影片切片、embedding 與逐字稿產出，避免每次從雲端拉大檔造成處理效率低落。
  - 雲端播放軌則將影片或後續剪輯後的短片放在 GCS 或 S3，前端與 LINE Bot 只透過 `video_url` 或 clip 連結播放，不直接消耗後端伺服器頻寬。
5. 影片處理狀態機與 API 設計
  - 會議中整理出 `queued`、`processing`、`completed`、`failed` 四種狀態，作為影片處理流程的狀態機。
  - 前端將透過 `/videos/:videoId/processing` 輪詢處理進度，必要時也要能拿到錯誤代碼。
  - 未來若要提升 LINE Bot 體驗，可再加入依 `startSec`、`endSec` 自動剪片並上傳雲端的 `clips` 流程。
6. LINE Bot 整合與安全問題排除
  - 目前 LINE Webhook 驗證失敗的核心原因，是 `app.js` 全域先跑了 `express.json()`，導致原始 request body 被改寫，簽章比對失敗。
  - 解法是針對 `/api/v1/line/webhook` 使用 `express.raw({ type: 'application/json' })`，保留原始 body 做 HMAC 驗證。
  - 會議也追蹤了 ngrok 連線問題與 Channel Access Token 外洩事件，要求全面改用 `.env` 管理 secrets，避免再寫死在程式碼或文件中。
7. 前端角色路由與展示方向
  - 張同學展示科技感 Landing Page，並規劃以 GSAP 與 Three.js 製作 3D 動效。
  - 系統角色維持 `Admin`、`Teacher`、`Student` 三種，登入後依角色導向對應儀表板。
  - 未來問答頁面需能顯示片段時間點與自動剪輯結果，讓多模態檢索成果更容易被使用者理解與操作。
8. 組員分工與下週檢查點
  - 前端負責 Landing Page、角色導流與學生 dashboard。
  - 後端負責修復 webhook、調整向量索引設定、補齊狀態機 API 與 QA API 2.0。
  - AI / 影片處理負責 Gemini Embedding 2 串接、15 至 30 秒切片邏輯、JSONL 匯出與自動同步腳本。
  - DB / LINE Bot 負責 schema 遷移、LINE 綁定驗證、MongoDB Atlas index 狀態，以及行動端訊息體驗升級。

## 決議事項

1. 棄用原本以文字為主的 embedding 流程，改採 Gemini Embedding 2 作為核心多模態檢索方案。
2. 影片預處理統一採用規則式切段，先以 15 至 30 秒作為標準 chunk 長度。
3. `video_segments` 必須擴充多模態向量欄位與時間戳欄位，支援精準跳轉與後續 clip 產生。
4. Whisper 保留，但角色調整為字幕顯示與術語校正輔助，不再作為主要檢索依據。
5. 系統採用「地端運算 + 雲端播放」雙軌架構，原始大檔留在地端運算，播放流量交由雲端儲存承接。
6. `/videos/:videoId/processing` 必須作為前後端同步的正式處理進度 API。
7. LINE webhook 必須改用 raw body 驗簽，並全面以 `.env` 管理所有 LINE secrets。
8. LINE 綁定流程維持 QR Code 搭配一次性 token 的方案，綁定成功後寫回 `LineUserId` 並更新使用者狀態。
