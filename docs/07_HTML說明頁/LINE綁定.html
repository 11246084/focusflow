0開工前的第一步

在 LINE Developers Console 打開正式 provider 的「Roles」，用 Weihao 的 LINE Developers 帳號 Email 邀請他，角色選 Admin（不是 Member）。Weihao 接受、出現在清單上才算完成。這樣 Weihao 才能幫你看設定，出問題時也能緊急處理。

1一個學生的故事

晚上十一點，阿哲在宿舍複習，想用 LINE 問 FocusFlow 一個問題。系統說要先綁定帳號。

他回到網頁，按「產生綁定碼」，畫面出現一串 64 個字元的亂碼。他在手機上長按複製、切到 LINE、貼給機器人……結果複製到一半，少了幾個字。

試了兩次都失敗，他就關掉了。

另一位同學綁成功了，問了問題，收到的回覆長這樣：

Bot：[MVP提示] 片段：75s - 120s ……

「MVP 提示」是什麼？75s 又是第幾分鐘？學生看不懂，這是開發時留下來的字樣。

老師那邊更是不知道：到底有多少學生在用 LINE 問問題？統計頁上只看得到總數。

2這次要解決什麼問題

不只是把綁定碼換成一顆按鈕，而是打通整段體驗：

連結帳號 → 開始提問 → 看得懂回答 → 老師看得到使用情況

終極目標：讓 LINE 成為學生輕鬆開始、安心使用、願意一直提問的學習入口。同時，任何人的 LINE 都不會被綁到別人的帳號。

名詞：LINE Login、provider、channel 是什麼？

LINE Login：讓 LINE 幫我們確認「這個人真的是這個 LINE 帳號的主人」，再把結果交給 FocusFlow。
provider：LINE Developers Console 裡管理服務的單位，像一個資料夾。
channel：一個 LINE 服務的設定，例如現在的聊天機器人就是一個 Messaging API channel。

3怎樣算成功

看得見的結果

  • 阿哲在網頁按「連結 LINE」，手機上按「同意」和「加好友」就完成，不用複製任何東西。
  • 網頁看得出三件事：有沒有綁定成功、有沒有加好友、要怎麼解除綁定。出錯時告訴學生該怎麼做，不只丟出錯誤碼。
  • Bot 的回覆像正式產品：沒有開發字樣，時間寫成 1:15 - 2:00。
  • 老師在統計頁看得到網頁和 LINE 各有多少提問。

安全不是自己說了算

Weihao 那邊事先寫好了一份攻擊情境清單，共 19 條，例如：

有人想……系統必須……
把自己產生的授權連結騙同學點開不能因此把同學的 LINE 綁到他的帳號
同一個授權請求用第二次拒絕
用已經綁在別人帳號上的 LINE 再綁一次拒絕，別人的綁定不變
在解除綁定時偷塞別人的帳號只解除自己的

每一條都要寫成自動測試並通過，再加上用測試環境在手機和電腦上實際跑過的紀錄。完整清單在 HANDOFF，AI 會自己讀。

4你和 AI 可以決定的事、不能踩的線

你和 AI 自己決定

  • 按鈕放哪、畫面長怎樣、文案怎麼寫
  • 程式怎麼拆、測試怎麼寫
  • 授權流程的細節，只要通過攻擊情境清單
  • 要在本機用測試環境，還是在正式 provider 測試
  • 圖文選單要不要這次一起做

這些線不能踩，要改先找 Weihao

  • 一個 LINE 只能綁一個帳號。想搶綁別人已經綁定的 LINE，一律拒絕。
  • 換綁要先確認。學生自己的帳號要換成新的 LINE，畫面要先問「確定要取代目前的 LINE 嗎？」。
  • 不存 LINE 的 token。用完就丟，資料庫裡少一份可以被偷的東西。
  • 沒登入就不能綁定。流程跳到另一個瀏覽器時，要請學生回原本的瀏覽器重來。
  • 已經綁好的同學不能因為改版失效。
  • 正式 LINE 後台每一步都先問。尤其把 channel 改成 Published 之後就無法退回。
  • 不推 main。推 main 會直接部署到正式站，部署由 Weihao 做。

5我們想到的一種做法 參考，不是規定

下面是查過 LINE 官方文件後整理的做法，你可以照著做，也可以想出更好的。

為什麼要「核對 state 和登入者」？ 假設壞人自己按了「連結 LINE」，把產生的授權連結傳給你。如果系統只看連結、不看是誰登入，你點了之後，你的 LINE 就會被綁到壞人的帳號，你之後在 LINE 問的問題都會記到他那邊。核對「發起的人＝現在登入的人」就能擋掉。

你可能想得到更好的

學生用電腦怎麼完成？

電腦上沒有 LINE App，LINE Login 會顯示 QR code 讓手機掃。流程會多一步，畫面怎麼引導最清楚？

學生在加好友那頁按了「略過」怎麼辦？

綁定成功了，但 Bot 傳不了訊息給他。「已綁定」和「已加好友」要分開顯示，並給他一顆加好友的按鈕。

從 LINE 那邊來的學生，怎麼引導他去綁定？

還沒綁定的學生直接在 LINE 傳訊息，Bot 可以回一顆按鈕，打開網頁的連結頁。還有沒有更順的方式？

在本機測試，還是在正式 provider 測試？

本機另開一個測試用 provider 最安全，但要多建一個測試用官方帳號。在正式 provider 測試，channel 還在 Developing 時只有 Admin、Tester 能登入；但加好友會加到正式的官方帳號，測試訊息也會送到正式伺服器。你來評估哪個划算。

業界怎麼做？
做法說明
LINE Login（參考做法）網頁按鈕發起，同一個流程可以順便加好友
LINE Account Link從 Bot 發起，但學生仍要在 LINE 內建瀏覽器登入，步驟沒有比較少
OAuth 的 state 與 PKCE業界標準的防偽造做法，LINE 官方文件也建議使用

6和 AI 一起做

  1. 先完成第 0 步：邀請 Weihao 為 Admin。
  2. git pull 取得最新的 dev，用 Codex 或 Claude Code 打開 FocusFlow 專案。
  3. 貼上開場指令。AI 會先用例子教你這個問題，請你用自己的話說說看，再和你討論做法與測試環境。
  4. 你選好做法、說「開始」，AI 就會在同一個對話裡一路做到完成，並自己 commit、測試、push 到 dev。
  5. 額度用完了？換另一個工具（Codex ↔ Claude Code）或等額度恢復，再貼一次開場指令，AI 會讀進度檔接著做。
  6. 做完後貼上回報指令，把摘要傳給 Weihao。

開場指令

你是我在 FocusFlow 專案的開發夥伴。我是百陶，這次負責「LINE 學習入口與帳號綁定」。 請先讀 docs/04_Features/LINE_Binding/HANDOFF.md，照裡面「開場時 AI 要做的事」進行： 1. 只讀它指定的段落，不要一次讀完整份 decisions.md。 2. 用一個具體例子跟我解釋這次要解決什麼問題，然後請我用自己的話說出要改什麼、怎樣算成功；我講錯的地方幫我釐清。 3. 先問我有什麼想法，再拿參考方案出來比較，說明取捨；也幫我評估測試環境要用本機測試 provider 還是正式 provider，並提醒我評估圖文選單能不能一起做。如果我的想法比較好，就採用，並寫回 decisions.md 和 docs/07_HTML說明頁/LINE綁定.html。 4. 我說「開始」之後，在這個對話一路做到完成：攻擊情境清單每一條都寫成測試、小步 commit、push 前跑測試、只 push 到 dev、每次 commit 後更新 evidence/進度.md。 5. 只有遇到 HANDOFF 寫的三種情況才停下來（正式 LINE 後台的每一步都算），並幫我寫好要傳給 Weihao 的訊息。如果預估 11/10 前做不完，最晚 11/6 提醒我求援。 如果 evidence/進度.md 已經存在，先讀它，從上次停下的地方接著做。

回報指令

請整理這次的回報，寫成 docs/04_Features/LINE_Binding/evidence/<今天日期>_回報.md，並在對話中給我一份可以直接傳給 Weihao 的摘要： 1. 成果：五個優先項目各做到哪裡，附 commit。 2. 測試證據：已執行與未執行的測試分開列，未執行要寫原因；附攻擊情境 A1～A19 與測試名稱的對照，以及手機、電腦端到端紀錄的位置。 3. 和參考方案不同的地方：改了什麼、為什麼；測試環境選了哪一種、為什麼。 4. 部署需要的設定清單，對照 HANDOFF 的正式環境關卡 P1～P6。 5. 我學到什麼：根據我們的對話，用我的口吻寫三到五句「我會怎麼向評審解釋這個功能的安全設計」，先給我確認再存。 6. 確認 decisions.md、HANDOFF.md 與 docs/07_HTML說明頁/LINE綁定.html 都已同步。

7什麼時候停下來找 Weihao

大部分時間 AI 會自己往前做。只有這三種情況要停下來，AI 會幫你寫好訊息：

  1. 任何正式環境的操作：正式 LINE 後台、webhook、伺服器、正式資料庫、部署。每一步都先問，Weihao 同意才做。
  2. 要踩到第 4 段那些線，例如想把 LINE 的 token 存起來，或要改問答回應的格式。
  3. 做不到，或發現要求互相矛盾。請照實說。

另外，如果 AI 預估 11/10 前做不完，最晚 11/6 就要求援。提早求援，Weihao 才有時間調人手；不要自己偷偷砍範圍。
