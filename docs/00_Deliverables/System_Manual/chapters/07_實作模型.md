# 第7章 實作模型

本章說明 FocusFlow 的正式環境部署拓撲、前後端與 AI Pipeline 的套件與元件分工，以及主要物件在其生命週期中的狀態與合法轉換。外部憑證、Atlas index 與各項 feature flag 屬執行環境設定，其實際狀態由 `/health` 端點與部署環境查證，不屬本章圖表描述的範圍。

---

## 7-1 佈署圖（Deployment diagram）

FocusFlow 的實作由四個可獨立啟動的區域構成：React SPA、Express API、Python AI Pipeline 與 MongoDB／Atlas。瀏覽器與 LINE 不直接讀寫資料庫；所有課程權限、影片管理及問答請求都先進入 API。Pipeline 是 CLI，不內嵌於 Node.js process；它以執行產物、MongoDB upsert 與 internal processing webhook 和 API 協作。

表7-1-1　部署層級、用途與外部依賴邊界

| 層級 | 實作元件與用途 | 依賴邊界 |
| --- | --- | --- |
| 使用端 | React 19 SPA（開發預設 5173）及 LINE App | SPA 以 `/admin` 分離管理員登入；其餘頁面主要以 component state 導覽。 |
| 應用層 | Node.js／Express 4 API（預設 4000）、JWT、Mongoose、Multer | API 依 routes → controllers → services → models 分層；internal processing endpoint 不用 JWT，改驗 shared secret。 |
| AI 處理層 | Python 3.10+、Faster-Whisper、FFmpeg／yt-dlp、Gemini embedding | 可處理單支或 CLI batch，具 checkpoint、manifest、resume。 |
| 資料與外部服務 | MongoDB／Atlas、Atlas Vector Search、Gemini／OpenAI provider、LINE、YouTube | 各服務是否已配置、index 是否存在、憑證是否有效，屬執行環境設定，非程式碼可推定的事實，一律以 `/health` 查證。 |

`.github/workflows/deploy.yml` 定義 push 至 `main` 後由 self-hosted runner 在 `/opt/focusflow` 拉取程式、安裝 backend dependencies、建置 frontend、調整 SELinux context、重啟 PM2 backend 並 reload Nginx。此流程只涵蓋部署自動化本身；對外網域、LINE 與 AI provider 的實際可用狀態取決於部署當下的環境設定，非本節圖表範圍。文件不記錄 IP、token、連線字串或其他環境秘密。

如圖7-1-1所示，Nginx 負責 HTTPS 靜態檔案與 API reverse proxy，PM2 管理 Node.js backend，Python Pipeline 以本機程序與受保護 webhook 協作。LINE webhook 目前經由常駐的 ngrok 通道直接對應到 4000 埠，不經由 Nginx 443；對外 80 埠不通，僅 443 對外提供 HTTPS。MongoDB Atlas、AI provider、LINE、YouTube 與 SMTP 均位於外部受管服務邊界；圖中的連線只表示介面責任，實際憑證與各服務可用狀態由執行環境決定。

## 7-3 元件圖（Component diagram）

以下為目前可由程式入口驗證的元件分工與依賴方向。

```text
main.jsx → App.jsx / AdminApp.jsx → DashboardApp → pages → services → api.js
                                                         ↓ HTTPS/JSON
routes → controllers → services → models → MongoDB
                         ├→ Gemini/OpenAI、LINE、YouTube adapters
                         └→ spawn/resume Python Pipeline
Pipeline stages → run artifact/checkpoint → MongoDB uploader → internal webhook
```

表7-3-1　主要元件責任與邊界

| 元件 | 主要責任 | 不應誤解為 |
| --- | --- | --- |
| `frontend/focus-flow/src/main.jsx`、`App.jsx`、`AdminApp.jsx` | 啟動 SPA、還原 session、分離 admin 入口。 | 完整 client-side router；導覽主要以 component state 切換。 |
| `DashboardApp.jsx`、pages、`api.js` | 依角色組合 Student／Teacher／Admin 頁面；集中 token header 與 HTTP 錯誤解析。 | 前端資料權限的最終判斷者；權限一律由 API 重驗。 |
| `routes/`、`controllers/`、`services/`、`models/` | URL/middleware、request orchestration、業務規則與 schema 分層。 | controller 直接讀寫 MongoDB；業務規則集中於 services。 |
| QA／citation 元件 | 取得允許範圍、檢索 Leaf segment、產生回答與 citations、記錄結果。 | 保證每個問題都能得到回答；visual segment 不產生畫面敘述。 |
| 影片／batch／processing 元件 | 單檔與多檔上傳、持久 batch aggregate、狀態轉換、重試與 webhook。 | batch flag 開啟即代表 Pipeline CLI 與外部服務行為皆已涵蓋；flag 只控制批次上傳本身是否可用。 |
| Pipeline 元件 | 掃描／下載、音訊處理、STT、正規化、chunk、embedding、artifact validation、publication。 | 本機執行產物等同已寫入 shared Atlas 並可供 QA 查詢；兩者是分開的步驟，須經 upload／publication 動作才進入可查詢範圍。 |

## 7-4 狀態機（State machine）甚至時序圖（Timing diagram）

### 可由程式驗證的狀態與轉換

表7-4-1　主要狀態、事件與實作約束

| 對象 | 狀態／事件 | 實作約束 |
| --- | --- | --- |
| 登入 session | anonymous、authenticated、invalid、unavailable、forbidden | `/auth/me` 驗證 user 仍有效；只有 401／403 清除憑證；network／5xx 保留可能有效的 session。 |
| Course | `draft`、`published`、`archived` | 學生內容存取還需 active Enrollment；僅 published 不是充分條件。 |
| Enrollment | `active`、`revoked` | 唯一 `(studentId, courseId)` 關係可重新啟用並保留稽核資料；無 active record 採 default-deny。 |
| Video processing | `queued → processing → completed` 或 `failed`；`failed → queued` retry | internal start／complete／fail 均檢查合法前態；重送 completed 需保持冪等。 |
| VideoBatch | `creating`、`processing`、`completed`、`partial`、`failed` | 結果由逐檔 upload／processing 狀態彙總；最大十檔。 |
| LINE binding | unbound → token issued → bound → course selected | token 有 TTL；webhook 必須先驗簽。 |
| ShortScript | `evidence_ready`、`generated`、`changes_requested`、`approved`、`dismissed` | `ALLOWED_TRANSITIONS` 表與 `assertTransition` 明確拒絕未列出的轉換，回傳 409 `SHORT_SCRIPT_STATE_INVALID`；`dismissed` 為終態。 |
| ShortAsset | `status`：`draft`、`published`、`archived`；`reviewStatus`：`pending`、`approved`、`rejected` | 發布需 CAS 條件成立（`reviewStatus=approved` 且 `generationVersion` 未變），否則 409 `SHORT_ASSET_NOT_APPROVED`；同一版本只允許審核一次，重審回 409 `SHORT_ASSET_REVIEW_CONFLICT`。 |
| YouTube upload（Video.youtubeUpload） | `uploading`、`uploaded`、`failed` | 重試需 `retrySafe=true` 且 `attemptCount` 未達上限，否則以 409 `YOUTUBE_UPLOAD_RETRY_UNSAFE`／`YOUTUBE_UPLOAD_RETRY_LIMIT_REACHED` 拒絕；逾時的 `uploading` 由背景回收工作隔離為 `failed`。 |

QA 檢索以 Leaf 片段為權威來源；Parent chunk 是選用的階層式聚合產物，是否併入檢索路徑由 `HIERARCHICAL_RETRIEVAL_ENABLED` feature flag 控制，預設關閉。

短影音成品由教師於系統外完成剪輯與渲染後人工上傳，系統本身不提供自動剪輯、9:16 渲染或字幕合成功能；腳本協作與成品上傳／審核／YouTube 排程功能是否開放由 `SHORT_SCRIPT_AUTOMATION_ENABLED` feature flag 控制。ShortAsset 的 `published` 狀態表示成品審核通過且已完成 YouTube 上傳，實際狀態轉換以圖7-4-8為準。

圖7-4-1顯示 session 還原時，401／403 會清除無效憑證；network／5xx 則進入 unavailable 並保留可能有效的 session。一般角色誤進 `/admin` 時進入 forbidden，但不破壞正常入口可用的登入資訊。
