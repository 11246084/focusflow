# 工作說明：recut RC11b（正式技術試跑工具）

分支 `wip/recut-rc11b-trial`，從 `feat/recut` 切出（RC1～RC9、[RC11a](RC11a-single-topic-run.md) 已合併）。單題的產片指令、本機資料庫與 Atlas 唯讀複製已在 RC11a 完成，本工單在它之上做多主題試跑與指標統計。先讀 `AGENTS.md` 與 [HANDOFF.md](../HANDOFF.md) 的「必守規則」。

這張工單只**做工具並用假資料測試**。實際試跑要讀共用 Atlas、呼叫 Gemini、產生費用，必須由使用者當次授權並確認目標後才執行，不在本工單內自行執行。

## 先讀

1. [recut 設計決策](../recut-design-decisions.md)第 40、41、52、58、64、76、90、92 項；RC11a 的指令與回報。
2. `backend/scripts/qa-eval/` 的既有評測腳本寫法（輸出格式、唯讀連線、報告產生）。

## 要做

1. **試跑腳本**（第 40、92 項）：用 RC11a 的單題指令依序跑 10 個主題；資料從本機資料庫讀寫，共用 Atlas 只經 RC11a 的唯讀複製；成品與中間檔只存本機。
2. **穩定度**（第 52 項）：每個主題用相同輸入跑 3 次第一步，計算三次選段的秒數重疊比例與標籤不同的句數。
3. **指標彙整**（第 41、58、64、76 項）：生成成功率、回答不了判斷、每支片的 Gemini 費用（依 token 數與模型價目換算）與渲染時間、三段操作時間的中位數與範圍；剪接自然度、團隊修改量、教授核准等人工指標留欄位由人填寫。第 41 項⑥的時間目標已由第 76 項改為不先訂數字。
4. **報告**：產生 Markdown 報告，放到 `docs/04_Features/Short_Video/evidence/`（登記在 evidence 索引），日期以實際執行日為準。

## 測試

用假的資料庫與 Gemini 回應跑完整流程，確認不寫入共用 Atlas、指標計算正確、報告格式正確。
