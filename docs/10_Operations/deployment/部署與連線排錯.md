# 部署與連線排錯

這份文件說明 FocusFlow 在 VM（執行服務的虛擬主機）上的部署流程與連線排錯方法，供維運時查閱。實際主機、網址、憑證與驗收結果只看[目前狀態](../../current-status.md)；排錯時以程序實際設定與 `/health` 回應為準。

## 部署流程

[部署流程設定](../../../.github/workflows/deploy.yml)在 push 到 `main` 時觸發：進入 `/opt/focusflow` 拉取程式 → 安裝後端套件 → 打包前端 → 執行 `restorecon` 還原檔案的安全標記 → 以 PM2（管理 Node.js 程序的工具）重啟後端，並讓 nginx（提供網頁與 API 轉送的伺服器）重讀設定。流程也傳入部分環境設定並做服務檢查；設定檔存在不代表部署成功。

- `.env` 不隨 Git 同步；主機上的設定檔與部署流程傳入的環境變數都要核對。
- 在主機內可用 `curl localhost:4000/health`，或由管理員「系統服務」頁呼叫 `GET /api/v1/admin/system-status`；外部 `/health` 是否轉送須核對 nginx 設定。

## nginx 與憑證

- nginx 參考位置為 `/etc/nginx/conf.d/focusflow.conf`；檢查前端檔案位置、`/api/` 轉送、`upload_size.conf` 與 `client_max_body_size`。上傳收到 413 時先核對大小限制。
- 檢查 HTTPS 回應標頭時，注意 `add_header` 的繼承範圍：在 `location` 區塊自行設定後，不會沿用外層的全部標頭。
- 憑證參考位置為 `/etc/nginx/ssl/focusflow.crt`、`focusflow.key` 與 `/opt/acme.sh`，以 TLS-ALPN-01（透過加密連線驗證網域控制權）申請。操作前查閱[憑證申請與回復步驟](2026-09-10_Lets_Encrypt憑證申請紀錄.md)，核對執行帳號、續約排程及是否會暫停 nginx。

## 連線排錯

- 查 HTTP 連線用 `curl -v http://<主機>`，避免只用會自動改成 HTTPS 的瀏覽器。
- 判斷封包是否到達主機，可在授權環境用 tcpdump（封包檢查工具）觀察，先確認網卡、篩選條件及權限：

```bash
tcpdump -ni <網卡> 'tcp[tcpflags] & tcp-syn != 0 and dst host <主機IP> and (dst port 80 or dst port 443)'
```

- CORS 是限制瀏覽器跨網站請求的規則；分別用允許與不允許的來源檢查 `Access-Control-Allow-Origin` 回應，不由設定名稱推定結果。
- LINE 回報網址若使用 ngrok（把外部連線轉送到本機服務的工具），核對 `ngrok.service`、轉送目標與 LINE 平台設定；暫時網址不是固定部署網址。

例：教師上傳影片收到 413 → 檢查 `client_max_body_size` 與 `upload_size.conf` → 調整後重讀 nginx 設定 → 以同一檔案重試上傳。
