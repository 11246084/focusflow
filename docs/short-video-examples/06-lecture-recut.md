# 06・原片剪輯 + 字幕強化

> 共用素材、分鏡表格式、吸引力規格、聲音規格、三道驗證關見 [_shared-conventions.md](_shared-conventions.md)（v7）。本檔只寫這支片的差異。
>
> **v6 變更**：字幕校正從純人工改成 **G3 半自動**——用 ASR 回讀原音，與人工校正稿逐字比對，對不上的地方才需要人看。這把「不能自動化」從全片降到只剩差異處。
>
> **最低成本、可以完全自動化。** 不寫新腳本、不生任何畫面、不重新配音——直接從課程原片剪出關鍵那 33 秒，轉成 9:16，把字幕做大。聲音 100% 是老師原話。

> ## ⚠️ 這支片的規格已於 2026-08-14 修訂
>
> 實查 Atlas 後發現，這批影片的逐字稿是**簡體字而且有 STT 錯誤**。資料庫裡實際存的內容是：
>
> > 这一个一个东西这个就叫token 啊这个也是token 啊包含最后的这个句点他也是token
>
> 其中「济费方式」應為「計費方式」、「自然与人处理」應為「自然語言處理」、「chat gbd」應為 ChatGPT。
>
> **原本的賣點「字幕 100% 是老師原話」不成立**。修訂後的定位是：
>
> - **聲音**仍然 100% 是老師原音，未經重錄、未加速——這部分沒變
> - **字幕**必須人工校正（簡轉繁 + 修 STT 錯字），level 從 `verbatim` 降為 **`corrected`**
> - 因此**這支片不再是完全自動化**，每支需要一次人工校對
>
> 校正只允許改「聽錯的字」，不可改語序、不可補詞、不可刪句。校正後的字幕必須與音檔逐字對得上。

## 字幕校正規則

| 允許 | 不允許 |
|------|--------|
| 簡體轉繁體 | 改語序 |
| 修 STT 聽錯的字（济費→計費、chat gbd→ChatGPT） | 補老師沒講的詞 |
| 刪贅詞（「啊」「那個」「呢」） | 刪整句 |
| 補標點 | 換更專業的用詞 |

**校正後必須與音檔逐字對得上。** 判準：關掉畫面、只聽聲音看字幕，每個字都對得起來。

### 用 G3 把校正變成半自動（v6 新增）

原本的做法是人工從頭校對一遍。v6 改成三步：

```
① 對原音跑一次 ASR（與資料庫裡那份 STT 逐字稿是不同的引擎）
      ↓
② 套上方的錯字對照表，自動修掉已知錯誤，簡轉繁
      ↓
③ G3 比對：ASR 結果 vs 校正稿
      → 一致的段落：直接採用
      → 不一致的段落：標記出來，**人只看這些**
```

**這樣人工負擔從「整支」降到「差異處」。** 兩套 ASR 都認同的字幾乎不會錯；兩套不一致的地方才是真正需要人耳判斷的。

實作要點：

- ASR 引擎要**與 pipeline 用的那套不同**，否則會犯一樣的錯，比對就沒有意義
- 專有名詞（`token`、`ChatGPT`）給 ASR 當 hint 詞表，正確率會明顯提升
- **仍然需要人做最後確認**。這是把工作量減少，不是取消

> 這支片因此從「不能自動化」變成「**半自動，人只看差異**」。它仍然是十支裡唯一需要人工介入字幕的一支，但負擔小很多。

## 選段規則（可程式化）

1. S1 起點取 `startSec - 4`（讓老師講完前一句、氣口自然）
2. S0 冷開場另外從該段裡挑一句「最反直覺的 2 秒」。可程式化的判準：找逐字稿裡含 `其实不是 / 不对 / 也是 / 包含` 的最短句
3. 終點取「該 chunk 最後一句的句尾」，**不可切在句中**
4. 總長超過 40 秒就往後砍段，**不可加速播放**
5. 起訖點各留 0.3 秒靜音，避免切到字頭字尾

## 什麼時候不能用這支手法

- 原片該段有 **「剛才那張投影片」「你們看螢幕」** 這種指涉，抽出來就看不懂
  - **這批影片要特別檢查**：`chunk_0007` 結尾是「我们直接来看他的那个…」，明顯指向畫面，所以 S3 的終點必須切在「有关系」之後、「那这边这个演算方法」之前
- 原片該段講到一半被學生打斷
- 原片畫質過低（轉直式要放大，1080p 以下會糊）
- **逐字稿錯字多到校正等於重寫**——那就失去這支片的意義，改用 01 或 02

## 轉檔指令

**用模糊背景填滿，不要裁切。** 直接裁會把老師或投影片切掉。

```bash
ffmpeg -ss 52 -to 101 -i aiA10_1140123_2.mp4 -filter_complex \
"[0:v]scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,gblur=sigma=24[bg];\
 [0:v]scale=1080:-2[fg];\
 [bg][fg]overlay=(W-w)/2:(H-h)/2" \
-c:a copy vertical.mp4
```

主體置中後，畫面上下各有約 480px 的模糊帶——**上帶放標題字卡，下帶放字幕**，剛好。

## 聲音設計（唯一一支不能設計聲音的）

這支片的聲音**沒有設計空間**，只有處理空間。

| 項目 | 規格 |
|------|------|
| 語氣 | 無法指定，是老師當下的樣子 |
| 語速 | **不可加速**。教學語音一加速，聽感會從「講課」變成「趕進度」，而且老師的口音會失真 |
| 剪點 | 一律落在氣口，不可切在換氣中間。切點前後各留 0.3 秒 |
| 配樂 | **不加**。原片已有教室環境音（冷氣、翻頁、學生聲），疊配樂會變成兩個空間 |
| 可以做的處理 | HPF 80Hz 濾冷氣低頻；整體 normalize 到 −14 LUFS；**輕度** de-noise（過度會有水下感） |
| 不可以做的 | 換配音、補錄漏字、用 AI 修飾語氣。一旦重錄，這支片的唯一優勢就沒了 |

> S0 冷開場是把原音的一段搬到最前面，**不是把它獨立出來重新處理**。兩處用的必須是同一份音檔，否則同一句話在 0 秒與 15 秒聽起來會不一樣。

## POST

字幕是這支片的主角——原片語速慢、贅詞多，**字幕做大做準才救得回來**。

| 項目 | 規格（與共用規範不同之處） |
|------|---------------------------|
| 每屏字數 | 4–6 字（比其他版本更少，因為原話較長） |
| 字級 | 72px（比標準的 64px 大） |
| 位置 | 下方模糊帶內，距底 240px |
| level | **`corrected`**，不是 `verbatim` |

無生成畫面，**不需要「AI 示意畫面」標示**。但要加一行小字標明來源：`節錄自課程影片 00:52–01:41`。

**驗收（共用清單外加）**
- [ ] 每一列的「來源」欄都有值，且 chunkId 存在於 `video_segments_text`
- [ ] **字幕已人工校正並逐字對過音檔**
- [ ] 校正只改了聽錯的字，沒有改語序或補詞
- [ ] 切點沒有切在句中
- [ ] S3 沒有切到「我们直接来看他的那个…」這種指涉畫面的句子
- [ ] 未使用加速播放
- [ ] 最後 5 秒是收束字卡，沒有導流
- [ ] 已標明節錄來源與時間區間
- [ ] 用的是 `6a67ffd295668cc2b904f3c4` 這一份影片，不是 Bridge Course 那一份
- [ ] **G3 比對跑過**，兩套 ASR 不一致的段落都經人確認
- [ ] ASR 的 hint 詞表有含 `token`、`ChatGPT`
