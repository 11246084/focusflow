# 使用個案邊界：Actor 規則與內部流程的歸屬

> 通用層。已知失效模式：把系統自己當 Actor、把內部技術流程寫成 use case。

## 硬性規則

| # | 規則 | 標記 |
|---|---|---|
| 1 | 被設計的系統（System under Design）**不得**在自己的使用個案圖中作為行為者 | `[UML:MUST]` |
| 2 | 外部系統**可以**作為行為者（次要／支援行為者） | `[UML:MAY]` |
| 3 | 純內部技術流程**不得**寫成使用個案 | `[OOAD:MUST]` |
| 4 | 避免使用「時間」或「排程器」作為行為者 | `[OOAD:SHOULD-NOT]` |
| 5 | 內部流程仍須以功能性需求條目登錄，追溯不得中斷 | `[OOAD:MUST]` |

### 規則 1 的說明

系統邊界框**內**是系統提供的使用個案，框**外**才是行為者。把系統自己畫成框外的 actor，
等於宣告「系統是自己的外部使用者」，在 UML 語意上是錯的，也讓系統邊界失去意義。

### 規則 2 的說明

外部系統作為行為者是**完全合法**的 UML 用法。判準是：它在系統邊界**之外**，且與系統有互動。

| 可以當 Actor | 不可以當 Actor |
|---|---|
| 第三方 API 服務 | 本系統的後端服務 |
| 外部訊息平台 | 本系統的排程器 |
| 支付閘道 | 本系統的資料庫 |
| 外部身分提供者 | 本系統的佇列 |
| 另一個獨立系統 | 本系統的任何模組 |

### 規則 4 的說明

Cockburn 等方法允許以「時間」作為觸發者，但這個慣例有爭議且容易被誤用為把所有排程
作業都塞進使用個案圖。本 skill 預設避免；若專案明確採用該慣例，須在系統規格章的方法論
宣告中載明後方可使用。

## 使用個案三測試

`[OOAD:HEURISTIC]` 用於提示，**不單獨作為退回理由**。

1. **老闆測試**：做完這件事，使用者會覺得有進展嗎？
2. **可觀察價值測試**：結果是行為者看得到的嗎？
3. **停止測試**：行為者可以在此處停下來去做別的事嗎？

三題皆「否」→ 高度可能不是 use case，提示作者確認。

## 命名判準

| | 使用個案 | 內部技術流程 |
|---|---|---|
| 觸發者 | 行為者（人或外部系統） | 系統內部事件、排程、訊息佇列 |
| 完成後 | 行為者獲得可觀察的價值 | 系統狀態改變，行為者不一定感知 |
| 命名 | 動詞 + 名詞，從使用者角度 | 技術動作 |
| 範例 | 「查詢課程問答」「上傳教學影片」 | 「呼叫向量檢索」「消費處理佇列」「清除快取」 |

`[OOAD:HEURISTIC]` 若 use case 名稱包含下列詞彙，提示作者確認是否為內部流程：
呼叫、寫入、讀取、同步、消費、發布、快取、索引、排程、重試、輪詢、轉換、批次。

## 內部流程的承接方式

`[OOAD:MUST]` 內部技術流程不寫成 use case，但**必須**被下列模型承接，且保留追溯。

| 面向 | 承接模型 | 追溯標註 |
|---|---|---|
| 需求登錄 | 功能性需求條目（`FR-xx`）——與使用個案同級但不同類 | 需求清單 |
| 流程行為 | 活動圖（有分支／並行／多參與者時） | `realizes: FR-xx` |
| 物件協作 | 循序圖 | `realizes: FR-xx` |
| 生命週期 | 狀態機圖 | 標對應的設計類別 |
| 結構落點 | 元件圖／佈署圖（若為獨立執行單元） | 元件編號 |

### 追溯鏈的兩條路徑

```
使用者觸發：  FR/NFR ──→ UC ──→ 設計圖（realizes: UC-xx）──→ 元件 ──→ 測試
內部流程：    FR     ─────────→ 設計圖（realizes: FR-xx）──→ 元件 ──→ 測試
                                （不經過使用個案圖）
```

兩條路徑都必須收斂到元件與測試，不得有任一段落空。

## 檢查清單

繪製使用個案圖時逐項確認：

- [ ] 系統邊界框存在且命名為本系統
- [ ] 框外的每個 actor 都在系統邊界之外
- [ ] 沒有 actor 是本系統的模組、服務、資料庫或佇列
- [ ] 沒有「時間」「排程器」actor（除非專案已宣告該慣例）
- [ ] 每個 use case 的名稱是「動詞 + 名詞」且從使用者角度
- [ ] 沒有 use case 的名稱是純技術動作
- [ ] `include`／`extend` 用於表達關係，不是流程順序
- [ ] 被排除的內部流程已在需求清單登錄為 `FR-xx`
- [ ] 被排除的內部流程已有對應的設計圖承接
