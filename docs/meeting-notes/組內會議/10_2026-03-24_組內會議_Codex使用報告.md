- 會議日期: 2026-03-24
- 會議時間: Notion 未記載

## 討論內容

1. Codex 的定位與功能層次

- 背景：團隊觀看 Codex 介紹影片，整理 AI Agent 對開發與一般電腦工作的協助方式。
- 內容：
  - 報告將 Codex 的能力分為程式碼協助、工程任務代理與電腦操作代理三個層次。
  - 程式碼協助包含撰寫、解釋與審查程式碼；工程任務代理可協助除錯、處理變更及開發流程；電腦操作代理則可處理檔案與跨工具工作。
  - Worktree、沙箱、計畫模式與技能擴充被列為重要機制，可用來隔離任務、降低誤操作風險，並在執行前先確認規劃。
- 結論傾向：AI Agent 的價值不只在產生程式碼，也在協助規劃、執行與整理多步驟工作。

2. 實作案例與使用方式

- 背景：報告以影片中的大量檔案處理及網頁遊戲開發案例，觀察 Codex 的實際工作方式。
- 內容：
  - 大量檔案案例透過辨識影片內容，依指定規則重新命名檔案。
  - 網頁遊戲案例先定義需求、架構與工作拆解，再逐步產生可執行成果。
  - 團隊認為清楚描述需求、先審查計畫及保留人工確認，是使用 AI Agent 時的重要做法。
- 結論傾向：開發者的工作會逐漸從逐行撰寫程式，轉向需求定義、架構判斷、結果審查與風險控管。

3. 與其他 AI 開發工具的比較

- 背景：會議內容比較 Codex、Claude Code 與 Claude Cowork 的介面、工程工作流及擴充方式。
- 內容：
  - Codex 偏向以圖形介面整合本機開發與電腦操作。
  - Claude Code 偏向開發者工作流、命令列操作、專案規則、子代理與 MCP 整合。
  - Claude Cowork 偏向跨文件、資料整理及多步驟辦公協作。
- 結論傾向：工具選擇應依任務場景決定，不以單一工具處理所有工作。
