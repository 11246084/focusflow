### 4.1 環境變數硬性要求

## 5. 短影片審核契約（ShortAsset）

### 5.1 資料模型變更

現況：`shortAsset.model.js:12-72` 完全沒有審核欄位，`status` enum 僅有 draft、ready、published、archived（`enums.js:53-58`），也沒有任何生成版本欄位。

須新增：

| 欄位 | 型別 | 預設 | 用途 |
| --- | --- | --- | --- |
| `reviewStatus` | String enum: `pending`、`approved`、`rejected` | `pending` | 審核狀態，與 `status` 生命週期分離 |
| `reviewedBy` | ObjectId ref User / null | `null` | 審核者 |
| `reviewedAt` | Date / null | `null` | 審核時間 |
| `reviewReasons` | Array of `{ code, note }` | `[]` | 退件原因，僅 rejected 時有值 |
| `generationVersion` | Number | `1` | 生成版本，每次重新生成 +1 |
| `reviewedGenerationVersion` | Number / null | `null` | 該次審核對應的生成版本 |

退件原因 code 沿用前端既有六類：`contentIncorrect`、`audioIssue`、`visualQuality`、`subtitleIssue`、`incomplete`、`other`。

### 5.2 API 契約

| 項目 | 內容 |
| --- | --- |
| 端點 | `POST /api/v1/shorts/:shortAssetId/review` |
| 權限 | 該短影片所屬課程的 owner teacher，或 admin |
| Middleware | `authenticate` → `authorizeRoles(teacher, admin)` → 課程 ownership 檢查 |

**Request body**

```json
{
  "status": "approved",
  "expectedGenerationVersion": 1
}
```

```json
{
  "status": "rejected",
  "expectedGenerationVersion": 1,
  "reasons": [
    { "code": "audioIssue", "note": "第 8 秒有雜音" }
  ]
}
```

**驗證規則**

- `status` 必為 `approved` 或 `rejected`
- `status` 為 `rejected` 時 `reasons` 至少一筆，且每筆 code 須在六類之內
- `note` 為選填，上限 500 字元
- `expectedGenerationVersion` 必填

**狀態機**

| 起始 reviewStatus | 動作 | 結果 |
| --- | --- | --- |
| `pending` | approved | `reviewStatus=approved`，記錄 reviewedBy／reviewedAt／reviewedGenerationVersion。此時 `status` 才可轉為 published |
| `pending` | rejected | `reviewStatus=rejected`，保存 reasons，`status` 保持 draft |
| `rejected` | 重新生成 | `generationVersion` +1、`reviewStatus` 重設為 pending、`reviewReasons` 清空 |
| `approved` | 重新生成 | 同上。**舊審核一律失效** |

**衝突判定**

以 `expectedGenerationVersion` 與資料庫當前 `generationVersion` 比對，採 compare-and-swap，樣板沿用 `avatar.service.js:205-251`。不使用 Mongoose `__v`。

| 情境 | HTTP | code |
| --- | --- | --- |
| 版本不符（送審期間已重新生成） | 409 | `SHORT_ASSET_REVIEW_STALE` |
| CAS 失敗（並發審核） | 409 | `SHORT_ASSET_REVIEW_CONFLICT` |
| 短影片不存在 | 404 | `SHORT_ASSET_NOT_FOUND` |
| 非該課程 owner | 403 | `SHORT_ASSET_ACCESS_DENIED` |
| 驗證失敗 | 400 | `VALIDATION_ERROR` |

**發布閘門**：`status` 轉為 `published` 前必須檢查 `reviewStatus === 'approved'` 且 `reviewedGenerationVersion === generationVersion`。不符則回 `409 SHORT_ASSET_NOT_APPROVED`。

### 5.3 前端修正

現況（`TeacherVideoReview.jsx`、`services/videoReview.js`）：

- 送出函式只 `console.log`，不發 HTTP
- payload 帶的是 `videoId`
- 註解中的目標端點是 `/videos/${payload.videoId}/review`
- 使用常數 `SAMPLE_VIDEO`

須修改：

1. 對象由 Video 改為 ShortAsset，payload 欄位改為 `shortAssetId`
2. 端點改為 `/shorts/${shortAssetId}/review`
3. 新增 `expectedGenerationVersion`
4. 移除 mock，改為實際呼叫 `apiFetch`
5. 移除 `SAMPLE_VIDEO`，改為由列表頁傳入真實短影片
6. 新增 409 衝突的處理：提示內容已更新，請重新載入後再審核
