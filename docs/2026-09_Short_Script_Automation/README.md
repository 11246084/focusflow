# 短影片腳本自動化整合文件

本資料夾集中管理短影片腳本自動化的規格、施工單與驗收證據。

## 這個任務在做什麼

把「學生常問問題 → 短影片」這條路自動化：系統**自動選題**、找證據、生成腳本 → 教師複製腳本產出影片並上傳（系統立刻以**非公開**傳上 YouTube 供教師預覽）→ **教師審核成品** → 通過才**對學生公開**（進學生短影片牆）；退回則不公開、把那支影片轉回私人，並把理由寫回腳本重生（DR-20、DR-21）。

腳本產出的是**結構化資料（JSON）**，不是完整 markdown——模板固定章節不由系統生成。

影片產製（B-roll、語音、合成）與既有腳本範例、模板的修改不在本輪範圍。教師端前端頁面已於 2026-09-04 由排除改為納入。

## 核准流程

本任務沿用[學生試用版施工單目錄說明](../2026-09_Student_Pilot_Backend/work-orders/work-order_README.md)的慣例，不另立一套規則。以下只記錄本任務特有的部分。

### 五個核准關卡

```text
① 規格書 v0.9 草案 → v1.0 Frozen
      核准人：專題負責人（P-02 相關另需指導教授）
      條件：規格書「核准與升版」節的條件表
      ↓
② 施工單 v0.1 草案 → 核准
      核准人：專題負責人 + 實作者
      條件：施工單「核准」節的七項對齊檢查表
      ↓
   實作批次 A（WO-01～WO-04）
      ↓
③ 停止點 SP-1
      核准人：專題負責人
      條件：規格書 7.1 檢查表 + 未觸發明確失敗條件 + 分群門檻已定版（2026-09-04 完成）
      ↓
   實作批次 B（WO-05～WO-07）
      ↓
④ 停止點 SP-2
      核准人：專題負責人
      條件：規格書 7.2 檢查表
      ↓
   實作批次 C（WO-08 上架）
      ↓
⑤ 停止點 SP-3
      核准人：專題負責人
      條件：規格書 7.3 檢查表，含實際上傳一支到 YouTube 並確認可播放
```

**三個停止點都需要人核准，不由實作者自行判定。** SP-1 觸發失敗條件時回頭調參數，不得進入批次 B。

### 簽核欄在哪

| 關卡 | 位置 |
|------|------|
| ① 規格書 Frozen | 規格書「核准與升版」節的簽核欄 |
| ② 施工單核准 | 施工單「核准」節的簽核欄 |
| ③④⑤ 停止點 | 證據檔內記錄核准人與日期 |

### 校準參數的處理方式（已完整走過一次）

分群門檻這類參數只能靠實際資料校準，若列為 Frozen 的前置條件會形成解不開的循環（校準要跑批次 A，批次 A 要施工單核准，施工單要規格書 Frozen）。

處理方式是把它定位為**校準參數而非規格決策**：Frozen 時維持預設值並標記未校準，取得證據後回填——屬參數回填，不觸發規格書退回。

此流程已於 2026-09-04 走完一次：門檻定版 0.90，證據入庫，P-01 自待決事項移除。

### 判斷順序

```text
規格書 > 施工單 > 現有程式碼 > 實作者推論
```

若互相衝突，記錄具體位置、停止該項工作、等待決議，不得自行選擇版本。改變範圍或安全紅線須升版並記入變更紀錄，不得直接改內文。

## 證據保存

驗收證據存入 `evidence/`，命名 `YYYY-MM-DD_<項目>.<副檔名>`。

證據須去識別化：不得包含學生姓名、email 或可辨識身分的原始提問全文；問句預覽比照學生試用版慣例，只保留長度與前 80 字。
