# 04 跨平台敏捷開發證據鏈

目標鏈：Notion 需求 → Kanban 任務 → 負責人 → GitHub Issue → Branch → Commit → Pull Request → 測試紀錄 → 部署 → Notion 更新與下一輪改善。

**整體結論**

- **GitHub Issue 這一環在所有案例都不存在**（repo 0 個 Issue）。簡報的流程圖要拿掉 Issue，或改成「Notion 任務卡（取代 Issue）」。
- Notion 和 GitHub 的關聯是**單向**：Notion 任務／報告寫了 PR、commit、Actions 連結；commit 訊息沒有寫 Notion 任務編號。
- PR 只在案例 1 有；其他案例是直接 commit 到 `main`，或在本機分支合併後推送。
- 以下五個案例只串接有證據的節點；沒有直接證據的節點標「尚未找到直接關聯證據」。

URL 縮寫：`N/` = `https://weihao61.notion.site/`，`G/` = `https://github.com/11246084/focusflow/`。

可信度：**高**＝原始系統紀錄直接證明（commit、Actions run、Notion 任務原文與日期）；**中**＝團隊自寫的報告或文件，與原始紀錄部分對得上；**低**＝推定或只有單一來源。
