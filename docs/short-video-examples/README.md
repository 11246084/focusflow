# 課程觀念解說・十種呈現手法

十支範例**全部是課程觀念解說，而且講的是同一個觀念、用同一組資料庫來源**。差別只在呈現方式。

這樣設計是為了可比較：同一份知識用十種方式講出來，可以直接 A/B 哪一種對學生有效，而不是在比題目好不好。

- 版本：**v8（2026-08-14）**
- **先讀**：[_shared-conventions.md](_shared-conventions.md)（共用素材、分鏡表格式、吸引力規格、聲音規格、紅線、prompt 常數、FFmpeg）
- 上位規格：[Phase2_Short_Video_Production_Spec_v1.md](Phase2_Short_Video_Production_Spec_v1.md)

> **v6 變更**：素材從虛構的「安全庫存」換成**資料庫實查的真實內容**（2026-08-14 連 Atlas 查證）。
>
> **v7 變更**：十支升到「生成 + 驗證」架構。每一鏡標定 profile，帶文字的鏡頭登記 `expectedText` 並跑 G2；語音跑 G3。02 新增虛擬講解員版本。
>
> **v8 變更**：**拿掉導流**——Shorts 定位為獨立的 30 秒學習單元，最後 5 秒改成收束重述，成功指標改成完播率+重播率。另定案配樂與音效自製、字型 Noto Sans TC、十支調色統一、標題描述模板、兩階段測試設計。

## 已定案的設計選擇

十支裡不再有「二選一」的敘述。以下八項已拍板：

| 項目 | 定案 |
|------|------|
| 旁白由誰唸（01、03、07、09、10） | **TTS**，不找老師錄 |
| TTS 音色 | **台灣中文女聲**，十支共用同一組參數 |
| 09 開場字卡縮放 | **放棄縮放**，改 0.3s 淡入 |
| 02 主版本 | **教師實拍本體版**；§B 虛擬講解員為替代方案 |
| 04 學生呈現 | **只拍背影 + 出聲**，不露臉、免肖像同意書 |
| 05 手寫實作 | **實拍手寫**（保留手與筆聲） |
| 三種備選開場 | 保留，但**第一階段不做**——見下方測試設計 |
| G2 失敗處理 | 重試 5 次後**退回程式化渲染**，不硬拚 |
| 配樂來源 | **自製一首 40 秒 ambient pad，十支共用**。零 Content ID 風險 |
| 音效來源 | **自製三種**（thud／字卡輕點／切鏡輕點），Audacity 五分鐘做完 |
| 字型 | **Noto Sans TC**（SIL OFL，商用免費）。字卡 Bold 96px／字幕 Medium 64px／小標 Regular 40px |
| 調色 | **十支統一**：5000K、低飽和、低對比。這是測試的控制變因 |
| 導流 | **不做**。Shorts 是獨立的 30 秒學習單元，最後 5 秒改成收束重述 |
| 成功指標 | **完播率 + 重播率**（原本的回流率沒有導流就量不到） |
| 標題／描述／hashtag | 有統一模板，見共用規範 §11b.3。hashtag 三個上限 |
| 發布流程 | 一律先 unlisted 上傳、等 Content ID 掃完確認無聲明再改可見度 |

## 共用的那份知識（全部實查自 `focusflow` database）

```
課程：影像處理導論（69f82564736febac6db8e97b）
影片：aiA10_1140123_2（6a67ffd295668cc2b904f3c4），全長 1800.1s
學生原問句：「說明token是什麼?」（2026-07-28 實際提出）
溯源記錄：原片 00:56（不做導流，不出現在畫面上）
```

| 代號 | chunkId | 時間 | 要點 |
|------|---------|------|------|
| A | `…chunk_0004` | 37.34–54.68s | token 是 NLP 裡一個特別的詞 |
| B | `…chunk_0005` | 56.18–68.04s | token = 把原本的句子拆成碎片化之後的東西 |
| C | `…chunk_0006` | 68.14–90.8s | 每一個碎片都是 token，**包含最後的句點** |
| D | `…chunk_0007` | 90.9–110.17s | ChatGPT 與其他語言模型的計費方式都跟 token 有關 |

十支只能從這四點裡挑、刪、重排。**「句點也算一個」是這份知識天生的鉤子**——幾乎所有人第一次都以為一個 token 就是一個字。

## 十支的驗證負擔（v7 新增）

每一鏡要標定 profile，帶文字的要跑 G2，語音要跑 G3。

| # | Profile 分佈 | 需要 G2 | 需要 G3 | 說明 |
|---|-------------|---------|---------|------|
| 01 | A×1、B×2 | ✓ | ✓ | 鉤子字卡生成 |
| 02 | 全實拍 | — | — | **驗證負擔最低**；§B 版則需 G3 |
| 03 | B×2 | — | ✓ | **刻意不用 A**，循環與 baked-in 文字不相容 |
| 04 | A×1（實拍 5 鏡） | ✓ | ✓ | S5 橫移鏡，G2 風險偏高 |
| 05 | 無生成鏡 | — | ✓ | 手寫是程式化／實拍 |
| 06 | 無生成鏡 | — | ✓ | G3 反向用途：驗字幕與原音一致 |
| 07 | A×2 | ✓ | ✓ | **最適合 profile A**——兩鏡都是靜態鏡 |
| 08 | 無生成鏡 | — | ✓ | 紙條是印的 |
| 09 | A×1、B×2 | ✓ | ✓ | 推近鏡，字可能被裁到畫外 |
| 10 | A×1、B×3 | ✓ | ✓ | **G2 失敗率預期最高**（暗場 + 中文） |

**05、08 完全不用 G2**，省掉整條出圖／回讀／重試迴圈；**02 連 G3 都不用**（真人現場收音）。這三支在 v7 架構下成本最低。

## 一個一般性的取捨

**要動的字用程式化渲染，要跟畫面融為一體的字用生成。兩者不能兼得。**

baked-in 的字不會推入、不會縮小、不會累積到左上、不會淡出。所以：

| 字卡類型 | 做法 |
|----------|------|
| 靜態、單一字串、只出現一次 | **生成**（profile A） |
| 會動、會累積、會淡出 | 程式化渲染 |
| 收束字卡 | **一律程式化**——它是全片的記憶點，寫錯等於整支白做 |
| 數學公式、多行條列 | 一律程式化——重試次數高到不划算 |

09 因此定案**放棄開場字卡的縮放**，改用 0.3 秒淡入，換取「字長在畫面裡」。

## Token 這個題目的特點

**05 和 08 是實拍演示，其餘八支用隱喻。**

v5 時代這兩支的獨佔性來自「禁止生成畫面帶資訊」，v7 開放之後沒有了——01、04、07、09、10 都能把文字放進畫面。這兩支現在的優勢改成：零生成成本、逐筆／逐刀浮現的過程感、**不需要 G2**。

其餘八支用實體隱喻：**整條吐司 → 切片 → 單獨一小片**（01、03、04、07、09），或抽象光帶斷開（10）。

**05 和 08 的切法必須跟老師課堂用的斷詞工具一致。** 這兩支會在畫面上數出「5 個 token」，這個數字不能自己決定，否則學生看完會跟課堂內容打架。

## 怎麼挑

| 你的情況 | 用哪一支 |
|----------|----------|
| 沒預算、要先驗證有沒有用 | 02 或 08（都是 NT$0） |
| 要衝重播率與播放數 | 03（無縫循環） |
| 學生反映「聽不懂 token」 | **05 或 08**（唯一能直接演示的兩支） |
| 學生已上過課，只需複習 | 09 |
| 要大量產出、老師沒空 | 01 或 09 |
| 想拉近師生距離 | 04 |
| 學生一直搞錯同一件事 | 07 |
| 觀念太抽象講不動 | 10（但需教師審核比喻） |

### 關於自動化

**06 原本是唯一可以完全自動化的，現在不是了。** 實查發現逐字稿是簡體且有 STT 錯誤（「济费方式」「chat gbd」），字幕必須人工校正一次。它仍然是成本最低的一支，但每支要付一次校對時間。

01 與 09 現在是自動化程度最高的兩支（腳本自動、畫面自動，只有字卡需要程式化渲染）。

## 三件最容易做錯的事

1. **跳過 G2 直接生影片。** 一張圖 NT$1.5、一段 8 秒影片 NT$40。在圖的階段重做二十次仍比在影片階段重做一次便宜。
2. **只驗一次 G2。** 圖生影片時模型常把首格的字改掉或糊掉，**影片生成後要抽首/中/末格再回讀一次**。橫移鏡（04-S5）與推近鏡（09-S1）風險最高。
3. **同一鏡混用 profile A 與 B。** 會讓模型同時收到「要有字」與「不准有字」，結果最不可控。要帶文字就整鏡走 A，不帶就整鏡走 B。

## 尚未確認事項

沿用 Phase2 規格 §13 與共用規範 §14。另有兩項是這次實查才發現的：

- **`token`、`ChatGPT` 的 TTS 唸法**：中文 TTS 唸英文字常變調，01、03、07、09、10 五支都受影響，合成後必須實聽
- **斷詞切法**：05 與 08 畫面上的 token 數量要對齊老師課堂用的工具，目前未確認老師實際用哪一套

十種手法的**教學效果也未經驗證**——哪一種真的讓學生在 30 秒內學會，要靠**完播率與重播率**實測。建議先做 08、02、01 各一支，比數據再決定要不要投資其餘七種。

## 測試設計（兩階段）

**十種手法與三種開場不能同時測**——那是 30 支，兩個變數混在一起什麼都測不出來。

| 階段 | 測什麼 | 支數 | 控制變因 |
|------|--------|------|----------|
| **一** | 十種呈現手法 | 10 | 開場一律用預設那句、調色統一、配樂同一首、字型同一套 |
| 二 | 階段一前 2–3 名 × 三種開場 | 6–9 | 手法固定 |

**調色、配樂、字型統一不是美學潔癖，是控制變因。** 十支長得不一樣，結果出來會分不出是「07 的對照結構有效」還是「07 剛好比較好看」。
