## 發現

### 1. Node.js 20 已停止支援（高）

Node.js 20 在 2026-04-30 結束維護，這次 10 月的 10 個漏洞（4 個高風險）不會有 20 版修補。後端 API 與部署流程裡的檢查腳本都用系統的 `node` 執行，等於對外服務跑在不再修補的執行環境上。

本機開發與測試已在 22 版進行（Backend 1123、Frontend 107 項測試於 2026-10-22 在本機通過），後端依賴沒有需要編譯的原生模組（密碼雜湊用的是純 JavaScript 的 `bcryptjs`），所以升級不用重裝 `node_modules`。

### 2. nginx 有 4 筆安全更新沒裝（高）

Rocky Linux 不會把 nginx 升到上游的 1.30 版，而是把修補補進同一個 `1.20.1` 版號，所以要看套件的修訂號，不看主版號。處理前裝的是 `1.20.1-24.el9_7.3`，套件庫已有：

| 公告 | 等級 | 修補後版本 |
|---|---|---|
| RLSA-2026:19374 | 嚴重 | `1.20.1-28.el9_8.2` |
| RLSA-2026:36331 | 重要 | `1.20.1-28.el9_8.4` |
| RLSA-2026:59362 | 重要 | `1.20.1-28.el9_8.5` |
| RLSA-2026:66542 | 重要 | `1.20.1-28.el9_8.6` |

nginx 是對外第一道門，所有網頁與 API 請求都先經過它。這 4 筆公告是否涵蓋 10/14 上游公布的兩個漏洞，可用 `dnf updateinfo info RLSA-2026:66542` 查看；Rocky 尚未出修補的漏洞，要等之後的套件更新。

### 3. 作業系統裝機後沒有整體更新（高）

主機是 Rocky Linux 9.7，`dnf history` 只有 15 筆，最後一筆是 2026-08-23 安裝 git、socat。與對外服務或權限直接相關的待裝更新：

| 套件 | 待裝公告 | 為什麼重要 |
|---|---|---|
| kernel（作業系統核心） | 32 筆，多數為重要 | 核心漏洞可能讓一般帳號取得最高權限；裝完要重開機才生效 |
| openssh | 5 筆（3 筆重要） | 遠端登入 VM 的服務 |
| openssl | 5 筆（3 筆重要） | HTTPS 加密與 Node.js 以外的 TLS 連線 |
| sudo | 3 筆重要 | 提權工具 |
| glibc、curl、libxml2、expat、pcre2 | 多筆中度到重要 | 幾乎所有程式都會用到的基礎程式庫 |

### 4. 主機裝了伺服器用不到的元件（中）

待裝清單出現桌面環境（GNOME、Xorg、PipeWire）、Firefox、Evince、容器工具（podman、buildah）、網頁管理介面 cockpit 與 samba 用戶端程式庫。其中 samba 程式庫（RLSA-2026:25049）與 webkit2gtk3（RLSA-2026:84583）是嚴重等級。這些元件不在 FocusFlow 的執行路徑上，但裝著就要跟著更新。cockpit 服務未啟用，但防火牆仍開著它的連接埠。

### 5. ngrok 通道直接開放整個後端（中）

ngrok 是把本機服務開通道到外網的工具。VM 的 `ngrok.service` 是 LINE webhook 的通道（見[系統手冊第 7 章](../../01_系統手冊/chapters/07_實作模型.md)），停掉 LINE 就收不到訊息，所以這次保留。

它轉送的是整個 4000 埠，不只 webhook 路徑：任何人用 ngrok 網址都能直接呼叫所有 API，繞過 nginx。API 本身仍要登入，不到立即可被入侵的程度，但多了一個不受 nginx 管的入口。ngrok 程式是手動放在 `/usr/local/bin`，`dnf` 不會更新它；`/etc/yum.repos.d/ngrok.repo` 的內容是下載失敗的錯誤訊息，讓每次 `dnf` 都出現警告。

防火牆只開放 SSH、HTTP、HTTPS，後端雖然監聽所有網卡，外網仍無法直接連 4000 埠，對外入口只有 nginx 與 ngrok 兩個。

### 6. nginx 公開版本號（低）

對外回應標頭帶有 `nginx/1.20.1`，攻擊者可據此比對已知漏洞。

### 2. 更新套件（17:45～18:00）

```bash
sudo mv /etc/yum.repos.d/ngrok.repo ~/ngrok.repo.broken
sudo sed -i.bak-20261023 's/pub_20\.x/pub_22.x/' /etc/yum.repos.d/nodesource-nodejs.repo /etc/yum.repos.d/nodesource-nsolid.repo
sudo dnf clean metadata && dnf list --showduplicates nodejs | tail -3   # → 最新為 22.23.4-1nodesource
sudo dnf upgrade --refresh   # 安裝 33、升級 499、移除 4（最舊的 el9_4 核心），下載 1.5G
sudo nginx -t && sudo reboot
```

同一批更新也把語音轉文字流程用到的 `ffmpeg` 升到 7.1.5、`python3.11` 升到 `3.11.13-10.el9_8`，都是修補等級。

### 4. 收尾加強（18:04）

```bash
echo 'server_tokens off;' | sudo tee /etc/nginx/conf.d/00-server-tokens.conf && sudo restorecon -v /etc/nginx/conf.d/00-server-tokens.conf && sudo nginx -t && sudo systemctl reload nginx
sudo firewall-cmd --permanent --remove-service=cockpit && sudo firewall-cmd --reload   # → dhcpv6-client http https ssh
sudo /usr/local/bin/ngrok update; sudo restorecon -v /usr/local/bin/ngrok; sudo systemctl restart ngrok   # 3.39.5 → 3.39.12
```

更新 ngrok 後再傳一次同樣的 LINE 問題，18:05 收到回答。從外部執行 `curl -sI https://focusflow.ntub.edu.tw/`，回應標頭為 `Server: nginx`，已不顯示版本號。

備份檔含 `.env` 金鑰，原本權限為 `-rw-r--r--`，已用 `sudo chmod 600` 改成只有 root 可讀（`-rw-------`）；確認不再需要後可刪除。

### 回滾方式

- 系統套件：`sudo dnf history` 找到這次更新的編號，執行 `sudo dnf history undo <編號>`；核心可在開機選單選回舊版。
- Node.js：把 `/etc/yum.repos.d/` 的兩個 `.bak-20261023` 改回原檔名，再執行 `sudo dnf downgrade nodejs`。回滾只為恢復服務，20 版仍不安全，要盡快重新升級。
- nginx 版本號設定：刪除 `/etc/nginx/conf.d/00-server-tokens.conf` 後 reload。
