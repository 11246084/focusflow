# 教師短影片腳本與成品上傳頁流程決策

這份文件記錄教師「短影片腳本」與「成品上傳」兩頁的流程與版面決策，包括狀態怎麼顯示、被退回後怎麼走、手機版怎麼切換。目的是讓換人或換 agent 接手時，不必從對話重建脈絡。功能完成與驗收只看[目前狀態](../../current-status.md)；後端規則以[規格書](specs/2026-09_Short_Script_Automation_Spec.md)與程式為準。

## 已定案（2026-10-28，第一階段：只改前端）

第一階段只改短影片腳本頁本身，不改 API、schema、狀態機或審核規則。當時成品上傳是同一頁的分頁，第二階段已改成獨立頁面（見下方「第二階段」）；以下提到成品上傳的地方都以第二階段為準。

### 1. 建立與生成是兩步

「建立腳本」（`POST /courses/:courseId/short-scripts/auto`）只凍結證據，狀態是 `evidence_ready`，還沒有腳本文字；「生成腳本」（`POST /short-scripts/:id/generate`）才呼叫模型產生第一版，約 30–45 秒。凍結證據的意思是：把當下找到的影片片段原文存成快照，之後影片怎麼改都不影響這份腳本。

- 建立按鈕的文字是「自動選題建立腳本（固定證據）」，選定主題時是「用選定主題建立腳本（固定證據）」，旁邊說明建立後主題會**永久離開候選清單**。後端排除候選時不看狀態，任何一份腳本（含已否決）都會讓該主題不再出現。
- 建立成功後自動選中這份腳本；`evidence_ready` 時操作區的主要按鈕是「生成腳本」，並預設展開證據對照表，讓教師生成前先核對。

### 2. 教師看到的狀態（前端推算）

推算邏輯在 [shortScriptStatus.js](../../../frontend/focus-flow/src/services/shortScriptStatus.js)，測試在 [shortScriptStatus.test.js](../../../frontend/focus-flow/tests/shortScriptStatus.test.js)。成品取同一份腳本（`sourceScriptId`）中還沒進學生牆的那支；沒有才取已發布的，封存的不算。

| 條件 | 顯示 | 分組 | 下一步 |
|---|---|---|---|
| `evidence_ready` | 待生成 | 需要我處理 | 生成腳本 |
| `generated`，沒有成品 | 待拍攝上傳 | 需要我處理 | 複製腳本，拍完後上傳成品 |
| `generated`，`upload.status` 是 `uploading` 或還沒寫入（null） | 傳送中 | 等待中 | 等待 |
| `generated`，`upload.status = failed`、`retrySafe = true` | 上傳失敗 | 需要我處理 | 到成品上傳重試 |
| `generated`，`upload.status = failed`、`retrySafe = false` | 上傳失敗 | 等待中 | 等管理員確認 |
| `generated`，已傳上 YouTube、`reviewStatus = pending` | 待審核 | 等待中 | 到「短影片審核」 |
| `generated`，已傳上 YouTube、`reviewStatus = approved` | 審核通過，等上架 | 等待中 | 影片傳完後自動上架 |
| `generated`，`reviewStatus = rejected` | 成品已退回 | 需要我處理 | 重傳或重新生成 |
| `changes_requested` | 需修改 | 需要我處理 | 重新生成，或重傳同一版 |
| `approved` | 已上架（學生可見） | 已完成 | 無 |
| `dismissed` | 已否決 | 已完成 | 無 |

表中後三種 `generated` 的情況是需求表沒有、但程式裡會出現的：審核在影片傳完前通過時，上架要等傳完才補做（`publishApprovedShortAsset`）；成品退回時，後端寫回腳本失敗不會讓審核失敗（`applyAssetRejection` 採 fail soft），腳本可能停在 `generated`。

成品詳情把三件事分開顯示：審核狀態、YouTube 傳送狀態、學生是否可見。「已傳上 YouTube」只代表影片以非公開傳上去，學生要等審核通過、成品變成 `published` 才看得到。

### 3. 被退回之後的兩條路

`changes_requested` 時先顯示最新一版的退回理由與來源（`rejectedAsAsset` 為 true 是成品審核退回，否則是教師自己退回），不要求重填，再並列兩條路讓教師自己選：

- (a) 依回饋重新生成腳本：直接呼叫 generate，產生下一版，之後依新版重拍上傳。
- (b) 腳本沒問題，只重錄或重剪影片：到「成品上傳」頁，用目前這一版重傳。

查證：`createAssetFromScript`（`backend/src/services/shortAssetPublish.service.js`）不檢查腳本狀態，只要求腳本至少有一版，所以 `changes_requested` 時可以上傳；上傳會把未上架的那支成品換代，審核通過後 `markScriptPublished` 把腳本轉成 `approved`（`changes_requested → approved` 是合法轉換）。

兩條路的按鈕都是次要樣式，避免畫面暗示哪一條比較好；系統不依退回原因推斷該走哪一條。

例：成品因「內容有誤」被退回 → 腳本變「需修改」，理由顯示「成品審核退回 · 第 1 版 · 講錯了／漏了重點」→ 教師判斷是腳本講錯，選 (a) 產生第 2 版；若只是收音不好，選 (b) 用第 1 版重錄後重傳。

### 4. 一般重新生成與失敗處理

`generated` 時「這版不要，重新生成」先呼叫 review（`request_changes`，回饋類型與一句回饋都必填），再呼叫 generate。review 成功但 generate 失敗時，腳本停在 `changes_requested`、回饋已存在最新一版；畫面重讀腳本後顯示第 3 節的兩條路，教師按「依回饋重新生成」即可重試，不必重填。任何操作失敗都不清空教師已輸入的回饋或上傳表單。

### 5. 已上架的腳本重新生成（降為次要操作）

`approved` 時「這版不要，重新生成…」放在「其他操作」，按下先出現確認視窗。查證後寫在視窗裡的影響：

- `submitReview` 只改腳本狀態與該版回饋，不動成品：目前上架的影片不會下架，學生仍看得到，YouTube 上的影片也不變。
- 已發布的成品不會被換代，所以依新版重拍上傳會建立另一支成品；它審核通過後也會上架，原本那支不會自動下架。

### 6. 否決主題「不做這一題」

在 `evidence_ready`、`generated`、`changes_requested`、`approved` 提供次要操作，呼叫 review（`dismiss`，理由選填，存成 `dismissReason`）。確認視窗說明：無法復原、不能再生成或上傳成品、主題不會回到候選清單；已上架時另外說明影片不會因此下架（`submitReview` 不動成品）。

### 7. 版面

- 桌面與平板（>768px）維持左清單、右詳情兩欄，點一下就切換腳本。左欄由上而下是「新腳本」（候選主題可收合，建立按鈕在同一區塊）、「需要我處理」、「等待中／已完成」（可收合）；寬度 ≤1100px 時候選主題預設收合，腳本名稱最多兩行。
- 右欄由上而下：標題與狀態、選題來源、依狀態出現的操作區、完整腳本與「複製完整腳本」、可收合的視覺隱喻／證據對照表／分鏡、底部成品摘要與「前往成品上傳」（導向成品上傳頁）。
- 每個區塊最多一個主要按鈕；操作區已有主要按鈕時，正文的「複製完整腳本」降為次要。
- 頁內不再重複「短影片腳本」標題；頂部副標題改為「依學生提問選題並生成腳本」，不再提腳本審核（系統沒有腳本審核，唯一的審核是成品影片審核）。

### 8. 手機版（≤768px）單欄切換

- 預設顯示清單（新腳本＋兩個分組）；點一份腳本，整個內容區切到詳情。詳情頂部是返回、標題（截斷）與狀態，下方有「切換腳本」按鈕，用共用的[底部抽屜](../../../frontend/focus-flow/src/components/BottomSheet.jsx)列出同課程的腳本（含分組與狀態），選完直接切換。
- 進詳情時推一筆同網址的瀏覽器歷史紀錄，瀏覽器返回鍵會回到清單；在詳情裡用抽屜切換腳本不再推紀錄。
- 退回通知的深連結（`requestOpenScript`）在手機上直接開到詳情。
- 手機單欄的切換與返回鍵處理在 [useMobileDetailView.js](../../../frontend/focus-flow/src/hooks/useMobileDetailView.js)，兩頁共用。
- 課程選擇獨占一列；兩條路上下排列；拖放區改成「點擊選擇成品影片」；確認視窗的按鈕上下排列，主要操作在上；按鈕與清單列的觸控範圍至少 44px，輸入框 16px。

## 已知限制（需要後端才能處理）

1. 後端不擋已否決腳本上傳成品（`createAssetFromScript` 不檢查狀態），目前只靠前端不顯示上傳表單。
2. 已上架腳本重新生成並重傳後，學生牆可能同時有新舊兩支同主題影片；要自動下架舊的需要後端規則。
3. 清單 API 回傳完整腳本文件（含每一版的 payload），腳本多時資料量大；目前前端只用 `status` 等欄位分組。

## 已定案（2026-10-28，第二階段：新增「成品上傳」頁，只改前端）

### 9. 成品上傳頁的定位

教師依腳本拍好影片後，到側欄的「成品上傳」（路徑 `/app/short-uploads`）上傳並送審。側欄順序是「短影片腳本 → 成品上傳 → 短影片審核」，對應做事的先後：生成腳本、上傳影片、審核影片。生成與重新生成只在腳本頁；成品上傳頁只處理影片。

- 頁面在 [TeacherShortUploads.jsx](../../../frontend/focus-flow/src/pages/TeacherShortUploads.jsx)，上傳表單與成品清單沿用 [ShortAssetPanel.jsx](../../../frontend/focus-flow/src/pages/ShortAssetPanel.jsx)；腳本頁的成品上傳分頁已移除。
- 版面同腳本頁：桌面與平板兩欄，手機單欄（清單 → 詳情，詳情頂部有返回與「切換腳本」抽屜）。
- 右欄由上而下：腳本標題與狀態、「依第幾版腳本拍攝」與下一步、可收合的「這一版腳本摘要」（主題、分鏡數、可展開唯讀全文，並連回腳本頁換視覺隱喻與複製）、上傳表單、這份腳本的成品清單（審核、YouTube、學生可見三種狀態分開）。
- 兩頁共用目前選的課程（sessionStorage），切換頁面時不必重選。

### 10. 成品上傳頁的清單分組

分組函式是 `groupUploadScripts`（[shortScriptStatus.js](../../../frontend/focus-flow/src/services/shortScriptStatus.js)），狀態推算與第 2 節相同：

| 分組 | 包含的顯示狀態 | 這一頁的下一步 |
|---|---|---|
| 待上傳 | 待拍攝上傳、需修改、成品已退回 | 上傳拍好的影片；需修改時可重傳同一版，或到腳本頁重新生成 |
| 處理中 | 傳送中、上傳失敗（可重試或需管理員確認）、待審核、審核通過等上架 | 等待，或在下方按「重試上傳」 |

待生成（還沒有腳本）、已上架、已否決的腳本不列。沒有任何需要處理的腳本時，空狀態說明「到短影片腳本頁生成腳本後，會出現在這裡」並提供連結。

### 11. 深連結的目標頁

`requestOpenScript({ scriptId, courseId, page })`（[scriptDeepLink.js](../../../frontend/focus-flow/src/utils/scriptDeepLink.js)，測試在 [scriptDeepLink.test.js](../../../frontend/focus-flow/tests/scriptDeepLink.test.js)）多了 `page`：`shortScripts`（預設）或 `shortUploads`。sessionStorage 與 window 事件兩條路都帶著 `page`，每一頁只取走指定給自己的請求，另一頁的請求留著等它掛載。

- 退回通知不帶 `page`，維持開到腳本頁（教師要在那裡選兩條路）；成品上傳頁開著時也不會攔走。
- 腳本頁的「前往成品上傳」與路 (b) 帶 `page: 'shortUploads'`，成品上傳頁開啟後直接選中那一份腳本；成品上傳頁的「在短影片腳本頁開啟」則反過來導回腳本頁。
- 舊格式（沒有 `page` 欄位）一律視為腳本頁。

例：教師在腳本頁看到「需修改」→ 選 (b)「前往成品上傳頁（第 1 版）」→ 進到成品上傳頁，詳情已是同一份腳本，表單上方說明會用第 1 版重傳。

### 12. 已上架腳本重傳的提醒

已上架（`approved`）的腳本不列在成品上傳頁，但從腳本頁的「前往成品上傳」仍可開到這裡上傳新影片。上傳表單上方固定顯示提醒：新影片會成為另一支成品，通過審核後也會上架，目前已上架的影片不會自動下架，兩支可能同時出現在學生短影片牆。依據是第 5 節的查證（已發布的成品不換代），行為不變。

已否決的腳本若透過深連結開到這一頁，只顯示「已否決，不能再上傳成品」，不顯示上傳表單。

## 目前這一輪待答題目

### Q1：已否決的腳本是否要在後端擋上傳？

**建議答案**：要。在 `createAssetFromScript` 加狀態檢查，`dismissed` 時回 `SHORT_SCRIPT_STATE_INVALID`。

**理由**：規則寫明否決後不能再上傳成品，目前只有前端擋，直接呼叫 API 仍可上傳。

### Q2：已上架腳本重傳新成品並通過審核時，舊的那支要不要自動下架？

**建議答案**：維持現狀（不自動下架），在腳本頁的確認視窗與成品上傳頁的上傳表單都明確提醒；要自動下架時另開後端工單，由成品審核通過的流程處理。

**理由**：自動下架會改變學生牆內容與 YouTube 隱私狀態，屬於審核規則變更，兩個階段都只改前端，不在範圍內。
