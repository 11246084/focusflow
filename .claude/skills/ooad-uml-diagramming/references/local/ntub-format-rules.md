# NTUB 排版與圖表格式規則

> **本層可整層移除**。依據《115 年系統手冊規範》—「1. 內容版面配置規定」與「3. 部分格式範例」。

## 圖表標號

`[NTUB:MUST]`

| 項目 | 規則 |
|---|---|
| **圖**標號位置 | 圖的**下方** |
| **表**標號位置 | 表的**上方** |
| 圖號格式 | `圖{章}-{節}-{序} {名稱}` |
| 表號格式 | `表{章}-{節}-{序} {名稱}` |
| 分隔 | 圖號與名稱之間用**空格**；**無冒號、無句點分隔** |
| 編號起算 | 每節內從 1 起編，不跨節連號 |

官方範例：`圖3-1-1 系統架構`、`表3-3-1 使用標準與工具表`

**不合規的寫法**：`圖 5.1: 系統架構`、`圖5-1：系統架構`、`Figure 3-1-1`

## 目錄要求

`[NTUB:MUST]`

- 需有封面、目錄、圖目錄、表目錄
- 圖目錄需有**圖片名稱**與**頁碼**
- 表目錄需有**表格名稱**與**頁碼**
- 目錄頁（含圖表目錄）字型大小一律 **14**

## 版面

`[NTUB:MUST]`

| 項目 | 規則 |
|---|---|
| 中文字型 | 標楷體 |
| 英文字型 | Times New Roman |
| 章標題 | 18 |
| 節標題 | 16 |
| 內文 | 14 |
| 目錄頁 | 14 |

`[FF:SHOULD]` 圖內文字的字型不受此規範拘束，但應在 14 字內文環境下仍可辨識。

## AI 使用揭露

`[NTUB:MUST]` 參考資料章需填寫 AI 使用表，欄位為官方範本：

| 序號 | 使用工具名稱 | 使用範圍及說明 | 頁碼 |
|---|---|---|---|

官方另註明：「**請於專題內文中同步標示序號以利索引**」。

官方要求的是**揭露與可索引**，**未規定紀錄的粒度**。一筆紀錄可以對應一張圖，也可以
對應一段工作範圍（例如「第 6 章循序圖共 5 張」）。

`[NTUB:MUST]` 本 skill 的要求：

1. AI 參與製圖時，在 `.puml` 檔頭記錄 `ai-assisted`，使該圖的 AI 參與情形**可追溯**
2. 檔頭紀錄必須足以彙整成 AI 使用表的內容（工具名稱、使用範圍）
3. 正文依專案決定的粒度標示序號

`[FF:SHOULD]` **紀錄粒度由專案決定**，本 skill 不規定一圖一筆。建議在
`focusflow-conventions.md` 載明所採粒度後一致套用，避免同一份手冊中混用兩種方式。

## 附錄

`[NTUB:MUST]` 附錄**未編號**，官方指定內容為「審查評審意見之修正情形（初評及複評之評審
建議項，均請填寫）」，格式為兩欄表：

| 評審建議事項 | 修正情形 |
|---|---|

`[FF]` 其他附錄內容屬本地延伸，須與官方指定內容區隔。

## 專案分工表

`[NTUB:MUST]` 第 4 章須採用官方分工表範本：

- 標記法：`●` 主要負責人、`〇` 次要負責人
- 每一項只能有 1 位主要負責人，次要負責人最多 2 位
- 「文件撰寫」與「報告」為固定欄位；「後端開發」「前端開發」「美術設計」視專題功能增列
- 另需「專題成果工作內容與貢獻度表」，貢獻度加總 100%，工作內容各限 100 字
- 4-3 GitHub 紀錄須標註每位同學的**中文姓名及學號**

## 階段範圍

`[NTUB:MUST]`

| 階段 | 範圍 | 頁數 |
|---|---|---|
| 初評 | 第 1～8 章為主 | 不限 |
| 複評 | 所有章節 | 50 頁以上 |

`[FF:SHOULD]` 製圖排序應依此優先級：第 5～8 章的圖先完成，第 9～14 章與附錄可延後。

## Markdown 母稿的限制

`[DOC:MUST]` 「圖說在下、表題在上」是 Word／PDF 排版層的要求。Markdown 渲染時位置由
工具決定，因此：

- Markdown 母稿中仍應把圖說寫在圖語法**之後**、表題寫在表格**之前**
- Markdown → Word 的轉換環節必須確認位置正確，否則整批不合規
- 此項列入交付前檢查

## 最終交付（供參考，非製圖規則）

官方附註「最終依最新公告為準」，目前列出：

1. 簡報（PDF）、系統簡介（PDF）、系統手冊 PDF 或 **MarkDown 檔**
2. 物件導向系統分析與設計 **VPP 檔或 VPD 檔**（Visual Paradigm）
3. 資料庫 **MDF 與 LDF** 檔
4. 所有軟體元件
5. 安裝程式，能將系統完整安裝至 PC 或 NB 執行

第 2、3、5 項與本專案的技術選型有落差，列為 open issue，見 `focusflow-conventions.md`。
**這些不阻塞本 skill 的製圖工作。**
