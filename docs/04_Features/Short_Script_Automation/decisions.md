# 教師短影片腳本與上傳短片頁流程決策

這份文件記錄教師「短影片腳本」與「上傳短片」（原名「成品上傳」）兩頁的流程與版面決策，包括狀態怎麼顯示、被退回後怎麼走、手機版怎麼切換。目的是讓換人或換 agent 接手時，不必從對話重建脈絡。功能完成與驗收只看[目前狀態](../../current-status.md)；後端規則以[規格書](specs/2026-09_Short_Script_Automation_Spec.md)與程式為準。

四個階段都只改前端，不改 API、schema、狀態機或審核規則。後面階段改到前面的內容時，已直接改寫成目前的做法，並註明是哪一節改的。

## 已定案（2026-10-28，第一階段：只改前端）

第一階段只改短影片腳本頁本身。當時上傳成品是同一頁的分頁，第二階段已改成獨立頁面（見第 9 節）。

### 1. 建立與生成是兩步

「建立腳本」（`POST /courses/:courseId/short-scripts/auto`）只凍結證據，狀態是 `evidence_ready`，還沒有腳本文字；「生成腳本」（`POST /short-scripts/:id/generate`）才呼叫模型產生第一版，約 30–45 秒。凍結證據的意思是：把當下找到的影片片段原文存成快照，之後影片怎麼改都不影響這份腳本。

- 建立按鈕的文字是「自動選題建立腳本（固定證據）」，選定主題時是「用選定主題建立腳本（固定證據）」，旁邊說明建立後主題會**永久離開候選清單**。後端排除候選時不看狀態，任何一份腳本（含已否決）都會讓該主題不再出現。建立按鈕在「＋ 新腳本」檢視裡（第 17 節）。
- 建立成功後自動選中這份腳本；`evidence_ready` 時操作區的主要按鈕是「生成腳本」。證據對照表預設收起，但主要按鈕旁多一個次要按鈕「點開核對證據（N 筆）」，按下會展開證據表並捲過去，維持「生成前先核對證據」的設計（第 18 節）。

### 2. 教師看到的狀態（前端推算）

推算邏輯在 [shortScriptStatus.js](../../../frontend/focus-flow/src/services/shortScriptStatus.js)，測試在 [shortScriptStatus.test.js](../../../frontend/focus-flow/tests/shortScriptStatus.test.js)。成品取同一份腳本（`sourceScriptId`）中還沒進學生牆的那支；沒有才取已發布的，封存的不算。

| 條件 | 顯示 | 腳本頁分頁 | 下一步 |
|---|---|---|---|
| `evidence_ready` | 待生成 | 需要你處理 | 生成腳本 |
| `generated`，沒有成品 | 待拍攝上傳 | 需要你處理 | 複製腳本，拍完後上傳成品 |
| `generated`，`upload.status` 是 `uploading` 或還沒寫入（null） | 傳送中 | 等待中 | 等待 |
| `generated`，`upload.status = failed`、`retrySafe = true` | 上傳失敗 | 需要你處理 | 到上傳短片頁重試 |
| `generated`，`upload.status = failed`、`retrySafe = false` | 上傳失敗 | 等待中 | 等管理員確認 |
| `generated`，已傳上 YouTube、`reviewStatus = pending` | 待審核 | 等待中 | 到「短影片審核」 |
| `generated`，已傳上 YouTube、`reviewStatus = approved` | 審核通過，等上架 | 等待中 | 影片傳完後自動上架 |
| `generated`，`reviewStatus = rejected` | 成品已退回 | 需要你處理 | 到上傳短片頁重傳，或重新生成 |
| `changes_requested` | 需修改 | 需要你處理 | 重新生成，或重傳同一版 |
| `approved` | 已上架（學生可見） | 已上架 | 無 |
| `dismissed` | 已否決 | 已否決 | 無 |

表中後三種 `generated` 的情況是需求表沒有、但程式裡會出現的：審核在影片傳完前通過時，上架要等傳完才補做（`publishApprovedShortAsset`）；成品退回時，後端寫回腳本失敗不會讓審核失敗（`applyAssetRejection` 採 fail soft），腳本可能停在 `generated`。

成品詳情把三件事分開顯示：審核狀態、YouTube 傳送狀態、學生是否可見。「已傳上 YouTube」只代表影片以非公開傳上去，學生要等審核通過、成品變成 `published` 才看得到。

### 3. 被退回之後的兩條路

`changes_requested` 時先顯示最新一版的退回理由與來源（`rejectedAsAsset` 為 true 是成品審核退回，否則是教師自己退回），不要求重填，再並列兩條路讓教師自己選：

- (a) 依回饋重新生成腳本：直接呼叫 generate，產生下一版，之後依新版重拍上傳。
- (b) 腳本沒問題，只重錄或重剪影片：到「上傳短片」頁，用目前這一版重傳。

查證：`createAssetFromScript`（`backend/src/services/shortAssetPublish.service.js`）不檢查腳本狀態，只要求腳本至少有一版，所以 `changes_requested` 時可以上傳；上傳會把未上架的那支成品換代，審核通過後 `markScriptPublished` 把腳本轉成 `approved`（`changes_requested → approved` 是合法轉換）。

兩條路的按鈕都是次要樣式，避免畫面暗示哪一條比較好；系統不依退回原因推斷該走哪一條。

例：成品因「內容有誤」被退回 → 腳本變「需修改」，理由顯示「成品審核退回 · 第 1 版 · 講錯了／漏了重點」→ 教師判斷是腳本講錯，選 (a) 產生第 2 版；若只是收音不好，選 (b) 用第 1 版重錄後重傳。

### 4. 一般重新生成與失敗處理

`generated` 時「這版不要，重新生成」先呼叫 review（`request_changes`，回饋類型與一句回饋都必填），再呼叫 generate。review 成功但 generate 失敗時，腳本停在 `changes_requested`、回饋已存在最新一版；畫面重讀腳本後顯示第 3 節的兩條路，教師按「依回饋重新生成」即可重試，不必重填。任何操作失敗都不清空教師已輸入的回饋或上傳表單。

### 5. 已上架的腳本重新生成（降為次要操作）

`approved` 時「這版不要，重新生成…」放在「其他操作」，按下先出現確認視窗。查證後寫在視窗裡的影響：

- `submitReview` 只改腳本狀態與該版回饋，不動成品：目前上架的影片不會下架，學生仍看得到，YouTube 上的影片也不變。
- 已發布的成品不會被換代，所以依新版重拍上傳會建立另一支成品；它審核通過後也會上架，原本那支不會自動下架。

### 6. 否決主題「不做這一題」

在 `evidence_ready`、`generated`、`changes_requested`、`approved` 提供次要操作，呼叫 review（`dismiss`，理由選填，存成 `dismissReason`）。確認視窗說明：無法復原、不能再生成或上傳成品、主題不會回到候選清單；已上架時另外說明影片不會因此下架（`submitReview` 不動成品）。

### 7. 版面

整體結構由第 16 節的單一面板取代；以下是詳情欄仍沿用的規則。

- 右欄（選了腳本時）由上而下：標題與狀態、選題來源、依狀態出現的操作區、完整腳本與「複製完整腳本」、可收合的視覺隱喻／證據對照表／分鏡、底部成品摘要與「前往上傳短片 →」。
- 每個區塊最多一個主要按鈕；操作區已有主要按鈕時，正文的「複製完整腳本」降為次要。
- 頁內不再重複「短影片腳本」標題；頂部副標題是「依學生提問選題並生成腳本」，不提腳本審核（系統沒有腳本審核，唯一的審核是成品影片審核）。

### 8. 手機版（≤768px）單欄切換

- 預設顯示清單（面板頂部列＋狀態分頁）；點一份腳本，整個內容區切到詳情。詳情頂部是返回、標題（截斷）與狀態，下方有「切換腳本」按鈕，用共用的[底部抽屜](../../../frontend/focus-flow/src/components/BottomSheet.jsx)列出同課程的腳本，抽屜裡用和清單一樣的分頁，選完直接切換。
- 進詳情時推一筆同網址的瀏覽器歷史紀錄，瀏覽器返回鍵會回到清單；在詳情裡用抽屜切換腳本不再推紀錄。
- 退回通知的深連結（`requestOpenScript`）在手機上直接開到詳情。
- 手機單欄的切換與返回鍵處理在 [useMobileDetailView.js](../../../frontend/focus-flow/src/hooks/useMobileDetailView.js)，兩頁共用。
- 課程選擇獨占一列；兩條路上下排列；拖放區改成「點擊選擇成品影片」；確認視窗的按鈕上下排列，主要操作在上；按鈕與清單列的觸控範圍至少 44px，輸入框 16px。

## 已知限制（需要後端才能處理）

1. 後端不擋已否決腳本上傳成品（`createAssetFromScript` 不檢查狀態），目前只靠前端不顯示上傳表單。
2. 已上架腳本重新生成並重傳後，學生牆可能同時有新舊兩支同主題影片；要自動下架舊的需要後端規則。
3. 清單 API 回傳完整腳本文件（含每一版的 payload），腳本多時資料量大；目前前端只用 `status` 等欄位分組。

## 已定案（2026-10-28，第二階段：新增上傳成品的獨立頁面，只改前端）

### 9. 上傳短片頁的定位

教師依腳本拍好影片後，到側欄的「上傳短片」（路徑 `/app/short-uploads`）上傳並送審。側欄順序是「短影片腳本 → 上傳短片 → 短影片審核」，對應做事的先後：生成腳本、上傳短片、審核短片。生成與重新生成只在腳本頁；上傳短片頁只處理影片。頁名在第四階段由「成品上傳」改成「上傳短片」（第 19 節）。

- 頁面在 [TeacherShortUploads.jsx](../../../frontend/focus-flow/src/pages/TeacherShortUploads.jsx)，上傳表單與成品清單沿用 [ShortAssetPanel.jsx](../../../frontend/focus-flow/src/pages/ShortAssetPanel.jsx)；腳本頁原本的上傳分頁已移除。
- 版面同腳本頁：單一面板，桌面與平板兩欄，手機單欄（清單 → 詳情，詳情頂部有返回與「切換腳本」抽屜）。
- 右欄（選了腳本時）由上而下：腳本標題與狀態、「依第幾版腳本拍攝」與下一步、收合的「這一版腳本摘要 · 第 N 版 · M 鏡」（主題、可再點開的唯讀全文，並連回腳本頁換視覺隱喻與複製）、上傳表單、這份腳本的成品清單（審核、YouTube、學生可見三種狀態分開）。
- 兩頁共用目前選的課程（sessionStorage），切換頁面時不必重選。

### 10. 上傳短片頁列哪些腳本

分組函式是 `groupUploadScripts`（[shortScriptStatus.js](../../../frontend/focus-flow/src/services/shortScriptStatus.js)），狀態推算與第 2 節相同，分組規則見第 13 節。待生成（還沒有腳本）、已上架、已否決的腳本不列。

### 11. 深連結的目標頁

`requestOpenScript({ scriptId, courseId, page })`（[scriptDeepLink.js](../../../frontend/focus-flow/src/utils/scriptDeepLink.js)，測試在 [scriptDeepLink.test.js](../../../frontend/focus-flow/tests/scriptDeepLink.test.js)）多了 `page`：`shortScripts`（預設）或 `shortUploads`。sessionStorage 與 window 事件兩條路都帶著 `page`，每一頁只取走指定給自己的請求，另一頁的請求留著等它掛載。

- 退回通知不帶 `page`，維持開到腳本頁（教師要在那裡選兩條路）；上傳短片頁開著時也不會攔走。
- 腳本頁的「前往上傳短片」與路 (b) 帶 `page: 'shortUploads'`，上傳短片頁開啟後直接選中那一份腳本；上傳短片頁的「在短影片腳本頁開啟」則反過來導回腳本頁。
- 舊格式（沒有 `page` 欄位）一律視為腳本頁。

例：教師在腳本頁看到「需修改」→ 選 (b)「前往上傳短片頁（第 1 版）」→ 進到上傳短片頁，詳情已是同一份腳本，表單上方說明會用第 1 版重傳。

### 12. 已上架腳本重傳的提醒

已上架（`approved`）的腳本不列在上傳短片頁，但從腳本頁的「前往上傳短片」仍可開到這裡上傳新影片。上傳表單上方固定顯示提醒：新影片會成為另一支成品，通過審核後也會上架，目前已上架的影片不會自動下架，兩支可能同時出現在學生短影片牆。依據是第 5 節的查證（已發布的成品不換代），行為不變。

已否決的腳本若透過深連結開到這一頁，只顯示「已否決，不能再上傳成品」，不顯示上傳表單。

## 已定案（2026-10-28，第三階段：上傳短片頁依誰要動手分組，只改前端）

### 13. 上傳短片頁依「誰要動手」分組

原本分「待上傳」「處理中」；可重試的上傳失敗被放在「處理中」，但其實要教師按「重試」。改成依誰要動手分，第四階段起兩組各是一個分頁：

| 分頁 | 包含的顯示狀態 | 列上顯示 |
|---|---|---|
| 需要你處理 | 待拍攝上傳、需修改、成品已退回、上傳失敗且 `upload.retrySafe = true` | 右側下一步動作：上傳、重傳、重試 |
| 等待中 | 傳送中（含 `upload.status` 為 null 的剛建立成品）、待審核、審核通過等上架、上傳失敗且 `retrySafe` 不是 true | 副標寫正在等什麼：傳送到 YouTube 中、等待審核、等影片傳完後上架、等管理員確認 |

- 對照舊分組：可重試的上傳失敗從「處理中」移到「需要你處理」；其他狀態歸屬不變，只是改名。
- 成品已退回（`asset_rejected`）需求清單沒列，但要教師重傳，歸在「需要你處理」。
- `retrySafe` 不是 true 的失敗要管理員確認 YouTube 是否已收到，教師重試可能重複上傳，所以歸在「等待中」。
- 兩頁的名稱統一為「需要你處理」（原本腳本頁是「需要我處理」）：頁面其他文案都用「你」稱呼教師，例如等待中的說明「這些在等系統或審核，你不需要動作」。
- 每列的動作與等待文字由 `groupUploadScripts` 回傳的 `cue` 決定。

### 14. 狀態標籤的圖示

狀態標籤都帶圖示，灰階也分得出來：待拍攝上傳是攝影機、上傳失敗（可重試）是警告三角形、需修改與成品已退回是鉛筆、傳送中是時鐘、待審核是沙漏、需管理員確認是提示圖示、審核通過等上架是上傳箭頭、待生成是星芒、已上架是勾選圓圈、已否決是禁止符號。圖示在 [Icons.jsx](../../../frontend/focus-flow/src/components/Icons.jsx)，沿用同樣的線條風格。第三階段的虛線框、旋轉圖示與「等待中」收合，第四階段改成分頁後已移除。

### 15. 右欄「尚未選擇腳本」的引導

只用頁面已載入的資料推算，不新增 API；共用元件在 [shortScriptGuide.jsx](../../../frontend/focus-flow/src/pages/shortScriptGuide.jsx)。手機單欄直接顯示清單，不會出現這個引導。第四階段移除了概況統計卡（數量改看分頁徽章）。

| 區塊 | 腳本頁 | 上傳短片頁 | 資料來源 |
|---|---|---|---|
| 建議下一步 | 「需要你處理」第一筆（最近更新的），次要按鈕「打開這份腳本」 | 「需要你處理」第一筆，主要按鈕「打開並上傳」 | `groupScripts`／`groupUploadScripts`，即 `listScripts` 與 `listAssets` 推算的顯示狀態 |
| 沒有需要處理時 | 說明候選主題數量，或候選主題來自學生提問、同一個問題被問到一定次數後才出現；按鈕「＋ 新腳本」 | 說明「到短影片腳本頁生成腳本後，會出現在這裡」，附前往連結 | `listCandidates` 的筆數；門檻是後端 `shortScriptTopicMinHitCount` |

- 課程沒有任何腳本時（全新課程），腳本頁改成一段引導文字加「＋ 新腳本」按鈕；上傳短片頁在沒有要處理影片的腳本時，改成引導文字加「前往短影片腳本 →」。
- 流程說明第五階段起移到頁面最上方常駐顯示，不再放在這個引導區塊裡，見第 20 節。
- 腳本頁的「打開這份腳本」用次要樣式，因為面板頂部已有主要按鈕「＋ 新腳本」。

## 已定案（2026-10-28，第四階段：單一面板與狀態分頁、上傳短片改名，只改前端）

使用者回饋：左欄疊多張卡片、右欄只有一張短卡，看起來割裂；統計卡和分組標題重複顯示同一個數字；分組標題沒有符號；候選主題為 0 時「新腳本」區塊仍佔很大空間；可收合的資訊要預設收起但標示可以點開；成品上傳頁要改名並換圖示。

### 16. 單一面板與狀態分頁

- 兩頁的內容區都是一個面板（沿用 `.card`）：頂部一列是課程選擇、重新整理（圖示按鈕，`aria-label` 是「重新整理」）、右側「＋ 新腳本」（只有腳本頁）；下方左右兩欄用 1px 分隔線切開，欄內區塊之間也只用分隔線，不另加卡片底色。兩欄用 grid 等高，右欄內容較短時貼齊上方，面板外框包住兩欄。
- 左欄頂部是狀態分頁，取代原本的分組卡片與右欄的統計卡，數量只在分頁徽章出現一次：
  - 腳本頁：需要你處理（驚嘆號圓圈）、等待中（沙漏）、已上架（勾選圓圈）、已否決（禁止符號）。分組函式 `groupScripts` 回傳這四組。
  - 上傳短片頁：需要你處理、等待中。「等待中」分頁頂部有一行說明「這些在等系統或審核，你不需要動作。」
  - 「需要你處理」數量大於 0 時徽章用強調色 #F14F21 實心，其他分頁是中性外框徽章；選中的分頁有外框與底色。
- 預設分頁：記住的分頁優先；否則「需要你處理」有資料就選它，再來是「等待中」，都為 0 時選第一個有資料的分頁。記住的是同一頁、同一課程最後選的分頁（localStorage `ffShortTab:<頁>:<課程>`，讀寫失敗時忽略）。邏輯在 [shortScriptTabs.js](../../../frontend/focus-flow/src/utils/shortScriptTabs.js)，測試在 [shortScriptTabs.test.js](../../../frontend/focus-flow/tests/shortScriptTabs.test.js)。
- 分頁用 `role="tablist"`／`"tab"`／`"tabpanel"` 與 `aria-selected`；左右方向鍵、Home、End 切換，只有選中的分頁在 Tab 順序裡。
- 第三階段「點概況數字捲到左欄分組」改成直接點分頁，`jumpToSection` 已移除。
- 手機：分頁是可以水平捲動的膠囊列，數量徽章仍可見；「切換腳本」抽屜裡用同樣的分頁。

### 17. 「＋ 新腳本」改成按鈕觸發

- 左欄不再常駐「新腳本」區塊。按面板頂部的「＋ 新腳本」後：桌面的右欄切換成「新腳本」檢視（標題、關閉按鈕、候選主題清單含幾人問過與次數、建立按鈕、凍結證據與主題永久離開候選清單的說明），關閉後回到原本的右欄內容並把焦點還給「＋ 新腳本」；手機用底部抽屜顯示同樣內容。
- 候選主題為 0 時，檢視裡說明候選主題的來源，但仍可以按「自動選題建立腳本」；沒有符合條件的主題時顯示後端回傳的原因。
- 建立成功後的行為不變：關閉新腳本檢視、自動選中新腳本，主要操作是「生成腳本」。在左欄點任何一份腳本也會關閉新腳本檢視。

### 18. 收合規則（兩頁一致）

- 可收合的區塊都預設收起：視覺隱喻、證據對照表、分鏡、這一版腳本摘要（含其中的完整腳本）。流程說明第五階段起改成頁首常駐、不收合，見第 20 節。
- 整列標題都是按鈕（`aria-expanded`、`aria-controls`），右側顯示「點開 ▾」，展開後是「收合 ▴」，不能只有箭頭；標題旁顯示數量，例如「證據對照表 · 4 筆」「分鏡 · 8 鏡」「視覺隱喻 · 2 組（目前：…）」。共用元件是 `Disclosure`（[shortScriptUi.jsx](../../../frontend/focus-flow/src/pages/shortScriptUi.jsx)）。
- 換一份腳本時各區塊回到收起。
- 例外：待生成時證據表仍預設收起，但「生成腳本」旁多一個次要按鈕「點開核對證據（N 筆）」，見第 1 節。

### 19. 「成品上傳」頁改名為「上傳短片」

- 側欄、頁面標題、按鈕與說明文字的頁名改成「上傳短片」，例如「前往上傳短片」「到上傳短片頁重試」；副標題改成「依腳本拍好短片後，在這裡上傳送審」。狀態說明裡的「成品」保留（例如「成品已退回」、「上傳成品並送審」），因為成品是審核的對象，不是頁名。
- 網址 `/app/short-uploads`、sub id `shortUploads` 與深連結的 `page: 'shortUploads'` 不變：已發出的通知、瀏覽器書籤與 `scriptDeepLink`、`pageRouting` 的測試都依賴它們，改名只是顯示文字。
- 側欄圖示從和「上傳影片」相同的雲朵上傳箭頭（`up`）改成場記板加上傳箭頭（`shortUp`）。

## 目前這一輪待答題目

### Q1：已否決的腳本是否要在後端擋上傳？

**建議答案**：要。在 `createAssetFromScript` 加狀態檢查，`dismissed` 時回 `SHORT_SCRIPT_STATE_INVALID`。

**理由**：規則寫明否決後不能再上傳成品，目前只有前端擋，直接呼叫 API 仍可上傳。

### Q2：已上架腳本重傳新成品並通過審核時，舊的那支要不要自動下架？

**建議答案**：維持現狀（不自動下架），在腳本頁的確認視窗與上傳短片頁的上傳表單都明確提醒；要自動下架時另開後端工單，由成品審核通過的流程處理。

**理由**：自動下架會改變學生牆內容與 YouTube 隱私狀態，屬於審核規則變更，四個階段都只改前端，不在範圍內。
