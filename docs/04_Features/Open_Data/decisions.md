# 教育開放資料補強設計決策

FocusFlow 參加 2026 大專校院資訊應用服務創新競賽「教育開放資料組」，決賽評分有 40% 看「教育部開放資料使用度（數量與程度）」，目前只有一項還沒上線的愛學網推薦，是最弱的一項。這份文件記錄 11/7 決賽前的補強方案：現況查證、已定案事項、目前這一輪的待答題目與建議答案；換 session 或換 agent 時以本文件接續。功能是否完成只看[目前狀態](../../current-status.md)。

## 名詞

- **開放資料（Open Data）**：政府機關公開、可免費下載再利用的資料，本文件指[政府資料開放平臺](https://data.gov.tw/)上的資料集，以編號稱呼（例 6318）。授權都是「政府資料開放授權條款－第 1 版」，使用時要標示來源。
- **教育部（含所屬機關）**：競賽「選項 1」的資料提供者範圍。國家教育研究院（以下稱國教院）、國家圖書館都是教育部所屬機關。
- **愛學網**：國教院的教學影片平臺，資料集 6318 是影片清單（標題、描述、關鍵字、學習領域、學習階段、網址），內容以國中小與高中為主。
- **學術名詞**：國教院整理的英中對照專業名詞，每個學科一個資料集，欄位是英文名稱、中文名稱。
- **向量（embedding）**：把一段文字轉成一串數字，意思相近的文字數字也相近；問答已經用 Gemini Embedding 比對學生問題與逐字稿片段。
- **兩層開關**：環境變數決定這個環境允不允許開啟，系統設定只能在允許範圍內切換，見[系統設定決策](../System_Settings/decisions.md)第 7 項。

## 整體流程（例，設計目標）

學生在「影片處理工具 - OpenCV」課程問「二值化的閾值要怎麼選？」→ 系統照常從課程逐字稿回答並附時間戳 → 回答下方多兩個區塊：

1. **中英術語**：答案裡出現的「二值化」「閾值」，從電子計算機學術名詞查到英文 binarization、threshold，標示來源為國教院。
2. **先備知識補強**：用問題向量比對愛學網影片，找到高中「資訊科技」的影像處理入門影片，標示「國家教育研究院愛學網，非本課程教材」。

教師在課程頁可看到學生最常需要補強的主題與術語（見 Q4）。

## 目前這一輪待答題目

第一輪：先決定用哪些資料、怎麼用、做到哪裡算完成，工單依答案在下一輪切出。**2026-10-27 起暫停**：未入圍教育開放資料組決賽，各題的「決賽」前提已不成立，重新啟用前要先改寫時程與 Q5、Q6。

### Q1：決賽要用哪幾個資料集？

**問題**：除了愛學網，要再接哪些資料集？

**建議答案**：愛學網 6318（升級）＋電子計算機學術名詞 15416＋資訊名詞 15406，共三個，全部來自國教院。NBINet 7502 列為選做，Q1～Q5 都完成後再評估；不用名錄類資料湊數量。

**理由**：評分是「數量與程度」，詢答時評審會問每個資料集用在哪裡，用不上的資料反而扣印象。兩份學術名詞格式相同（英文、中文），可以合成一張術語表並保留每筆的來源，多一個資料集幾乎不增加工作量。NBINet 沒有主題欄，只能用書名比對，下載連結目前也打不開，10/28～11/1 做不完驗證。

### Q2：愛學網要怎麼比對？

**問題**：現在的「關鍵字整詞比對」多數問題推不出影片，要怎麼改？

**建議答案**：改用向量比對。匯入時把每支影片的「標題＋描述＋關鍵字」轉成向量，存在 `open_edu_videos`；推薦 API 把學生問題轉成向量，取相似度最高且超過門檻的前 3 支，關鍵字命中時加分。門檻用 Q5 的題庫校準，寧可推不出來也不推錯。區塊名稱從「延伸學習」改成「先備知識補強」。

**理由**：問答已經有 Gemini Embedding（[問題向量服務](../../../backend/src/services/queryEmbedding.service.js)），不用新增服務。推薦 API 與問答是分開的請求，每題多算一次問題向量，費用很低；全部影片的向量只在匯入時算一次。愛學網是國高中內容，當成大專課程的「延伸」並不貼切，當成「基礎沒學好時回頭補」就符合實際內容，詢答時也能說明為什麼選這份資料。這一題已決定維持「不進入回答 prompt」，回答本身的品質與快取都不受影響。

### Q3：學術名詞要怎麼用？

**問題**：術語表要放在哪裡、做到什麼程度？

**建議答案**：只做「中英術語」卡：回答產生後，找出答案文字裡出現的中文術語，列出英文對照，最多 5 個，依術語長度與在答案中出現的次數排序，附來源。決賽前**不做**「用術語表改寫學生問題再檢索」。

**理由**：術語卡只是在答案之外附加資訊，不改回答流程，出錯頂多少一張卡；它也呼應教育部推動的大專校院雙語化學習政策，學生同時學到英文專業名詞。改寫問題再檢索會改變檢索結果與 FAQ 快取，需要先跑比較實驗（見[多模態檢索](../Multimodal_Retrieval/decisions.md)的門檻做法），10/28～11/1 做不完；詢答時可以說是下一步。

### Q4：要不要做教師端統計？

**問題**：「資料呈現方式」算在創新分數裡，要不要給教師看開放資料的統計？

**建議答案**：做簡版。教師的課程頁加一張卡片：近 7 天學生最常被推薦的補強主題（依愛學網的學習領域與標題）前 5 名、最常出現的術語前 10 名。資料來自每次推薦時記下的紀錄，不記學生姓名。Q2、Q3 完成後才做。

**理由**：只有學生看得到時，開放資料是「附加連結」；彙整給教師後，就變成「學生哪些基礎不夠」的教學資訊，評審比較容易看到資料的價值。只統計主題與術語、不記個人，避免額外的個資問題。

### Q5：做到哪裡算可以上線？

**問題**：推薦與術語卡的品質門檻是什麼？

**建議答案**：用 [QA 評測題庫](../QA_Evaluation/datasets/question-bank.json)與[影像文字檢索題集](../QA_Evaluation/datasets/2026-09-29_影像文字檢索評測題集.json)的題目跑一次，逐筆人工判定。推薦出的影片至少三分之二要判定為相關，術語卡錯誤對照（中文對了、意思不同）不超過 1 成；達不到就提高門檻再跑。報告寫在 `evidence/`，列出「有推薦的題數、相關率、術語卡命中數」。

**理由**：決賽要有具體數字支撐「程度」，也能回答「推薦準不準」。只看相關率會鼓勵什麼都不推，所以同時列出有推薦的題數，兩個數字一起看。

### Q6：上線時程與授權

**問題**：是否照上方時程，11/1 一次完成部署與正式站設定？

**建議答案**：是。11/1 需要授權的操作有四項：①部署 `dev` 到 VM；②正式站匯入愛學網（含向量）與術語表（先 dry-run，再用 `--expected-count` 寫入）；③開啟 `OPEN_DATA_EXTENSION_ENABLED`（環境變數與系統設定兩層）；④若 Q4 要做，建立統計用的新集合。期中考週只修會讓展示失敗的問題。

**理由**：一次列清楚讓使用者一次確認，不用每一步都等。匯入腳本已經有 dry-run 與筆數確認，重跑不會產生重複資料。期中考週改程式容易在決賽前出新問題。

### Q7：分工

**問題**：誰負責哪一塊？

**建議答案**：愛學網語意比對由原作者組員 11246084 負責或審查；術語表與術語卡交給 Codex 平行開發，由主 session 審查；教師端統計、驗收與展示腳本由使用者指定。

**理由**：原作者最清楚 10/03 實測時的問題。三塊改的是不同檔案，可以同時開發，不會互相覆蓋。
