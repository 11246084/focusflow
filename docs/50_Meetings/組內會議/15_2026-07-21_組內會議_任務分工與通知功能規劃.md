# 組內會議（任務分工與通知功能規劃）

- 會議日期: 2026-07-21
- 會議時間: Notion 未記載
- 會議類型: 組內會議（問題討論）
- 與會者: 邱偉豪、鍾百陶

## 討論內容

1. 環境變數同步與行政待辦

- 背景：前端、後端與 RAG 使用的 `.env` 不一致，容易造成設定遺漏及執行差異。
- 內容：
  - 需要建立可維護的環境變數同步方式，同時避免把憑證或金鑰提交到版本庫。
  - 初評影印費用仍未完成分攤。
- 結論傾向：先整理各服務需要的變數名稱、用途與範例值，再建立一致的共享規則。

2. 各成員後續分工

- 背景：團隊依目前 Phase 2 缺口重新確認個人任務。
- 內容：
  - 鍾百陶：建立常見問題回答資料、取得網域後完成網域設定。
  - 張家瑜：移除前端管理員入口，並確認短影片介面是否需要持續滑動。
  - 張庭語：實作 Chunk Overlap、多層級切段與檢索，以及圖片 Embedding。
  - 邱偉豪：修正登入與註冊、實作系統通知，以及補上後端頭貼上傳與讀取。
- 結論傾向：各成員沿既有模組責任推進，下一次會議回報實作進度與問題。

3. 登入、註冊、通知與頭貼

- 背景：目前登入入口缺少帳號角色驗證，註冊流程也可能失敗；前端頭貼介面已有初版，但後端尚未完成。
- 內容：
  - 登入流程需檢查帳號角色，避免教師帳號從學生入口登入後被錯誤導向。
  - 註冊 API 需檢查欄位驗證、重複帳號、密碼加密及資料寫入，並回傳明確錯誤訊息。
  - 影片處理完成後，系統需通知修課學生；管理員也需能發送系統問題或維護通知。
  - 通知需有資料結構、已讀／未讀狀態及前端查詢 API。
  - 頭貼功能需由後端接收與儲存檔案、關聯使用者並提供讀取 API。
- 結論傾向：先完成登入註冊修正、系統通知與頭貼後端處理，公告功能延後。

4. 公告與通知的功能邊界

- 背景：團隊區分教師臨時訊息與系統事件訊息，避免一次擴大太多功能。
- 內容：
  - 公告用於教師發布教室異動等臨時訊息。
  - 通知用於影片完成、系統問題與維護等事件。
- 結論傾向：公告暫緩，現階段先聚焦影片處理相關通知與管理員系統通知。

## 決議事項

1. 建立前端、後端與 RAG 的環境變數同步規則。
2. 公告功能暫緩，先聚焦影片處理與系統通知。
3. 影片建立或處理完成時通知修課學生，並建立管理員發送系統通知的能力。
4. 修正登入帳號角色驗證及註冊流程，補上清楚的錯誤訊息。
5. 各成員依本次分工推進任務。
